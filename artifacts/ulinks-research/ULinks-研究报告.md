# ULinks 研究报告

> 研究对象：ULinks（一款面向香港浸会大学学生的校园社区 App）
> 调研日期：2026-10-13
> 信息来源：香港浸会大学官网、浸大学生事务处、Google Play / App Store 元数据、第三方商店情报平台（Appfigures / AppBrain / MWM）

---

## 一、一句话结论

ULinks 是**香港浸会大学 9 名在校生**做的**校内实名 + 匿名双身份的校园社区 App**，用「浸大邮箱验证」做护城河式封闭社区，核心是**选课/教授评分 + 匿名树洞 + 校园攻略 + 二手/组队**。目前是**校园明星项目**（获得校方创业比赛种子基金与官方宣传），但仍是**极小规模、零收入、未验证留存**的早期项目。

## 四、产品功能拆解

### 已上线功能（商店页口径）

| 模块 | 具体能力 | 实质 |
| --- | --- | --- |
| **① 课程 & 教授评分** | 每门课有 grading / difficulty / workload 分项评分 + 综合分 + 同学评价；教授页有 teaching / grading / support 评分 | 对标"选课前查评分"，是**最强刚需钩子**（add-drop 期间） |
| **② Mask 身份 · 匿名发帖** | 双身份体系：profile 人设（交友）+ mask 别名（自由发言），两者完全隔离 | 流量引擎，但也是最大的合规风险面 |
| **③ 校园攻略** | 新生指南、校园生活 tips，由高年级学生实测沉淀 | 内容护城河，新生获取入口 |
| **④ 社区 + 私信** | 带话题标签的论坛（热榜讨论 / 校园情报 / 日常分享）+ 私信 | 主阵地 |
| **⑤ 校园服务** | 储物柜（lockers）等陆续上线；官方报道中另提到**二手买卖、寻找组员** | 从"内容"走向"履约" |
| **⑥ 验证与隐私** | 浸大邮箱验证（wall conditon）+ mask 与 profile 隔离 + 举报/拉黑 | 封闭社区的信任基座 |
| **⑦ AI 一键翻译** | 打破语言障碍，方便本地生与非本地生交流 | AI 目前只作为**一个功能点**存在 |

### 线下延伸（这是最值得注意的部分）

- **与顺丰供应链合作**暑期行李寄存服务：为约 **130 名**学生处理了近 **400 箱**行李，定价刻意压低（对标市面上"不够便利或价钱高昂"的寄存）
- **与高德地图合作**：推出**全港首个学生专属出行优惠**，为浸大学生提供独家打车优惠码
- 获 Village CARE 颁发的 **Innovation Creative Award**

> 这两件事说明团队最稀缺的能力不是写 App，而是**把学生需求翻译成企业愿意配合的线下服务**。这是纯软件团队学不来的。

## 六、资源与资金

- **HK$20,000 种子基金**：通过浸大校内创业比赛 **"Start-up Saturday"** 获得（该比赛优胜队最高可获 HK$30,000，即他们拿到上限的 2/3）。该比赛由浸大学生事务处事业策划中心主办，背后有「洪瑞琳创业起动基金」（HK$150 万捐赠）支持
- **StarHub 顾问指导**：浸大首个校园就业支援及创业培育中心。顾问的关键建议是"**深入走进学生的真实生活场景去验证价值主张**"，直接促使团队做大范围调研并锁定定位。团队持续使用 StarHub 共创空间协作
- **校方背书**：获浸大官网首页级报道 + 学生事务处专题报道，是校方对外讲"留学香港 / 学生创业"故事的样板案例

## 七、竞争格局

ULinks 并不是在真空里跑，香港校园社区赛道已经有人在做**跨校聚合**：

| 玩家 | 形态 | 覆盖 | 与 ULinks 的关系 |
| --- | --- | --- | --- |
| **ULinks** | 单校封闭社区（邮箱验证） | 仅浸大 | 深度优先，护城河=校方关系 + 线下履约 |
| **Triple Uni** | **跨校聚合器**（把 HKU Pupu、中大"马料水 Beeper"、科大"星尘空间站"聚到一个 App） | 港大 / 中大 / 科大 | ⚠️ **正面威胁**。它抢的是"跨校社交"心智，且主体是深圳三中视界网络科技（公司化运营，2026-04 上架） |
| **HiByeFd** | 全匿名校园社交（8+ 港校） | 港八大 | ⚠️ 抢"匿名表达"心智，与 ULinks 的 Mask 功能直接重叠 |
| **Dcard u life / Threads secrets / LIHKG / Telegram 换科群** | 非结构化舆论场 | 全港 | **真正的现任王者**。学生的"查课、换课、吐槽 prof"实际发生地 |

**关键判断**：ULinks 的真正对手不是别的 App，而是 **Telegram 换科群 + Instagram Secrets + Dcard** 这套"免费且已成型"的草根基础设施。ULinks 要用"实名验证 + 结构化评分 + 履约服务"去替代它们，本质是**用产品秩序替换社区混沌**——做得成就有壁垒，做不成就只是"学期初热两周"。

## 八、七个关键风险

1. **匿名 + 教授评分 = 法律与舆论核弹**
   Mask 身份 + 教授分项评分（教学/给分/支持），一旦出现点名攻击、诽谤或隐私泄露，在香港《个人资料（私隐）条例》与诽谤法框架下，运营公司 UHUB LIMITED 是**第一责任人**；同时会立刻招致校方施压。这是产品核心玩法与合规底线的直接冲突，不是加个"举报按钮"能解决的。

2. **创始团队毕业潮（最致命）**
   两位运营核心都是四年级，2027 年毕业。校园项目的第一大死因就是"创始人毕业 = 项目猝死"。目前公开信息里**看不到任何全职化、融资、或交接机制**。

3. **增长天花板写死在架构里**
   `@hkbu.edu.hk` 邮箱验证 = 信任极强，但**用户池上限就是浸大 2,900 名本科新生量级**。要破局必须跨校，而跨校就撞上 Triple Uni / HiByeFd，且**失去校方独家背书**这个最大资产。

4. **零商业模式**
   商店明确标注 Not Monetized。已露出的变现胚子有：顺丰物流履约、高德品牌合作、储物柜服务——但都是**一次性活动型收入**，不是可复制的产品化收入。

5. **季节性剧烈**
   校园社区只有 4 个流量窗口（开学 / 选课 add-drop / 考试 / 搬宿舍），其余时间静默。这要求团队有极强的节奏感与常态化内容运营，而学生团队在期末周基本停摆（团队自己也承认"兼顾期末考是最大挑战"）。

6. **工程与运营成熟度信号不佳**
   正式商店页挂着 `davidzhangtest@gmail.com` 这种明显是测试用途的邮箱；安装包 117–123 MB（对功能体量偏臃肿）；第三方数据源之间版本号口径不一致（1.1.0 / 1.1.5）。这些不是硬伤，但指向"缺一个成熟的工程负责人"。

7. **政策与主体风险**
   无法排除校方未来自建同类平台（学生会/资讯处完全有能力做），那时 ULinks 的"校方背书"会瞬间反转成"校方竞品"。

## 九、给你的启示（DeepTutor 视角）

如果我看这个项目是为了给自己的 agent-native 学习产品找参照，有三点值得抄、三点值得避：

**值得抄：**
- **邮箱验证 = 天然 gating + 高信任数据源**。它用一道验证同时解决了"用户真实性"和"归属感"，成本几乎为零。教育类产品都该有类似的"身份飞轮"。
- **线下履约建立不可复制的护城河**。顺丰行李寄存、高德打车优惠——这些"看似不务正业"的合作，反而是最难的竞品壁垒。纯 AI 产品最缺的就是这个。
- **用校方创业资源做冷启动**。Start-up Saturday + StarHub = 免费种子资金 + 免费顾问 + 免费官方宣传位。这是给在校生创业者的**最低成本分发路径**，值得系统性研究。

**值得避：**
- **别把 AI 当功能点**。ULinks 的 AI 只是"一键翻译"。在这个赛道真正没被做的是：**选课决策助手、课业学习陪伴、基于真实课程数据的个性化规划**——这才是 AI-native 该切的地方，而不是给社区加个翻译按钮。
- **别只在"信息聚合"上竞争**。论坛/评分/二手这些，Telegram + Dcard 已经免费提供了十几年。要有增量价值就必须是"帮你做决策"或"替你完成事情"，而不只是"让你看到信息"。
- **别让项目跟着创始人毕业**。这是校园项目的结构性宿命，唯一解法是尽早把项目"机构化"（公司化、全职化、或有明确的接棒人）。

## 十、信息缺口（需要进一步验证）

- MAU / DAU / 留存曲线 / 发帖活跃度 —— **完全未知**，这是判断真伪的唯一关键
- 是否有融资、是否有全职人员、9 人团队的真实分工
- 「课程/教授评分」的数据从哪来（学生自发填写？爬取？——若为爬取则另有隐私风险）
- 隐私政策实际执行情况（匿名帖子在服务端是否真的与身份解耦）
- 是否已启动跨校扩展，或与其他港校接触
