伙伴（Partners）是持久的学习伙伴，拥有自己的身份、灵魂（soul）、模型策略、资料库、记忆与渠道配置。它不是另一套机器人引擎：每一条进来的消息——无论来自网页还是 IM 应用——都走**同一个** `ChatOrchestrator → AgenticChatPipeline` 循环，也就是驱动[主页](/zh-cn/explore/chat-workspace/)的那一个。可以把伙伴理解成「一段有了人格、还带了手机号的聊天」。

## 它在哪里

点击左侧栏的 **Partners**（伙伴）。页面会列出你拥有的伙伴和管理员分配给你的伙伴，包括头像、状态、描述与已连接渠道；下方还会显示 Partner Groups，并提供 **New partner**（新建伙伴）按钮。

![伙伴列表](/screenshots/dev/partners.png)

## 账号伙伴与工作区资源

**伙伴属于账号。** 切换工作区后，仍然能看到同一批伙伴与伙伴群组。伙伴的身份、渠道和关系历史，不会因为你从课程切换到研究项目而消失。

在 **Configure → Workspace（配置 → 工作区）**中，为资料选择两种方式之一：

| 方式 | 伙伴使用什么 | 适用场景 |
| --- | --- | --- |
| **Partner private workspace（伙伴私有工作区）** | 自己的资料库；把知识库、技能、收藏夹集合复制进来 | 专职伙伴，需要稳定且独立演进的材料 |
| **现有工作区** | 该工作区最新的文件、知识库、技能和收藏夹集合；生成文件进入它的 outputs 文件夹 | 课程或项目伙伴，需要与实际工作保持同步 |

选择器列出伙伴所有者的工作区。绑定不会转移所有权，也不会授予其他账号资源的访问权；资源选择及所有者的模型、工具授权仍然约束每一轮。修改绑定从下一条消息生效，不会把旧伙伴会话搬到主页。

私有模式中，普通知识库、技能和收藏夹集合在分配时复制，之后修改原始内容不会更新副本。连接型知识库没有可复制的目录，因此受支持的连接保留实时源指针。绑定模式中，请在对应工作区的**资源**中管理共同材料，在**学习**中学习同一批来源；无需再向伙伴复制私有 Library。

两种模式都保留伙伴自己的灵魂与关系状态。渠道运行状态在 `data/partners/<id>/channels/<channel>/` 下。已认证非管理员用户的会话与关系记忆按用户隔离在 `users/<user_id>/` 中，伙伴也可以读取该用户自己的共享记忆。管理员及尚未归属账号的渠道消息回退到伙伴顶层历史与记忆。共享材料不会合并这些私有关系。

## 所有权与共享访问

Partner 已不再是管理员专属资源。任何已认证用户都可以创建 Partner，并自动成为所有者；所有者和管理员可以配置它的灵魂、资料库、渠道、工具、模型与生命周期。管理员也可以把 Partner 分配给其他用户，让对方能够聊天，但看不到也不能修改内部配置。

共享 Partner 时，这层分工很重要：身份和知识资产保持一致，每个人的会话与关系记忆仍然私有。外部 IM 账号在私聊中执行 `/link <code>` 后，也可以进入该用户对应的同一份私有作用域。

## 创建一个伙伴

点击 **New partner**，走完向导：

1. **Identity**（身份）——名字、头像、描述、默认回复语言。
2. **Soul**（灵魂）——伙伴的角色与沟通风格，会落成它的 `SOUL.md`。
3. **Mind**（心智）——模型选择、启用的系统工具、MCP 工具、投递偏好。
4. **Library**（资料库）——选择私有工作区并复制获准资产，或绑定现有工作区共享实时资源。私有复制不支持 Obsidian、MarginNote 与 subagent 知识库。
5. **Review**（确认）——检查身份、模型、工作区与资产后创建伙伴。渠道可以稍后添加，也可以只在网页使用。

这里选的一切，之后都能在伙伴详情页里继续修改。

## 与伙伴对话

打开一个伙伴会进入它的 **Chat** 标签页——一个完整的对话视图，表现得就像主工作台，只是换成了那个伙伴。顶部的标签依次是 **Chat**、**Configure**、**Channels**、**Archive**。


因为伙伴有记忆，它会随时间积累对你的认识。问它「你了解我什么？」，你会看到一个 `Recalling memory` 步骤——伙伴先读取自己的记忆层，再用它的灵魂作答。**Configure** 标签页涵盖身份、灵魂、心智与资料库。**Archive** 是软归档：Resume 会重开同一 session key，Branch 会复制完整历史并归档来源，只有 Delete 才会永久删除。

## Partner Groups

**Partner Group（伙伴群组）**会把两个或更多 Partner 带进同一段共享对话。选好成员、讨论模式和共享记忆模式后，可以让所有成员回答，也可以只 @ 指定成员。每个 Partner 的回复占据独立 seat，因此即使围绕同一段公开讨论推理，各自的观点仍清楚分开。

群组拥有自己的会话与持久历史。某个 seat 失败时，可以只重试该成员，而不用让已经完成的回答重跑。Partner Groups 显示在 Partners 页面上各个伙伴卡片的下方；至少要有两个可访问的 Partner 才能组建群组。

## 渠道

渠道是围绕同一个伙伴大脑的投递适配器。**Channels** 标签页在左侧列出所有支持的应用；选中一个，在右侧配置凭据与行为，然后 **Save** 并启用。页面会轮询正在运行的 Partner，显示连接成功、连接中、listener 正在运行、等待扫码、缺少配置、不可用、连接失败或尚未连接。

![伙伴渠道配置](/screenshots/dev/partners-channels.png)

大多数渠道卡片共用几个开关：

| 字段 | 含义 |
| --- | --- |
| **Enabled** | 为该伙伴启动这个渠道。收集凭据期间先关着。 |
| **Send Progress** | 为耗时较长的轮次投递叙述/进度。在 IM 里，沉默 60 秒会让人以为坏了，这时很有用。 |
| **Send Tool Hints** | 投递一行式的工具调用提示，如 `rag(query=…)`。生产环境想安静些就关掉。 |
| **Allow From** | 允许的用户 id、群 id、邮箱或 `*`（每行一个）。留空通常拒绝一切；`*` 则完全开放。 |

每张卡片的其余部分因渠道而异（base URL、token、轮询等）。完整的应用清单与各渠道的配置步骤见[**渠道矩阵**](/zh-cn/partners/channels/)——可以先从[**个人微信**](/zh-cn/partners/weixin/)、[**企业微信**](/zh-cn/partners/wecom/)或 [**QQ / NapCat**](/zh-cn/partners/qq/)开始。

需要扫码的渠道也留在浏览器里完成。WeChat/WeCom onboarding 与 WhatsApp bridge 都能把服务端生成的二维码显示在卡片中；在那里扫码或刷新，再观察同一面板从 **Waiting for scan** 进入已连接状态。只有状态详情仍解释不了故障时才需要查日志。


## 把伙伴当作可咨询的智能体

伙伴也可以被**连接为智能体**，在普通的一轮聊天里被咨询——DeepTutor 把你的问题送进伙伴自己的会话，再把它的答复收拢回来。详见[我的智能体](/zh-cn/explore/subagents/)。

## CLI 对应命令

```bash
deeptutor partner list
deeptutor partner create math-tutor --soul "Socratic math tutor"
deeptutor partner start math-tutor
deeptutor partner stop math-tutor
```

CLI 适合做冒烟测试，但配置渠道还是推荐用网页 UI——它会对密钥打码，就地展示字段结构，并给出实时配置/运行状态。
