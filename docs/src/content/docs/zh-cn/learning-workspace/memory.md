记忆（Memory）是 DeepTutor 的**可审计**个性化系统。它刻意*不是*隐藏的向量库——而是一条可读、可整理、可审计的三层管线。结论与它引用的工作区实体或来源界面并列，引用精度也如实可见。

## 它在哪里

从左侧栏的**个性化 → 记忆**进入。总览一眼呈现三层，每层都有实时计数，并提供 **Refresh**（刷新）、**Memory settings**（记忆设置），以及进入 **Memory Graph**（记忆图谱）的入口。

![记忆总览](/screenshots/dev/memory.png)

## 三个层级

记忆从工作区里的实时实体逐级上升到综合知识。每一层都是对持久内容的不同抽象。

| 层级 | 标签 | 存储 | 角色 |
| --- | --- | --- | --- |
| **L1 · 工作区镜像** | LIVE | 工作区 + `snapshot/<surface>/` | 各界面当前存在的实体。**Refresh** 会存下 fingerprint、label、`last_refresh` 与只追加的变更历史。 |
| **L2 · 各界面摘要** | CURATED | `L2/<surface>.md` | 由整理器直接从实时 L1 实体抽取的、按界面归类的事实，并引用其背后的实体。 |
| **L3 · 跨界面综合** | SYNTHESIS | `L3/<profile\|recent\|scope\|preferences>.md` | Update 与 Audit 从 L2 综合 profile、recent 和 scope；preferences 只在聊天助手调用 `write_memory` 时直接写入。 |

记忆只在你实际使用的界面上追踪——`chat`、`notebook`、`quiz`、`kb`、`book`、partner（伙伴）与 `cowriter`。L2 可以引用一个具体的 L1 实体；当前 L3 引用通常只指向整个 L2 界面。偏好则跟随那次明确的聊天写入，因此引用仍可检查，但粒度并不完全相同。

## 记忆图谱

图谱把三个自动综合的 L3 槽位——profile、recent 与 scope——放在中心，**L2 事实位于中环，实时 L1 实体位于外圈**。悬停可预览，点击可锁定并高亮现有连接；Preferences 不在图中。

![记忆图谱](/screenshots/dev/memory-graph.png)

L2 到 L1 可指向具体实体。当前 L3 引用界面名，因此图谱只画到对应 L2 集群的软连接，而非精确的端到端链。可先定位支撑领域，再检查相关事实与实体。

Update、Audit 和 Dedup 的预算在 **设置 → 记忆**。见[设置](/zh-cn/self-hosting/settings/)。`deeptutor memory show` 可以打印某一层；参数见[命令参考](/zh-cn/developers/reference/cli/)。

## 实践建议

- 长周期的学习工作流就把记忆开着——那才是它发挥价值的时候。
- 当 DeepTutor 的语气或假设不对劲时，去看 L3；对综合槽位，图谱会显示当前可用的支撑界面与实体。
- 刷新 L1 会记录工作区发生了什么变化；L2 Update 则直接读取当前工作区快照。
- 多用户模式下，普通用户拥有私有的伙伴关系记忆；伙伴还会读取当前交互用户的共享记忆，只写入关系记忆。

## 账号级个性化与工作区依据

记忆位于**个性化**下，切换工作区不会创建一个新的个人身份。但工作区镜像与来源引用仍对应具体材料：应区分跨项目偏好与某个项目的事实。“使用本课程的符号”适合放入工作区指令；“先让我尝试，再给解答”更适合作为长期偏好。

可以在聊天中明确提出一项偏好，再到记忆中核查保存了什么。摘要出乎意料时打开引用来源，修正相关文档或偏好，不要默认所有综合结果始终最新。收藏保留来源内容，学习日志记录目标与交接，记忆归纳个性化信息；它们都不能替代原始依据的核查。
