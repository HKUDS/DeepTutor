CLI App 让智能体调用真实命令行程序，却不授予通用主机 shell。DeepTutor 把每个应用安装在独立环境中，以只读方式挂载到沙箱运行器，再暴露一个程序固定、参数向量由模型生成的工具。

## 浏览目录

打开**个性化 → CLI Apps**。商店收录了从两个 CLI-Anything 注册表快照下来的 101 个工具，涵盖媒体、文档、地理空间与 3D 应用。

![CLI 应用目录](/screenshots/dev/cli-apps.png)

目录随软件包一起发布，所以离线也能浏览，部署对“当前可以安装什么”始终有稳定答案。**Include unavailable** 会显示安装器依赖当前运行环境所没有的包管理器的条目。

| 信任标签 | 含义 |
|---|---|
| **Pinned** | 来自本版本审查并锁定的 CLI-Anything 修订。 |
| **Third-party** | 其他上游，使用注册表记录的修订。 |
| **Third-party, unpinned** | 其他上游，使用其默认分支当前最新内容。 |

## 安装仅限管理员

安装软件包会以应用用户身份运行第三方构建代码，因此绝不能作为账号自助操作。DeepTutor 会把注册表中的安装字符串解析成计划，而不是交给 shell 执行；npm install script 被禁用，更新失败时则恢复之前可用的环境。

安装与授权是两个决定：管理员可以先安装应用，而不把运行权限自动授予所有账号。

## 运行仍在沙箱内

每个已安装应用会成为一个名为 `cli_<app id>` 的工具。模型提供类似 `['scene', 'list']` 的参数向量；可执行程序本身固定，因此下游不需要用 shell 解析命令字符串。

使用指南按渐进披露加载。初始清单只为每个应用提供一行说明，只有 `load_tools` 选中该应用后，完整指南才会送入模型。多用户授权按 app id 设置 CLI App 白名单，非管理员账号默认拒绝。

## 从安装到完成任务

1. 打开**个性化 → CLI 应用**，按任务或应用搜索，检查可用性与上游信任标记。
2. 尚未安装时，由部署管理员安装并给账号授权。目录中可见不等于已经可以运行。
3. 把输入文件放在当前工作的工作区，在主页提出明确的转换目标与输出要求。智能体可按需发现应用工具并加载使用说明。
4. 检查生成文件，把有用结果保留为工作区成果。需要重复执行固定步骤时，把流程写进技能，避免每次粘贴命令配方。

个性化在各工作区显示可复用应用目录；每次执行仍使用当前轮次的沙箱与文件，不会让主机所有目录都可读。程序可用、账号获准、输入文件存在，是三个独立条件。

## 更新与移除

管理员管理安装环境及启用状态。更新失败时，DeepTutor 会恢复之前的环境；重试用户任务前先检查安装结果。删除或停用应用也会影响依赖其工具的技能。保持技能说明与安装版本一致，并用实际消费输出的程序检查生成文件。
