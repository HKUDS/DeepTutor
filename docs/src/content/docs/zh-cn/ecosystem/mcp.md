MCP 服务把 DeepTutor 之外的工具带进与内置工具相同的智能体循环。远程服务连接到个人账号；部署级服务器则由管理员管理。

## 浏览商店

打开**个性化 → MCP 服务**。**Installed** 显示当前账号已连接的服务；**Store** 提供 39 个托管服务器。完整的 46 项目录还有 7 个仅管理员可用的 `stdio` 定义，因此不会出现在自助商店里。

![MCP 服务目录](/screenshots/dev/mcp.png)

卡片会标出分类、是否需要凭据，以及条目是本版本精选还是来自公共注册表。连接后，服务工具通过正常的工具发现流程进入智能体；选择器会先把工具折叠在一个服务条目下，而不是一次列出数百个 schema。

## 连接托管服务

流程取决于服务器的要求：

| 服务器需要 | 连接方式 |
|---|---|
| **无需凭据** | 一键立即连接。 |
| **API key** | 只粘贴一次；服务器配置保存 `${secret:…}` 引用，而不是令牌本身。 |
| **OAuth** | DeepTutor 运行带 PKCE 和动态客户端注册的 OAuth 2.1，并保存该账号的授权。 |

后台重连不会卡在同意页面。授权过期后，服务状态变为 **needs auth**，界面会重新提供 Connect 操作。

## 添加商店外的服务

**Installed → Add a server by URL** 接受公网端点，或管理员明确批准的私网来源（协议、主机、端口须完全匹配）；回环与元数据地址仍被拦截。**Deployment registry** 管理共享的 `mcp.json` 条目。

自助商店拒绝 `stdio`：命令以应用用户身份运行，须由管理员加入注册表。旧的 `/settings/mcp` 路径跳转到这里。

## 凭据与授权

按账号保存的 MCP 凭据位于代码沙箱永不挂载的 `data/system`。多用户部署中，非管理员授权按工具名设置白名单，默认拒绝；执行时还会再次检查权限，而不只是在展示 schema 时检查。

## 让工作区使用连接

连接成功后，打开**设置 → 工作区**，将服务加入目标工作区的 MCP 资源选择。回到该工作区主页，如果只有当前对话需要它，再在输入框中选中。对话可以缩小工作区范围，不能扩大范围或覆盖用户工具授权。

同一账号可以只连接一次文献服务，再让文献综述和论文写作两个工作区使用，同时让无关课程保持不使用。文件与学习材料仍属于工作区资源；服务授权属于账号。

## 维护与排错

先在 **Installed** 检查连接状态，再排查聊天提示。对 **needs auth** 服务重新授权，在连接配置中修正端点或 API key 后重试。如果服务已连接但本轮看不到工具，先检查工作区选择和用户授权，避免反复重连。

停用或删除服务器会使工具不可用。删除前检查引用它的工作区；残留选择不会重建连接，也不会补上凭据。Partner 使用时需要明确配置其 MCP 工具和工作区绑定，不会自动继承当前主页会话的选择。
