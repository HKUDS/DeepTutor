**Personalization** is the account shelf. A workspace holds the work: conversations, learning activities, and materials. The shelf supplies ways of working that stay available when you switch workspaces. A workspace still decides which of those resources a turn may use, and a conversation can narrow that further. Nothing on the shelf is visible to another account.

| You keep it here | It is |
| --- | --- |
| [Personas](/customize/personas/) | A voice and a response policy for a turn |
| [My Agents](/customize/agents/) | A connected harness, or an imported transcript you can consult |
| [Skills](/customize/skills/) | A reusable procedure the model reads when the task calls for it |
| [MCP services](/customize/mcp/) | Tools from a remote server, authorized on the account |
| [CLI Apps](/customize/cli-apps/) | A program an administrator installed, run in a sandbox |
| [Memory](/learning-workspace/memory/) | Preferences and summaries you can open and correct |
| [EduHub](/customize/eduhub/) | Community skills you review before import |

Retrieval is not one of those account objects. A [RAG integration](/customize/rag/) belongs to a knowledge base and the files that base indexes.

Each path has its own trust boundary. A skill is instructions. An MCP service is a remote tool boundary. A CLI app is code on the host. EduHub distributes skills and does not run them. The workspace assignment references the account catalog. It does not copy credentials or bypass a per-user grant.

A partner can start from a persona, then keep its own soul, library, and channels. That identity is the partner's, so later edits to the persona do not rewrite it. See [Channels](/channels/).
