# درسیار (Darsyar) — اسناد محصول و توسعه

این پوشه مرجع اختصاصی محصول درسیار است؛ محصولی وب‌محور برای آموزش هوشمند دانش‌آموزان ایران بر پایه کتاب‌های رسمی و منابع آموزشی تأییدشده که هسته Agent/RAG پروژه DeepTutor را به‌عنوان زیرساخت اولیه حفظ می‌کند.

## اسناد

| سند | کاربرد |
|---|---|
| MASTER_SPEC.md | نیازمندی‌های محصول، رفتار کاربر، منابع، آموزش، آزمون، مدیریت و مدل تجاری |
| ARCHITECTURE.md | معماری هدف، مرزهای ماژول‌ها، داده‌ها، امنیت، API و زیرساخت |
| ROADMAP.md | فازبندی، وابستگی‌ها، دروازه‌های پذیرش و تست‌های هر فاز |
| EXISTING_CAPABILITIES.md | ممیزی قابلیت‌های موجود DeepTutor و تصمیم حفظ/تکمیل/توسعه |
| DECISIONS.md | تصمیم‌های تثبیت‌شده، پیشنهادهای معماری و موضوعات نیازمند ADR |
| KILOCODE.md | دستورالعمل اجرایی عامل کدنویس برای توسعه کنترل‌شده درسیار |

## قواعد استفاده

1. فایل ریشه AGENTS.md و قراردادهای فعلی معماری/توسعه/تست همچنان لازم‌الاجرا هستند. این اسناد جایگزین آن‌ها نیستند؛ نیازمندی‌های محصول درسیار را به آن‌ها اضافه می‌کنند.
2. وضعیت «موجود» در ممیزی به معنی وجود کد یا Manifest است، نه تأیید کیفیت نهایی، سازگاری فارسی، آمادگی تجاری یا Production.
3. هیچ ماژول یا وابستگی‌ای بدون بررسی مالکیت کد، نمودار وابستگی، تست و امکان جایگزینی حذف نشود.
4. فازها به‌ترتیب اجرا شوند. پایان هر فاز به گزارش شواهد، تست‌های قابل تکرار و معیارهای پذیرش وابسته است.
5. هیچ راز، رمز عبور، کلید API، OTP یا داده واقعی دانش‌آموز در Git، fixture عمومی، لاگ یا گزارش تست ثبت نشود.
6. دریافت و استفاده تجاری از کتاب‌ها و منابع تابع مجوز و شواهد حقوقی هر منبع است؛ وجود فایل قابل دانلود مجوز بازنشر یا پردازش تجاری را اثبات نمی‌کند.
7. هر تغییر ناسازگار یا تصمیم معماری جدید باید ADR داشته باشد و با مسیر مهاجرت/rollback توضیح داده شود.

## شروع کار

ابتدا KILOCODE.md، DECISIONS.md بخش F و ROADMAP.md را بخوان. Phase 0 انجام شده و Gate 0 برای شروع Phase 1 با وضعیت ACCEPTED CONDITIONAL PASS پذیرفته شده است. توسعه فقط مطابق تصمیم‌های مصوب Phase 1 و روی branch مستقل انجام شود؛ پس از Gate 1 بدون دستور صاحب محصول وارد Phase 2 نشو.
