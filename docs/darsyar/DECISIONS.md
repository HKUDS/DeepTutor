## C. موضوعات باز که نباید با حدس نهایی شوند

1. کدام درگاه پیامک ایرانی برای OTP انتخاب می‌شود؟
2. واحد پول محصول و واحد نمایش/ثبت حسابداری چیست؟
3. پلن‌های اولیه، قیمت، سهمیه و سیاست refund چه هستند؟
4. کدام درگاه پرداخت برای خرید اشتراک استفاده می‌شود؟
5. آیا و در چه شرایطی کاربر می‌تواند خارج از کتاب‌های انتخاب‌شده سؤال بپرسد؟
6. منابع آموزشی مکمل چه شواهد مجوز و چه محدوده استفاده دارند؟
7. سیاست حفظ/حذف سوابق دانش‌آموز و رضایت والد/سرپرست چگونه است؟
8. grading تشریحی تا چه حد خودکار باشد و چه نوعی بازبینی انسانی لازم دارد؟
9. providerهای OCR، embedding، reranker، TTS و video در اولین استقرار کدام‌اند؟
10. حجم مورد انتظار کاربران همزمان و بودجه زیرساخت چقدر است؟

## D. محدودیت‌های امنیتی غیرقابل مذاکره

- رمز خام کاربران هرگز قابل مشاهده نیست.
- API key و OTP در response/log/browser افشا نمی‌شوند.
- Super Admin مجوز اجرای shell دلخواه یا خواندن secretهای OS را از پنل نمی‌گیرد.
- scope پایه/رشته و rights منابع توسط Backend enforce می‌شود.
- تراکنش اعتبار و مصرف idempotent و audit-able است.
- Production default credential ندارد.
- سند/فایل آپلودشده به‌عنوان prompt/instruction مورد اعتماد اجرا نمی‌شود.

## E. مدیریت تغییر تصمیم

هر تصمیمی که روی database، identity، auth، RAG retrieval, billing، provider credentials، media job lifecycle یا data retention اثر می‌گذارد باید ADR اختصاصی با status، context، options، consequences، migration و rollback داشته باشد. این سند نباید به‌جای ADR جزئیات اجرای production را تصویب کند.

### F-4. استثنای Gate 1 — پذیرش صریح مالک (2026-11-17)

**تصمیم:** Gate 1 با استثنای مستند بسته می‌شود؛ بخش browser E2E آن در sandbox توسعه اجرا نمی‌شود.

#### چرا — با جزئیات فنی، نه ادعای کلی

sandbox توسعه مرورگر ندارد و **نمی‌تواند داشته باشد**. چهار مسیر آزمایش شد:

| مسیر | نتیجه |
| --- | --- |
| `npx playwright install chromium` | CDN مسدود (`cdn.playwright.dev` → کد 000) |
| `@sparticuz/chromium` از npm | باینری ۱۹۹MB با موفقیت استخراج شد |
| اجرای آن باینری | ۳ کتابخانهٔ گمشده: `libnspr4.so`, `libnss3.so`, `libnssutil3.so` |
| `sudo apt-get install libnss3` | مخازن Debian مسدود (`deb.debian.org` → 151.101.66.132) |

نکتهٔ تعیین‌کننده: `sudo` بی‌گذرواژه **کار می‌کند**؛ مانع دسترسی نیست، **شبکه** است. از ۱۱ کتابخانهٔ موردنیاز chromium، ۸ حاضر است و همین ۳ تا کل مانع‌اند. `libnss3` روی npm عرضه نمی‌شود، و کامپایل از سورس بدون مخزن ممکن نیست.

**پس این استثنا ضعف اجرا نیست؛ قید محیط است — و اکنون با شواهد قابل بازتولید مستند شده.**

#### چه چیزی پوشش داده **نشد** — بدهی صریح

1. **چیدمان بصری RTL.** ۷۵۹ توکن کلاس به logical تبدیل شد و وجود `margin-inline-start` در CSS کامپایل‌شده تأیید شد، اما **آینه‌شدن واقعی چیدمان فارسی هرگز دیده نشد**. jsdom چیدمان محاسبه نمی‌کند.
2. **hydration واقعی.** کلاس باگ مستند در همین ریپو: «سرور HTML را رندر می‌کند، اما هیچ event handler متصل نمی‌شود» — نوار بالا با صفحهٔ خالی. فقط مرورگر این را می‌بیند.
3. **responsive واقعی.** وجود `lg:hidden` تست شد، رفتار آن در ۳۷۵px نه.
4. **redirect نقش در تجربهٔ مرورگر.** منطق middleware با ۵ آزمون واحد تأیید شد، اما نه اینکه در مرورگر واقعی همان اتفاق بیفتد.

#### چهار نقص واقعی که همین اجرا پیدا کرد — و هیچ لایهٔ دیگری نمی‌گرفت

1. **`/admin/users` گارد سمت سرور نداشت** (در گام ۱.۶ بسته شد، اما CI ثابت کرد برای استقرار واقعی کافی نبود — زیر).
2. **`DEEPTUTOR_API_BASE_URL` ورودی build است، نه ران‌تایم.** `proxy.ts` آن را در سطح ماژول می‌خواند؛ ست‌کردنش فقط روی مرحلهٔ start، پراکسی را به ۸۰۰۱ می‌فرستاد و هر `/api` با ۵۰۰ برمی‌گشت.
3. **`DEEPTUTOR_AUTH_ENABLED` هم همین‌طور.** بدون آن در build، `AUTH_ENABLED` روی `false` قفل می‌شد و **دروازهٔ admin اصلاً در باندل وجود نداشت** — یعنی `/admin/users` به هر بازدیدکننده‌ای سرو می‌شد. این جدی‌ترین یافتهٔ کل فاز است.
4. **ترتیب بررسی نقش و گذرواژه معکوس بود.** دانشجویی با گذرواژهٔ موقت در `/admin/login` **بدون هیچ پیامی** به `/profile?change=1` پرتاب می‌شد و هرگز نمی‌فهمید حسابش ادمین نیست.

#### درس فرآیندی

تفاوت **«E2E نداریم»** و **«E2E نوشته شده، ولی اجرا نشده»** سه بار دیگر هم ظاهر شد: آزمون‌هایی که خودشان باگ داشتند (`.first()` روی تصویر پنهان، regex `users` در برابر `User Management`، `startsWith("/login")` که `/admin/login` را نمی‌گرفت). **آزمون اجرانشده با آزمون غایب فرقی ندارد** — و این دقیقاً همان چیزی است که F-4 ریسکش را پذیرفته بود. ریسک تحقق یافت و مهار شد.

**وضعیت Gate 1: PASS کامل.** انتشار Production از این جهت مجاز است. F-4 بسته می‌شود.

| D-022 | صف کار به‌صورت جدول در دیتابیس، بدون broker (Redis/Celery)؛ `enqueue` بر `dedupe_key` idempotent است | CONFIRMED |
| D-023 | مرز داده ISO-8601 است (رشته) و فقط در لبهٔ PostgreSQL به `datetime` تبدیل می‌شود | CONFIRMED |
| D-024 | `identity.py` در یک درز نوشتن (`_write_users`) به دیتابیس وصل می‌شود؛ فایل JSON به‌عنوان مسیر rollback حفظ می‌شود | CONFIRMED |

### D-019 — PostgreSQL به‌عنوان source of truth

**Context:** `.gitignore` و schema موجود نشان می‌داد محصول روی فایل JSON و SQLite محلی رشد کرده است. Supabase از ۱۴–۱۵ نوامبر ۱۶ جدول داشت که هیچ اثری از آن‌ها در ریپو نبود.

**Decision:** PostgreSQL مرجع داده تجاری است. SQLite برای توسعهٔ محلی و آزمون باقی می‌ماند، اما رفتار مرجع نیست.

**Consequences:** همهٔ SQL باید در دو موتور کار کند. این هزینهٔ واقعی داشت: سه باگ که هیچ‌کدام در SQLite پیدا نمی‌شد (ایندکس یکتای گمشده، `timestamptz` در برابر متن ISO، و `%` در psycopg).

**Rollback:** `DEEPTUTOR_DATABASE_URL` خالی ⇒ لایهٔ دیتابیس غیرفعال. محصول به رفتار فایل JSON برمی‌گردد.

### D-021 — فاز ۲ مرجع است، نه schema قدیمی

**Context:** schema موجود Supabase با فاز ۲ ناسازگار بود: `phone_number NOT NULL` در برابر «username همان شماره است»، `is_active` در برابر `disabled`، جدول `otp_codes` در برابر `otp.json`.

**Decision:** مدل فاز ۲ مرجع است. schema با `ALTER` هم‌تراز می‌شود.

**Consequences:** هر ۱۱ کلید خارجی و کل دادهٔ مرجع (۱۲ پایه، ۳ رشته، ۳ طرح، تنظیمات پرداخت) سالم ماند. جدول‌های خالی کاربری حذف و بازساخته شدند.

### D-027 — چرا ستون مشتق‌شده و نه عبارت در query

**Decision:** ستون مشتق‌شده، محاسبه‌شده در یک تابع (`_derive_retrievable`).

**Consequences:** قاعده در یک جا است و ایندکس‌پذیر. هزینه: ستون می‌تواند از ورودی‌هایش drift کند. جبران: محاسبهٔ مجدد در هر تغییر + یک آزمون ماتریسی روی هر ۲۵ ترکیب (۵ وضعیت حقوق × ۵ وضعیت review).

**Rollback:** حذف `publicly_retrievable` و جایگزینی با `WHERE rights_status='cleared' AND review_status='approved'` در `list_retrievable`.

### D-030 — شناسه‌های تولیدشده باید URL-safe باشند

**Decision:** slug ASCII + digest پایدار.

**Consequences:** شناسه در log و curl بدون encoding کار می‌کند. عنوان‌های کاملاً فارسی شناسهٔ digest-محور می‌گیرند که کمتر خواناست اما پایدار است.

**کشف:** با `curl` روی سرور زنده (HTTP 405)، نه با هیچ آزمون واحدی.

## §I — فاز ۵: دریافت، OCR و مدرسِ مستند

### D-031 — فیلتر دامنه تابع است، نه پارامتر

**Context:** فیلتر پایه/رشته می‌توانست پارامتری با پیش‌فرض باشد یا از enrolment استخراج شود. در حالت پارامتر، هر مسیر جایگزینِ گفتن دامنه، یک مسیر برای دور زدن آن است؛ و پارامتری که کلاینت کنترل می‌کند در اولین باگ UI به نشتی تبدیل می‌شود.

**Decision:** دامنه فقط از `scope_sql(enrolment)`. `retrievable()` پارامتر `grade_number` یا `ignore_scope` نمی‌پذیرد.

**Consequences:** گسترش دامنه فقط با جعل هویت ممکن است، که مسئلهٔ جدا و آزمون‌دار است. یک آزمون ساختاری (`ignore_scope=True` ⇒ `TypeError`) این را قفل می‌کند.

**Rollback:** افزودن پارامتر — که خودش تصمیم جدیدی است و باید ADR بگیرد.

### D-032 — «قابل مشاهده» و «مرتبط» دو پرسش‌اند

**Context:** پیش‌نویس اول فقط `retrievable()` داشت. آزمون abstention شکست خورد. علت طراحی بود: تابعی که «چه چیزی مجاز است» را جواب می‌دهد هرگز خالی برنمی‌گردد، پس هرگز نمی‌تواند abstain کند.

**Decision:** دو تابع و دو endpoint. `retrievable`/`/browse` برای مجوز؛ `search`/`/search` برای ارتباط. فقط دومی می‌تواند خالی باشد.

**Consequences:** abstention یک رفتار طراحی‌شده است. هزینه: `search()` اول کل دامنهٔ مجاز را می‌خواند (بودجهٔ ۲۰۰ قطعه) و سپس امتیاز می‌دهد؛ برای کتابخانهٔ بزرگ باید به SQL منتقل شود.

**Rollback:** ادغام در یک تابع — که abstention را غیرممکن می‌کند و پذیرش ROADMAP را می‌شکند.

### D-033 — `chunk_key` مکانی است، نه متنی

**Context:** کلید می‌توانست از متن مشتق شود (مقاوم به تغییر صفحه) یا از موقعیت.

**Decision:** مکانی: `sha256(source_id | document_key | page_index | ordinal)`.

**Consequences:** ارتقای parser متن را به‌روز می‌کند و کلید را نگه می‌دارد؛ ارجاع‌های صادرشده نمی‌شکنند. `uq_ingestion_chunk_identity` جلوی تکرار را می‌گیرد و `ON CONFLICT DO UPDATE` به‌روزرسانی درجا را.

**Rollback:** غیرممکن بدون بازسازی همهٔ ارجاع‌ها. این تصمیم برگشت‌ناپذیر است و به همین دلیل ADR دارد.

### D-034 — `ocr_required` از `failed` جداست

**Context:** یک PDF اسکن‌شده در برابر یک فایل خراب، دو درمان مختلف دارد.

**Decision:** `failure_kind` هفت مقدار دارد: `ocr_required`، `encrypted_document`، `parse_error`، `empty_document`، `storage_error`، `invalid_input`، `interrupted`.

**Consequences:** اپراتور درمان درست را انتخاب می‌کند. هزینه: تشخیص بر اساس متن exception است (`_classify_failure`)، که شکننده‌تر از یک کد خطای ساخت‌یافته است.

**Rollback:** ادغام همه در `failed`.

### D-035 — مجموعهٔ طلایی شکل خودش را دارد، نه `EvalCase`

**Context:** `EvalCase` در `services/rag/eval` دقیقاً متن gold را تطبیق می‌دهد و `extra="forbid"` است. پذیرش فاز ۵ به زبان **فصل** و **abstention** بیان شده، که هیچ‌کدام در آن طرح نگنجید: فصل یک ادعای دامنه است و abstention غیاب نتیجه.

**Decision:** مدل جدا در `services/ingestion/golden.py` که به معیارهای موجود آداپت می‌شود.

**Consequences:** هیچ معیار موجودی تضعیف نشد؛ ۸۹ آزمون eval بدون تغییر پاس. هزینه: دو شکل داده برای ارزیابی، با خطر واگرایی.

**Rollback:** گسترش `EvalCase` با فیلد اختیاری — که `extra="forbid"` را می‌شکند و همهٔ مجموعه‌های موجود را تحت تأثیر می‌گذارد.

### D-036 — ارجاع فقط با مجموعهٔ بازیابی‌شدهٔ همان پرسش معتبر است

**Context:** اعتبارسنجی ساده («آیا این کتاب هست؟») ارجاع به کتابی را تأیید می‌کند که هست ولی برای این پرسش بازیابی نشده — یعنی پاسخ ساختگی موجه به نظر می‌رسد.

**Decision:** `validate_citations` با فهرست قطعه‌های همان پرسش می‌سنجد. `grounded_answers` هر دو مجموعه را ذخیره می‌کند.

**Consequences:** ارجاع به کتاب درست با فصل اشتباه هم رد می‌شود. پاسخ بدون ارجاع معتبر نیست. هزینه: پرسشی که واقعاً چند کتاب را می‌طلبد باید همه را در یک بازیابی برگرداند.

**Rollback:** اعتبارسنجی در برابر کاتالوگ — که معیار «صفر ارجاع ساختگی» را بی‌معنا می‌کند.

### D-037 — نرمال‌سازی فارسی به‌صورت موقت در دو جا

**Context:** هم `eval.matching.tokenize` و هم `grounding._normalise_fa` باید ZWNJ، ی/ك عربی، ارقام فارسی و اعراب را نرمال کنند.

**Decision:** فعلاً هر دو جدا، با بدهی ثبت‌شده.

**Consequences:** ریسک واگرایی اگر یکی به‌روز شود و دیگری نه. **بدهی:** باید به یک ماژول مشترک منتقل شود.

**Rollback:** ندارد؛ آسان است.

## §J — فاز ۶: مرکز آزمون و ارزیابی

### D-038 — ارسال، snapshot می‌سازد؛ نمره‌دهی بانک زنده را نمی‌خواند

**Context:** نمره‌دهی می‌توانست از `exam_questions` زنده بخواند یا از یک snapshot. با خواندن زنده، اصلاح یک غلط تایپی در بانک نمرهٔ آزمون ماه گذشته را عوض می‌کند و کسی متوجه نمی‌شود.

**Decision:** سه ستون snapshot در `exam_attempts`: سؤال، سیاست، پاسخ‌ها. `grade_exam` تابعی خالص از snapshot است.

**Consequences:** تغییرناپذیری یک ویژگی ساختاری است، نه یک قول. `regrade_attempt` همیشه همان عدد را بازتولید می‌کند. هزینه: تکرار داده (~۵۰KB به‌ازای هر attempt).

**Rollback:** خواندن از بانک زنده — که پذیرش ROADMAP را می‌شکند.

### D-039 — نسخهٔ سؤال در آزمون قفل می‌شود

**Context:** `exam_items.question_version` می‌توانست ثابت باشد یا «آخرین» در زمان نمره‌دهی حل شود.

**Decision:** عدد ثابت، قفل‌شده در زمان ساخت آزمون.

**Consequences:** آزمون ساخته‌شده با v1 بعد از انتشار v2 هم v1 می‌ماند. هزینه: یک آزمون برای استفاده از نسخهٔ اصلاح‌شده باید از نو ساخته شود.

**Rollback:** غیرممکن بدون بی‌معنا کردن نمره‌های گذشته.

### D-040 — `(exam, user, attempt_no)` هویت attempt است

**Context:** یک retry شبکه‌ای که caller از موفقیت مطمئن نیست، نباید attempt دوم بسازد؛ ولی امتحان مجدد عمدی باید ممکن باشد.

**Decision:** ایندکس یکتای `uq_exam_attempt_identity`. تکرار همان پاسخ ⇒ همان attempt؛ پاسخ متفاوت ⇒ `409`؛ امتحان مجدد ⇒ `attempt_no=2`.

**Consequences:** روی PostgreSQL واقعی اثبات شد (`23505` برای تکرار، پذیرش برای `attempt_no=2`).

**Rollback:** حذف ایندکس — که ثبت دوباره را ممکن می‌کند.

### D-041 — نمرهٔ منفی نسبت است، نه عدد

**Context:** قاعدهٔ کنکور «یک‌سوم» است. به‌صورت `0.33` ثابت برای سؤال ۲ نمره‌ای غلط می‌شود.

**Decision:** `negative_ratio` کسری از وزن همان سؤال.

**Consequences:** برای هر وزنی درست است. اثبات: سؤال ۱ نمره‌ای ⇒ `-1/3`، سؤال ۹ نمره‌ای ⇒ `-3`.

**Rollback:** ستون عدد مطلق.

### D-042 — سؤال خراب void می‌شود و همیشه پرچم بازبینی می‌زند

**Context:** نسخهٔ اول فقط `broken_question_policy='fail_exam'` را پرچم می‌زد. حالت `void` — که پیش‌فرض است — نمره را قابل‌استفاده می‌دانست ولی هیچ‌کس را خبر نمی‌کرد. آزمون این را گرفت.

**Decision:** هر void شدنی `review_required = 1`. تفاوت دو حالت فقط در پیام هشدار است، نه در اینکه کسی خبردار می‌شود.

**Consequences:** یک سؤال غیرقابل‌نمره‌دهی هرگز بی‌سروصدا رد نمی‌شود. هزینه: آزمون‌هایی با کلید ناقص همیشه در صف بازبینی می‌مانند.

**Rollback:** بازگشت به رفتار قبلی — که نقص بانک را پنهان می‌کند.

### D-043 — گزینهٔ متنی قبل از ایندکس تفسیر می‌شود

**Context:** در آزمون ریاضی گزینه‌ها خودشان عدد هستند: `["۳","۴","۵","۶"]`. پاسخ `"۳"` باید گزینهٔ اول باشد. کد ابتدا ایندکس را می‌خواند و پاسخ درست را غلط می‌زد.

**Decision:** جست‌وجوی متن گزینه قبل از تفسیر موقعیتی. سپس ایندکس، سپس حرف لاتین، سپس حرف فارسی.

**Consequences:** روی سرور زنده دیده شد (نمره `2.0001` به‌جای `6.0`). **هیچ آزمون واحدی نگرفت** چون همهٔ آزمون‌ها گزینه‌های حرفی داشتند.

**Rollback:** ندارد؛ ترتیب قبلی غلط بود.

### D-044 — برچسب فارسی «الف» صریح نگاشت می‌شود

**Context:** برگهٔ پاسخ فارسی با الف/ب/ج/د برچسب می‌خورد. «ب» تک‌حرفی بود و کار می‌کرد؛ «الف» سه‌حرفی بود و هرگز مطابقت نمی‌کرد.

**Decision:** نگاشت صریح `{"الف": 0, "آ": 0}`.

**Consequences:** همهٔ پاسخ‌های یک فرم فارسی درست خوانده می‌شوند. **پیش از اصلاح، هر پاسخ اول از چنین فرمی بی‌سروصدا غلط شمرده می‌شد.**

**Rollback:** ندارد.

### D-045 — کلید پاسخ در سرور حذف می‌شود، نه در کلاینت

**Context:** کلید می‌توانست در پاسخ بماند و کلاینت آن را نشان ندهد.

**Decision:** `GET /api/exam/exams/{id}` آیتم‌ها را بدون `answer_key` می‌سازد. آزمون رشتهٔ سریال‌شده را می‌گردد، نه مدل.

**Consequences:** قاعده‌ای که کلاینت اجرا کند با یک کلاینت تغییریافته لغو می‌شود؛ این نسخه نه. هزینه: دو شکل پاسخ برای یک آیتم (پیش و پس از ارسال).

**Rollback:** ندارد.

### D-046 — attempt متعلق به صاحبش است؛ غیرمالک ۴۰۴ می‌گیرد

**Context:** شناسهٔ attempt مبهم است ولی راز نیست. رفتار با آن به‌عنوان capability همان IDOR است.

**Decision:** `GET /api/exam/attempts/{id}` پارامتر `user_id` را با مالک مقایسه می‌کند و در ناسازگاری `404` می‌دهد (نه `403`).

**Consequences:** حدس زدن شناسه چیزی افشا نمی‌کند. هزینه: `user_id` فعلاً از کلاینت می‌آید؛ در تولید باید از نشست بیاید.

## §J۲ — ترمیم فاز ۶ (2026-11-18)

سه باگ واقعی که آزمون‌های فاز ۶ نمی‌دیدند، چون با کلاینت مؤدب نوشته شده بودند. هر سه پیش از اصلاح تولید مثل شدند.

### D-047 — داور یکتایی، ایندکس است نه خواندن

**Context:** `submit_exam` تلاش قبلی را بیرون از تراکنش درج می‌خواند و سپس درج می‌کرد. دو ارسال هم‌زمان هر دو «تلاشی نیست» می‌دیدند و بازنده روی `uq_exam_attempt_identity` با `DatabaseError` می‌مرد — یعنی دانش‌آموزی که دوبار کلیک می‌کرد خطای ۵۰۰ می‌گرفت، همان چیزی که idempotency برای جلوگیری از آن نوشته شده بود.

**Decision:** درج به `_insert_attempt` منتقل شد و `submit_exam` برخورد یکتایی را می‌گیرد و **برندهٔ مسابقه را می‌خواند**. اگر اثر انگشت پاسخ‌ها یکی باشد پاسخ تکراری برمی‌گردد؛ اگر متفاوت باشد همان تعارض ۴۰۹ قبلی.

**Consequences:** خواندن قبل از درج فقط یک بهینه‌سازی است، نه تصمیم. تصمیم را دیتابیس می‌گیرد. هزینه: یک بازخوانی در مسیر برخورد، که نادر است.

**Rollback:** حذف بازیابی — که خطای ۵۰۰ را برمی‌گرداند.

### D-048 — دامنه از پروفایل، و مقدار درخواست **نادیده گرفته می‌شود**

**Context:** `grade_number` و `major_code` از query string خوانده و به‌عنوان محدوده استفاده می‌شدند؛ یک دانش‌آموز پایهٔ هفت روی کاغذ پایهٔ دوازدهم نمره گرفت. سؤال طراحی این بود که مقدار ارسالی را با پروفایل **مقایسه** کنیم یا **دور بریزیم**.

**Decision:** دور ریخته می‌شود. اگر حساب پروفایل دارد، پروفایل حاکم است — بی‌قید به اینکه احراز هویت روشن باشد یا نه. بدون پروفایل و با احراز هویت روشن: ۴۰۳. بدون پروفایل و با احراز هویت خاموش: مقدار ارسالی با علامت `unverified` پذیرفته می‌شود.

**Consequences:** این مقدار هرگز نمی‌تواند دامنه را باز کند، چون خوانده نمی‌شود. مقایسه این فیلد را به یک خطا تبدیل می‌کرد و به کلاینت‌ها یاد می‌داد همچنان بفرستند. هزینه: کلاینتی که عادت دارد پایه را بفرستد، بی‌صدا نادیده گرفته می‌شود — که همان رفتار درست است.

**Rollback:** ندارد؛ بازگشت به رفتار قبلی یعنی حفرهٔ امنیتی.

### D-049 — آزمون رشته‌دار برای دانش‌آموز بی‌رشته باز نیست

**Context:** قاعدهٔ متقارن («رشتهٔ خالی با هر رشته‌ای می‌خواند») ساده‌تر بود، ولی پایه‌های ۱ تا ۹ رشته ندارند — پس «بی‌رشته» حالت طبیعی یک دانش‌آموز هفتم است و قاعدهٔ متقارن فیلتر رشته را تزئینی می‌کرد.

**Decision:** آزمون رشته‌دار فقط برای دانش‌آموزی است که رشتهٔ **همان** آزمون را دارد. بی‌رشته فقط آزمون بی‌رشته می‌بیند.

**Consequences:** فیلتر رشته از کسی محافظت می‌کند. هزینه: قاعده نامتقارن است و باید در هر دو سو (فهرست و ارسال) یکسان نوشته شود؛ `list_exams_in_scope` آینهٔ `require_scope_reaches` است تا از هم جدا نیفتند.

**Rollback:** ندارد.

### D-050 — ۴۰۳ برای دامنه، نه ۴۰۴

**Context:** D-046 برای attempt غیرمالک ۴۰۴ را انتخاب کرد، چون شناسهٔ attempt مبهم است و نباید تأیید کند وجود دارد. آزمون اما **عمومی فهرست شده** است.

**Decision:** نقض دامنهٔ آزمون ۴۰۳ می‌دهد. تفاوت آگاهانه است: برای چیزی که فهرست عمومی‌اش کرده، ۴۰۴ دروغ است و باگ دامنه را پشت خطای به‌ظاهر معقول پنهان می‌کند.

**Consequences:** تفاوت‌گذاری بین دو حالت مستند شد تا کسی آن را ناهماهنگی نگیرد.

**Rollback:** ندارد.

### D-051 — یک resolver برای همهٔ سطوح دامنه‌دار

**Context:** فاز ۵ قاعدهٔ دامنه را در `scope_sql` نوشت، ولی `ingestion.search` همان مقادیر را بدون بررسی از پارامتر می‌گرفت و `catalogue` هم با `(? IS NULL OR ...)` گشایش را دوباره دست‌نویس کرد.

**Decision:** `resolve_enrolment` و `caller_id` در `services/exam/scope.py` تنها راه رسیدن به دامنه‌اند؛ هر دو روتر از آن استفاده می‌کنند.

**Consequences:** قاعده‌ای که در تابع بعدی دوباره دست‌نویس شود قاعده نیست. هزینه: نام ماژول `exam` است ولی `ingestion` هم از آن استفاده می‌کند؛ اگر سطح سوم اضافه شود، ماژول باید به `services/scope` منتقل شود.

**Rollback:** جابه‌جایی فایل؛ رفتار تغییر نمی‌کند.

## §K — فاز ۷: تسلط، کارت‌های مرور و مرور شخصی‌شده (2026-11-18)

### D-052 — زمان‌بند مرور، یک تابع خالص است و `now` پارامتر است

**Context:** `SpacedRepetitionScheduler` موجود ساعت را خودش می‌خواند (`time.time()` در چند نقطه). ROADMAP الگوریتم deterministic می‌خواهد. اگر تابع خودش ساعت بخواند، تنها چیزی که می‌توان آزمود «چیزی تولید کرد» است، نه «همان ورودی همان خروجی».

**Decision:** `services/review/schedule.py` هیچ ساعتی نمی‌خواند؛ `now` پارامتر است و `schedule(state, type, rating, now=...)` خالص است. زمان‌بندی واقعی به همان `SpacedRepetitionScheduler` واگذار می‌شود.

**Consequences:** determinism و بازپخش تاریخچه آزمون‌پذیر شد. هزینه: هر فراخوان باید لحظه را پاس بدهد، و یک فراخوان بی‌دقت می‌تواند زمان اشتباه بدهد — که با یک نقطهٔ واحد (`_epoch`) در مخزن مدیریت شده.

**Rollback:** خواندن ساعت درون تابع — که determinism را از بین می‌برد.

### D-053 — چهار دکمهٔ مرور، نه یک کیفیت استنباط‌شده

**Context:** سیستم mastery کیفیت را از نتیجه استنباط می‌کند. مرور کارت ورودی انسانی دارد.

**Decision:** چهار رتبه: `again`/`hard`/`good`/`easy` با کیفیت ۰.۰/۰.۴/۰.۷/۱.۰ و نگاشت نامتقارن (hard نزدیک‌تر به again تا به good).

**Consequences:** ورودی ساده و پایدار. هزینه: پنج‌درجه‌ای‌ها دقت بیشتری می‌دهند؛ ولی ورودی ناپایدار نویز زمان‌بندی می‌شود. رتبهٔ ناشناخته **خطا** است، نه پیش‌فرض — مقدار غیرمنتظره یک باگ بالادست است.

**Rollback:** افزودن رتبه‌ها؛ نگاشت می‌تواند گسترش یابد.

### D-054 — dedup با ایندکس یکتایی است، نه پیمایش دوره‌ای

**Context:** dedup می‌توانست یک پاس دوره‌ای باشد یا یک قید.

**Decision:** `content_key = sha256(متن نرمال‌شده | نوع provenance | شناسهٔ provenance)` با `UNIQUE (user_id, content_key)`. افزودن تکراری **خطا نیست**؛ پاسخ تکراری با `duplicate=True` برمی‌گردد.

**Consequences:** تولید دوبارهٔ deck از همان فصل بی‌خطر است. هزینه: نرمال‌سازی باید درست باشد وگرنه نشت می‌کند — پوشش: فاصله، حروف، ZWNJ/ZWJ، ارقام فارسی/عربی، ی/ک.

**Rollback:** ندارد.

### D-055 — provenance بخشی از هویت کارت است

**Context:** آیا یک سؤال از دو فصل یک کارت است یا دو؟

**Decision:** دو کارت، چون provenance در `content_key` است.

**Consequences:** «مشتق چیست؟» در فصل ۲ و فصل ۵ دو کارت است، که درست است چون یکی ممکن است ساده‌سازی دیگری باشد. هزینه: تکرار متنی بین فصل‌ها تکرار کارت می‌سازد.

**Rollback:** حذف شناسهٔ provenance از کلید — که کارت‌های واقعاً متفاوت را یکی می‌کند.

### D-056 — «بدون شاهد» صفر نیست، غایب است

**Context:** داشبورد تسلط می‌توانست برای فصل بدون داده `0.0` بدهد.

**Decision:** `mastery = None` و گروه در خروجی غایب است.

**Consequences:** «هیچ‌وقت ندیدیم» و «همیشه غلط» یکی نمی‌شوند. هزینه: کلاینت باید `null` را مدیریت کند، و توصیهٔ تمرین برای گروه بدون داده ساخته نمی‌شود.

**Rollback:** ندارد؛ صفر کردن یک دروغ است.

### D-057 — کارت‌های مرور متعلق به ماژول `mastery` اند، نه `server`

**Context:** روتر تازه `deeptutor.learning` را import می‌کند و `server` اجازهٔ این وابستگی را ندارد. `tests/modules/test_isolated_features.py` این را گرفت.

**Decision:** `services/review`، `api/routers/flashcards.py` و `db/repositories/flashcards.py` به manifest ماژول `mastery` اضافه شدند، که از قبل `deeptutor/learning` را دارد.

**Consequences:** مرز ماژول دست‌نخورده ماند و ۲۵ آزمون جداسازی سبز است. هزینه: مرور شخصی‌شده به نصب ماژول mastery گره خورد، که از نظر محصول درست است.

**Rollback:** ندارد.

### D-058 — مرور کارت وضعیت زمان‌بندی را از مسیر ویرایش جدا می‌کند

**Context:** `update_card` می‌توانست هر ستونی را بنویسد.

**Decision:** فقط `front`/`back`/`hint`/`status`. `due_at` و `review_count` فقط از `review_card` حرکت می‌کنند.

**Consequences:** تاریخچه همیشه وضعیت را توضیح می‌دهد. هزینه: اصلاح دستی یک زمان‌بندی خراب مسیر جدا می‌خواهد (که بعداً و با ثبت شاهد اضافه می‌شود، نه با ویرایش خاموش).

**Rollback:** ندارد.

### D-059 — hold در جدول جدا، نه در کیف پول

**Context:** `user_wallets` قید `CHECK (tokens_remaining = tokens_total - tokens_used)` دارد. رزروی که فقط `tokens_remaining` را کم کند این قید را می‌شکند.

**Decision:** `media_reservations` جدول جدا؛ `available = tokens_remaining − Σ(open reserved_tokens)` و این محاسبه **داخل** تراکنش درج رزرو انجام می‌شود.

**Consequences:** قید کیف پول دست‌نخورده و معنادار ماند؛ overdraw غیرممکن است چون check و write اتمیک‌اند. هزینه: هر خواندن موجودی یک subquery اضافه دارد، و یک آزمون جهش لازم بود چون SQLite race را پنهان می‌کند.

**Rollback:** ندارد؛ شل‌کردن CHECK راهی است که یک روز موجودی منفی تولید می‌کند.

### D-060 — لایسنس داخل کلید کش است

**Context:** دو رندر با متن یکسان ولی مجوز متفاوت.

**Decision:** `sha256(kind | script | source_id | licence | render_settings)`.

**Consequences:** تغییر مجوز cache miss می‌دهد و شرایط قدیمی بی‌صدا منتقل نمی‌شود. هزینه: دارایی تکراری وقتی مجوز عوض شود — که همان جهت امن است.

**Rollback:** دارد اگر مجوز واقعاً بی‌اثر شود، که نیست.

### D-061 — کش per-user است، نه global

**Context:** دو دانش‌آموز همان درس را می‌خواهند.

**Decision:** `(user_id, content_hash)`.

**Consequences:** ذخیره‌سازی به سهمیهٔ درست حساب می‌شود. هزینه: بایت تکراری روی دیسک. این معاوضه آگاهانه است: یک دارایی مشترک پشت سهمیهٔ یک نفر، یک شکایت صورتحساب است.

**Rollback:** دارد، اگر سیاست ذخیره‌سازی مشترک شود (با مدل سهمیهٔ گروهی، نه شخصی).

### D-062 — شکست غیرنهایی hold را آزاد نمی‌کند

**Context:** نسخهٔ اول در هر شکست refund می‌کرد؛ تلاش دوم چیزی برای settle نداشت.

**Decision:** refund فقط وقتی `attempts >= max_attempts`. hold متعلق به **خرید** است، نه **تلاش**.

**Consequences:** retry روی یک hold کار می‌کند و هزینه دوبار حساب نمی‌شود. هزینه: jobی که برای همیشه در صف گیر کند، hold را نگه می‌دارد — که خودش سیگنال درست است، نه باگ.

**Rollback:** ندارد.

### D-063 — هزینهٔ غیرتوکنی به توکن تبدیل نمی‌شود

**Context:** provider ویدیو بر ثانیه صورت‌حساب می‌کند، کیف پول بر توکن.

**Decision:** `non_token_units` / `non_token_unit` / `non_token_cost_toman` جدا ثبت می‌شوند.

**Consequences:** هیچ نرخ اختراعی وارد accounting نشد و Gate 8 می‌تواند هزینهٔ واقعی را ببیند. هزینه: جمع‌زدن دو واحد متفاوت کار گزارش است، نه یک ستون واحد.

**Rollback:** دارد اگر نرخ رسمی و ثابت تعریف شود.

### D-064 — provenance از منبع متن می‌آید، نه از پارامتر caller

**Context:** caller می‌توانست `source_id` بدهد بدون اینکه متن منبع را بدهد.

**Decision:** اگر متن از prompt است، `provenance = user_prompt` و `source_id = None`؛ و متن منبع بدون `source_id` خطاست.

**Consequences:** یک دارایی نمی‌تواند خودش را مجوزدار جا بزند. هزینه: caller باید هر دو را با هم بدهد.

**Rollback:** ندارد.

### D-065 — شکست رسانه از chat جدا می‌ماند چون صف مشترک فقط نام‌فضا دارد

**Context:** الزام پذیرش: «خطای ویدئو/صوت chat عادی را مختل نکند.»

**Decision:** kindها با پیشوند `media.` وارد صف مشترک می‌شوند و `run_once` نوع ناشناس را عمداً fail می‌کند؛ هر نوع handler خودش را دارد.

**Consequences:** یک job رسانه‌ای که منفجر شود، فقط خودش را fail می‌کند. این با اجرای واقعی اثبات شد: پس از شکست ویدیو، `/health`, `/health/ready`, `/api/platform/health/live` همه ۲۰۰ ماندند.

**Rollback:** ندارد.

### D-066 — خواندن و مالکیت دو محمول جدا هستند

**Context:** عملیات مالک‌محور (حذف، ابطال اشتراک، فهرست اشتراک‌ها) از `get_asset` استفاده می‌کردند که «آیا این شخص می‌تواند بخواند؟» را جواب می‌دهد. وقتی اشتراک‌گذاری اضافه شد، گیرنده هم «می‌توانست بخواند» — پس می‌توانست حذف کند.

**Decision:** `_require_owner` برای هر عملیاتی که مالکیت می‌خواهد؛ `get_asset` فقط برای خواندن.

**Consequences:** افزایش سطح دسترسی بسته شد و جهش آن را می‌گیرد (۴ آزمون). هزینه: دو تابع با نام مشابه که تفاوتشان مهم است — که با نام‌گذاری صریح پوشش داده شد.

**Rollback:** ندارد. یک محمول مشترک برای دو سؤال متفاوت، همان الگویی است که این باگ را ساخت.

### D-067 — اشتراک یک ردیف است، نه یک پرچم

**Context:** «یا کسی که مجاز است» می‌توانست با ستون `visibility` حل شود.

**Decision:** جدول `media_asset_grants` با `granted_by`، `expires_at`، `revoked_at`؛ یک ردیف برای هر (دارایی، گیرنده).

**Consequences:** «چه کسی و چه زمانی و چرا» قابل پاسخ است؛ انقضا بدون job پاک‌سازی بسته می‌شود؛ ابطال تاریخچه را حفظ می‌کند. هزینه: یک join در مسیر خواندن. `visibility` فقط می‌توانست بگوید «همه»، که هیچ‌کدام از موارد واقعی کلاس نیست.

**Rollback:** دارد، اگر اشتراک همیشه عمومی شود — که نمی‌شود.

### D-068 — گیرنده نمی‌تواند دوباره به اشتراک بگذارد

**Context:** دریافت‌کنندهٔ اشتراک یک asset دیگر هم «دسترسی» دارد.

**Decision:** فقط مالک می‌تواند grant بسازد و ابطال کند.

**Consequences:** اشتراک، اختیار مالک را کپی نمی‌کند. هزینه: اشتراک گروهی باید از مالک عبور کند. این هزینه پذیرفته است چون جایگزینش — توزیع بی‌صدا — همان چیزی است که یک درس خصوصی را به گروه چت می‌رساند.

**Rollback:** دارد، اگر مدل نقش (معلم/دانش‌آموز) اضافه شود؛ آن‌وقت باید صریح باشد، نه ضمنی.

### D-069 — انقضای اشتراک در زمان خواندن بررسی می‌شود

**Context:** grant با `expires_at` می‌توانست با یک cron منقضی شود.

**Decision:** `has_access` شرط `expires_at IS NULL OR expires_at > now` را در همان query دارد.

**Consequences:** اشتراک منقضی همان لحظه بسته است، بدون پنجرهٔ بین انقضا و اجرای پاک‌سازی. هزینه: یک مقایسهٔ رشته‌ای در مسیر داغ خواندن.

**Rollback:** ندارد؛ یک cron که دیر اجرا شود یک حفرهٔ امنیتی است.

### D-070 — ذخیره‌سازی به‌جدا از توکن حساب می‌شود

**Context:** `storage_used_bytes` وجود داشت و studio هرگز آن را تغییر نمی‌داد.

**Decision:** ساخت دارایی کسر می‌کند، حذف آزاد می‌کند، `can_store` پیش از رندر پرسیده می‌شود.

**Consequences:** سهمیهٔ ذخیره‌سازی واقعاً اعمال می‌شود. ساخت دارایی بدون wallet شکست نمی‌خورد (بایت و توکن قبلاً خرج شده‌اند)، ولی اگر wallet وجود داشته باشد و سهمیه پر باشد، خطا می‌دهد.

**Rollback:** ندارد.

### D-071 — renderer محلی واقعی می‌سازد، ولی ویدیو نمی‌سازد

**Context:** Gate 8 «یک smoke واقعی» می‌خواهد، ولی هیچ provider پولی در دسترس نیست.

**Decision:** `render.py` با Pillow و `wave` خروجی واقعی می‌سازد. `video_lesson` یک **storyboard** است و در فیلد `content` و در نام صریحاً همین را می‌گوید. `audio_overview` لحن جایگزین است، نه گفتار.

**Consequences:** خط تولید با بایت واقعی آزموده می‌شود و هزینه از خروجی اندازه‌گیری می‌شود (نه از جدول). هزینه: هیچ‌کدام از این دو «درس» قابل ارائه به دانش‌آموز نیستند و این در خروجی خودشان نوشته شده.

**Rollback:** دارد، وقتی provider واقعی وصل شود — که `render_local` را جایگزین می‌کند و بقیهٔ زنجیره دست‌نخورده می‌ماند.

### D-072 — شکل‌دهی فارسی اجباری است، نه اختیاری

**Context:** PIL بدون raqm حروف فارسی را جدا و برعکس می‌کشد.

**Decision:** `shape()` اگر `arabic-reshaper` و `python-bidi` نباشند **خطا می‌دهد**؛ renderer امتناع می‌کند.

**Consequences:** هیچ‌وقت درسِ خراب با صورت‌حساب درست تولید نمی‌شود. هزینه: وابستگی اجباری در extra `studio` — که همان‌جا اعلام شد تا کسی مجبور نشود کشفش کند.

**Rollback:** ندارد. یک تصویر خراب از یک خطا بدتر است، چون خرابی ماندگار است و خطا نه.

### D-073 — تخمین‌ها غلط از آب درآمدند و این یک یافته است

**Context:** اندازه‌گیری با renderer واقعی نشان داد `DEFAULT_ESTIMATES` بین ۲۰ تا ۵۰ برابر بیشتر از هزینهٔ واقعی است.

**Decision:** تخمین‌ها به‌عنوان **سقف** نگه داشته می‌شوند، نه تعرفه؛ و شمارش `actual` منبع حقیقت است.

**Consequences:** hold محافظه‌کارانه است، پس overdraw رخ نمی‌دهد، ولی موجودیِ قابل استفاده بدبینانه نمایش داده می‌شود. اگر Gate 8 را بر پایهٔ این جدول می‌پذیرفتیم، یک عدد ۲۰ برابر غلط را پذیرفته بودیم. اعداد واقعی provider لازم است.

**Rollback:** دارد، وقتی اعداد واقعی اندازه‌گیری شوند.

### D-074 — worker جدا از فرایند API اجرا می‌شود

**Context:** یک job ویدیو دقیقه‌ها طول می‌کشد.

**Decision:** `python -m deeptutor.services.studio.worker` مستقل؛ اجرا داخل فرایند سرویس‌دهنده انجام نمی‌شود.

**Consequences:** بدون worker، job در صف می‌ماند و API کامل پاسخ‌گو است — که همان الزام «خطای ویدیو chat را مختل نکند» است و با اجرای واقعی اثبات شد. هزینه: یک فرایند استقرار اضافه.

**Rollback:** ندارد.

### D-075 — مجوز برای محتوای منبع‌دار اجباری است

**Context:** یک دارایی می‌توانست از `src_9` ساخته شود با `licence_code = ''`. ردیف می‌گفت از کجا آمده و هیچ نمی‌گفت با چه حقی. کش و provenance هر دو روی فیلدی تکیه می‌کردند که تهی بودنش یعنی هیچ.

**Decision:** `licence_required` در سرویس + رد در سطح ثبت. این یک سیاست مجوزدهی **نیست** — نمی‌داند کدام کد معتبر است، فقط از ثبت منبع بدون شرایطش امتناع می‌کند.

**Consequences:** هیچ دارایی منبع‌داری بدون شرایط ثبت نمی‌شود. هزینه: کلاینت باید هنگام ارسال `source_id` مجوز هم بفرستد؛ خطای ۴۲۲ گویاست. محتوای ساخته‌شده از prompt کاربر مجوز نمی‌خواهد، چون چیزی استفاده نشده.

**Rollback:** ندارد. مجوز اختیاری یک فیلد تزئینی است.

### D-076 — حذف اول بایت‌ها را می‌برد، بعد شمارنده را

**Context:** نسخهٔ قبل شمارنده را صفر می‌کرد و فایل را نگه می‌داشت. با سه چرخهٔ ساخت/حذف، ~۱۵KB در هر چرخه بی‌آنکه جایی دیده شود هدر می‌رفت.

**Decision:** ترتیب: بایت‌ها → شمارنده → tombstone. اگر شیء از قبل نبود، شمارنده هنوز درست می‌شود (`delete` که `False` برمی‌گرداند یعنی «از قبل نبود»، نه شکست).

**Consequences:** سهمیه و دیسک با هم می‌خوانند. اثبات: پس از سه چرخه دیسک صفر رشد کرد و شمارنده صفر شد. هزینه: حذف حالا به store وابسته است؛ اگر store استثنا بدهد، خطای `storage_delete_failed` داده می‌شود تا نیمه‌حقیقت «حذف شد» گفته نشود.

**Rollback:** ندارد.

### D-077 — داوری انسانی سه‌مقداری است و استقلال جدا شمرده می‌شود

**Context:** `quality_checklist` سؤال‌ها را می‌داد و جایی برای جواب نبود؛ Gate 8 داوری انسانی می‌خواست.

**Decision:** جدول `media_quality_reviews`؛ verdict ∈ {pass, fail, unclear}؛ `review_status` دو عدد جدا می‌دهد: `complete` و `independent_reviews`.

**Consequences:** خودداوری مجاز و ثبت‌شدنی است ولی مستقل شمرده نمی‌شود، پس گزارش نمی‌تواند شواهد را بیش از واقعیت جلوه دهد. `unclear` اطمینان کاذب تولید نمی‌کند. هزینه: هر بازبینی نیاز به هویت بازبین دارد.

**Rollback:** ندارد.

### D-078 — قید مجوز در سطح جدول، با trigger نه CHECK

**Context:** بررسی سرویس‌سطحی را نویسندهٔ بعدی می‌تواند دور بزند.

**Decision:** تضمین در سطح *جدول* است، ولی با **trigger** که در زمان راه‌اندازی نصب می‌شود (`services/studio/integrity.ensure_guards`)، نه با `CHECK` در مایگریشن. دو دلیل: SQLite نمی‌تواند `CHECK` را به جدول موجود اضافه کند بدون بازسازی کامل، و بدنهٔ trigger به `BEGIN ... END` نیاز دارد که قطعه‌کنندهٔ دستورات این پروژه نمی‌فهمد. نصب در زمان راه‌اندازی یک ویژگی مهم دارد: یا نصب می‌شود یا استثنا می‌دهد — هیچ مسیری نیست که جدول باشد و قید بی‌صدا نباشد.

**Consequences:** درج خام که سرویس را کامل دور می‌زند مسدود می‌شود (اثبات‌شده با آزمون). ردیف‌های legacy با مجوز خالی دیدنی‌اند و پاک‌سازی‌شان خودکار نیست. هزینه: یک گام نصب اضافه در راه‌اندازی، و trigger فقط روی SQLite — اگر روزی دیتابیس دیگری اضافه شود، این باید بازبینی شود.

**Rollback:** دارد، اگر مایگریشن‌ها روزی compound statement را پشتیبانی کنند؛ آن‌وقت trigger به مایگریشن منتقل می‌شود.

### D-079 — مجوز یک مجموعهٔ اختیارات است، نه یک رشته

**Context:** D-075 مجوز را اجباری کرد ولی هیچ‌چیز نمی‌دانست «cc-by» یعنی چه. هر رشتهٔ ناتهی می‌گذشت، پس `citation-only` — که اجازهٔ نقل قول می‌دهد و نه ساختن درس — دقیقاً مثل `cc-by` رفتار می‌کرد. یک فیلد اجباری که محتوایش بی‌معناست، فقط یک فیلد اجباری است.

**Decision:** `services/studio/licences.py` یک registry دارد: هر کد مجموعه‌ای از اختیارات (`reproduce`, `adapt`, `render_audio`, `render_visual`, `redistribute`) و مجموعه‌ای از تعهدات است؛ هر kind مجموعه‌ای از نیازها. `check(code, kind)` اگر اختیار لازم را ندارد **رد می‌کند** (`licence_insufficient`), اگر کد ناشناخته باشد **رد می‌کند** (`unknown_licence`)، و اگر تعهدی داشته باشد که pipeline نمی‌تواند انجام دهد **رد می‌کند** (`licence_obligation_unsupported`). صفر نتیجه: رد.

**Consequences:** «داریم این کتاب را رندر می‌کنیم» حالا به «با چه اجازه‌ای» گره خورده و جواب ماشین‌خوان است. `citation-only` برای هر پنج kind رد می‌شود، `cc-by` برای همه پذیرفته. **آنچه این حل نمی‌کند:** اینکه آیا ما واقعاً آن مجوز را برای آن کتاب داریم همچنان سؤال انسانی است (Gate 5/6). این registry ادعای حقوق را *اجرا* می‌کند، نمی‌سازد. هزینه: نگهداری registry؛ کد مجوزی که در آن نیست رد می‌شود، که خودش یک شکست قابل‌دیدن بهتر از یک پذیرش خاموش است.

**Rollback:** ندارد.

### D-080 — بار حقوقی روی خودِ محصول سوزانده می‌شود

**Context:** تعهد attribution در D-079 ثبت شد، ولی جایی که کاربر می‌بیند فقط یک ردیف در دیتابیس بود. تعهدی که فقط در جدولی خوانده می‌شود که کسی نمی‌بیند، انجام نشده است.

**Decision:** رشتهٔ attribution در `submit` ساخته می‌شود (یک‌بار، تا هر renderer همان را بزند) و در `RenderSettings.attribution` به تصویر کشیده می‌شود. متن ترکیبی فارسی/لاتین روی `—` شکسته می‌شود: فقط بخش فارسی شکل‌دهی و راست‌چین می‌شود، بخش لاتین ساده و چپ‌چین، و فونت تا جا شدن کوچک می‌شود.

**Consequences:** PNG با و بدون attribution بایت‌های متفاوت دارد (آزمون‌شده)، و URL بلند بریده نمی‌شود. **آنچه این حل نمی‌کند:** attribution برای kindهایی که متنی نیستند (چیزی که خوانده نمی‌شود) راه دیگری لازم دارد؛ فعلاً همهٔ kindها تصویر یا متن می‌سازند. هزینه: یک پارامتر اضافه در مسیر رندر و یک تابع رسم که باید بی‌دقت نکند.

**Rollback:** دارد: `attribution = ""` رسم را حذف می‌کند، ولی آن‌وقت تعهد نقض می‌شود — پس عملاً ندارد.

### D-081 — هزینه با tokenizer واقعی سنجیده می‌شود، و اگر نباشد با عددی که خطایش نوشته شده

**Context:** D-073 گفت تخمین‌ها ۲۰ تا ۵۰ برابر غلط‌اند و باید اندازه‌گیری شوند. اولین پیاده‌سازی `len(text) // 4` بود — قاعدهٔ سرانگشتی انگلیسی. با cl100k واقعی سنجیده شد: **۶۰٪ کم‌شمارش روی فارسی (۲.۹ برابر)**، چون فارسی بدون مصوت کوتاه نوشته می‌شود و cl100k برای خط عربی تقریباً هیچ merge ندارد؛ یک واژهٔ ۴ حرفی فارسی ~۳.۵ توکن است، در حالی که واژهٔ ۹ حرفی انگلیسی می‌تواند یک توکن باشد.

**Decision:** دو مدل، یکی برای هر خط: فارسی ~۰.۸۷ توکن بر حرف، لاتین ۱ توکن بر واژه + ۱ بر هر ۴ حرف بیش از هفت. اگر فایل BPE روی دیسک باشد (`DEEPTUTOR_TIKTOKEN_BPE` یا cache مستقیم)، tokenizer واقعی استفاده می‌شود و عدم‌قطعیت صفر گزارش می‌شود؛ در غیر این صورت تخمین‌گر با خطای کالیبره‌شده گزارش می‌شود.

**Consequences:** روی ۲۰ جمله (۶۷۶ توکن واقعی) خطای تخمین‌گر **۰.۶٪** است، در برابر ۵۵.۵٪ روش قبلی. هر پاسخ شمارش `method` و `uncertainty` را حمل می‌کند، و `GET /api/studio/cost/method` آن را عمومی می‌کند. اعداد مرجع در `tests/data/cl100k_reference.json` کامیت شده‌اند تا CI بدون شبکه صحت کالیبراسیون را بسنجد و با `scripts/measure_tokens.py --check` بازتولید شوند. **آنچه این حل نمی‌کند:** هزینهٔ واقعی provider. این شمارش توکن است، نه صورتحساب؛ تعرفهٔ دلاری هنوز لازم است و روی این host هیچ کلید provider وجود نداشت. هزینه: فایل مرجع باید وقتی متن نمونه عوض می‌شود بازتولید شود، وگرنه آزمون می‌شکند — که خودش هدف است.

**Rollback:** ندارد. عدد بدون منبع خراب‌تر از نبودِ عدد است.

### D-082 — ظرفیت با اندازه‌گیری، و اندازه‌گیری با شکلِ منحنی

**Context:** Gate 8 ستون capacity می‌خواست و «کار می‌کند» پاسخ نبود.

**Decision:** `scripts/measure_capacity.py` چهار سطح بار را می‌سنجد و نتیجه در evidence ثبت می‌شود. آزمون‌ها عدد مطلق را قفل نمی‌کنند (به host وابسته است)؛ رفتار را قفل می‌کنند: هیچ job گم نمی‌شود، هیچ hold بعد از تسویه باز نمی‌ماند، و burst با concurrency بالاتر کار را از دست نمی‌دهد.

**Consequences:** اندازه‌گیری روی این host: throughput حدود ۷۵–۸۶ job/ثانیه و صاف تا concurrency ۱۲، اما p50 تأخیر از ۱۳ms (تک‌رشته) به ۲۵۳ms (۲۴ رشته) می‌رود و در ۲۴ رشته throughput هم ۷۶ می‌شود — یعنی **گلوگاه SQLite است، نه رندر**. حافظه در ۱۲۰ job تنها ۱۰MB رشد کرد. **آنچه این حل نمی‌کند:** این اعداد rendererهای محلی (Pillow + stand-in) هستند؛ rate limit provider، تأخیر شبکه و throughput GPU اندازه‌گیری نشده و روی این host قابل اندازه‌گیری نیست، چون هیچ provider واقعی در دسترس نبود.

**Rollback:** ندارد.

### D-083 — retry رزرو را نگه می‌دارد؛ این یک انتخاب با هزینهٔ شناخته‌شده است

**Context:** آزمون ظرفیت نشان داد jobی که شکست می‌خورد و در انتظار retry است، hold توکن را باز نگه می‌دارد. backoff نمایی است (۲، ۴، ۸ ثانیه)، پس تا ۱۴ ثانیه توکن قفل می‌ماند.

**Decision:** رفتار حفظ می‌شود. اگر در اولین شکست refund کنیم، رزرو بسته می‌شود و retry چیزی برای تسویه ندارد — یا کاربر دوباره شارژ می‌شود یا هیچ‌وقت. تسویهٔ درست مهم‌تر از آزادسازی زودتر است.

**Consequences:** توکن‌ها در دورهٔ backoff در `tokens_available` دیده نمی‌شوند. با `MAX_BACKOFF_SECONDS` کران دارد، پس قفل بی‌پایان نیست. **آنچه این حل نمی‌کند:** کاربری که حجم بالایی job شکست‌خورده دارد، موقتاً فقیرتر از واقعیت دیده می‌شود. اگر این در عمل آزار داد، راه درست refund-plus-rehold است، نه refund زودتر. آزمون هر دو نیمه را قفل می‌کند: hold در حین retry باقی می‌ماند و پس از اتمام تلاش‌ها آزاد می‌شود.

**Rollback:** دارد، به قیمت تسویهٔ دوباره در مسیر retry.

### D-084 — `all-rights` یک مجوز ثبت‌شده است، نه یک کد ناشناخته

**Context:** آزمون از قبل موجود `test_a_different_licence_is_not_a_cache_hit` با `all-rights` می‌نوشت و پس از D-079 شکست، چون registry آن را نمی‌شناخت.

**Decision:** ثبت صریح `all-rights` با همهٔ اختیارات و بدون تعهد.

**Consequences:** کاربری که کتاب خودش را آپلود می‌کند همان واژه‌ای را می‌زند که طبیعتاً می‌زند و «کد ناشناخته» نمی‌بیند. **درس عمومی:** وقتی یک قید جدید آزمون قدیمی را می‌شکند، دو احتمال است — یا آزمون چیز درستی می‌خواست، یا خودِ قید ناقص است. اینجا دومی بود، و تفاوت بین «بستن آزمون» و «شنیدنِ آن» همین است.

**Rollback:** هیچ; کد ثبت‌شده‌ای که حذف شود، دارایی‌های موجود را یتیم می‌کند.

### D-085 — هزینه در پول ثبت می‌شود، نه فقط در توکن

**Context:** دفتر هزینه `tokens` و یک رقم تومانی برای واحدهای غیرتوکنی داشت، ولی هیچ رقم دلاری‌ای برای خودِ توکن‌ها نداشت. «۱۸۵ توکن» هزینه نیست؛ فقط وقتی هزینه می‌شود که در نرخ provider ضرب شود، و آن نرخ جای دیگری زندگی می‌کند.

**Decision:** `V0013` ستون `cost_microusd` (عدد صحیح) و `price_json` اضافه می‌کند. `pricing.py` نرخ‌ها را از کاتالوگ عمومی provider می‌خواند، با تاریخ خواندن. `RenderResult` سه فیلد تازه دارد و `record_cost` همه را می‌نویسد.

**Consequences:** یک درس روی ارزان‌ترین endpoint پرداختی **۴۲ میکرودلار** است — هزار درس **۴.۲ سنت**. این عددی است که Gate 8 قبلاً نمی‌توانست بگوید. **چرا عدد صحیح:** نرخ‌ها بین ۶e-۸ و ۱.۸۳e-۶ دلار بر توکن‌اند؛ ذخیره به‌صورت REAL یعنی ذخیرهٔ عددی که ارقام معنادارش زیر یک سنت است، و دفتری که float جمع می‌زند دقیقاً همان‌جایی خطا می‌گیرد که کسی نگاه نمی‌کند. **چرا NULL ≠ صفر:** endpoint رایگان واقعاً صفر است؛ renderer بی‌قیمت واقعاً نامعلوم. یکی‌کردن این دو، همان راهی است که گزارش به ادعای هزینه‌ای می‌رسد که هرگز اندازه‌گیری نکرده. آزمون روی ۲۵ توکن با نرخ ارزان‌ترین endpoint قفل شده: Decimal مقدار ۲ می‌دهد، float مقدار ۱ — و ۳۹۶ مورد اختلاف از این دست در کاتالوگ وجود دارد.

**Rollback:** دارد: ستون‌ها nullable هستند و حذفشان داده از دست نمی‌دهد، فقط رقم دلاری را برمی‌دارد.

### D-086 — طرح رایگان با «سقف درخواست» بسته می‌شود، نه با هزینه

**Context:** مدل `nvidia/nemotron-3.5-super-vl:free` دقیقاً صفر قیمت دارد. اگر گزارش فقط همین را بگوید، نتیجه‌گیری طبیعی «پس بی‌نهایت درس می‌توانیم بسازیم» است — و غلط است.

**Decision:** هر نقل‌قول قیمت همراه با `daily_ceiling` منتشر می‌شود. برای endpoint رایگان، محدودکنندهٔ واقعی **تعداد درخواست** است: ۲۰ در دقیقه و **۵۰ در روز** (یا ۱۰۰۰ در روز اگر ۱۰ دلار اعتبار خریده باشید). `GET /api/studio/pricing` این را برمی‌گرداند.

**Consequences:** عدد ظرفیت این فاز (۸۶ job بر ثانیه) با طرح رایگان **بی‌معنا** است: گلوگاه ۵۰ درس در روز است، یعنی ۵٫۸ در ساعت. این تفاوت بین «مقرون‌به‌صرفه است» و «کافی است» را نشان می‌دهد. **آنچه این حل نمی‌کند:** چرا سقف ۵۰ است و آیا برای pilot کافی است — این تصمیم محصولی است، نه فنی. هزینه: کاتالوگ قیمت باید نگهداری شود؛ مدلی که در آن نیست خطا می‌دهد، نه نرخ حدسی.

**Rollback:** ندارد. سقفی که پنهان شود، در production کشف می‌شود.

### D-087 — provider وصل شد ولی از این sandbox فراخوانی نمی‌شود؛ تفکیکش را نوشتم

**Context:** کاربر کلید OpenRouter و مدل را داد. سنجش نشان داد `openrouter.ai` و `api.openai.com` و `api.anthropic.com` از این sandbox در لایهٔ TLS بسته‌اند — DNS حل می‌شود و TCP وصل می‌شود، ولی handshake از سمت شبکه قطع می‌شود؛ حتی HTTP ساده هم پاسخ نمی‌دهد. `github.com` و `pypi.org` کار می‌کنند، پس فیلتر انتخاب egress است.

**Decision:** سه چیز جدا گزارش می‌شود: (۱) **کد ما درست است** — با یک stand-in محلی که همان قرارداد OpenAI را دارد، مسیر `/api/v1/chat/completions`، هدر `Bearer`، و ارسال مدل با `:free` تأیید شد؛ (۲) **قیمت واقعی است** — از کاتالوگ عمومی provider خوانده شد، نه از حافظه؛ (۳) **completion واقعی اجرا نشد** — هیچ پیام مدلی تولید نشد.

**Consequences:** Gate 8 ستون cost اکنون **قیمت‌گذاری‌شده** است، ولی هزینهٔ *اندازه‌گیری‌شده* هنوز نه: عدد از توکن‌های محاسبه‌شده × نرخ منتشرشده می‌آید، نه از صورتحساب واقعی. `provider` در رکورد `openrouter` است و `cost_method` می‌گوید توکن‌ها چطور شمرده شدند. **آنچه این حل نمی‌کند:** اینکه provider واقعاً چه چیزی برگرداند و آیا فاکتور مطابق این عدد است — آن را فقط یک اجرای واقعی می‌گوید، و روی این host ممکن نیست.

**Rollback:** ندارد؛ کلید در هیچ فایلی ذخیره نشد و فقط از متغیر محیطی خوانده می‌شود.

### D-088 — برای داوری انسانی، خودِ بسته باید درست باشد

**Context:** ستون quality باز مانده بود چون `independent_reviews = 0`. راه‌حل بدیهی «یک بازبین پیدا کن» است، ولی بازبین به چیزی نیاز دارد که داوری کند و ابزاری که داوری را ثبت کند. اگر آن بسته خراب باشد، داوری حاصل، شاهدی دربارهٔ چیزی است که کسی ندیده.

**Decision:** `scripts/build_review_package.py` یک پوشهٔ خودبسنده می‌سازد: پنج اثر واقعی از renderer واقعی، `review.html` که بدون اینترنت کار می‌کند، `verdict_template.json` برای کسی که مرورگر ندارد، `load_verdict.py` که داوری را از راه همان `record_review` ثبت می‌کند، و `manifest.json` با hash هر فایل تا داوری به دقیقاً همان چیزی گره بخورد که دیده شده. داوری خود شخص با `reviewer == owner` در loader **رد می‌شود**.

**Consequences:** حلقه بسته شد و با اجرا اثبات شد: خودداوری `complete=true, independent=0`؛ داوری مستقل روی همان هفت آیتم `independent=7, independently_reviewed=true`. **آنچه این حل نمی‌کند:** پیدا کردن آن انسان. ابزار، کار او را از «راه‌اندازی دیتابیس و صدا زدن API» به «باز کردن یک فایل HTML» کاهش می‌دهد؛ خودِ داوری را نمی‌تواند انجام دهد.

**Rollback:** ندارد؛ اسکریپت مستقل است و چیزی را در محصول تغییر نمی‌دهد.

### D-089 — سه نقص که فقط با نگاه کردن به خروجی پیدا شدند

**Context:** پیش از تحویل بسته، خروجی‌ها را باز کردم. سه چیز غلط بود که هیچ آزمونی نمی‌گرفت:

۱. `title = lines[0]` — اولین خط بدنه به‌عنوان عنوان **هر** اسلاید. در یک اسکریپت audio_overview آن خط «در این ویدیو یاد می‌گیریم» است، پس ویدیو سه بار خودش را معرفی می‌کرد.
۲. شاخه‌های نقشهٔ ذهنی **پرتکرارترین کلمات** بودند: «مشتق / قاعده / نمودار / نرخ / تغییر». «قاعده» و «نرخ» تکه‌های یک جمله‌اند، نه مفهوم.
۳. وقتی شاخه‌ها عبارت شدند، چیدمان با شعاع ثابت آن‌ها را روی hub انداخت و متن موضوع را پوشاند.

**Decision:** `RenderSettings.chapter_title` (عنوان واقعی، نه خط اول بدنه) و `concept_outline` (برچسب مفهوم از هر جمله، با تشخیص نشانگرهایی مثل «قاعده»، «کاربرد»، «تعریف») و چیدمان بر اساس اندازهٔ اندازه‌گیری‌شدهٔ هر گره، با hub که **قبل از** حلقه اندازه می‌گیرد.

**Consequences:** هر سه در بازرندر چشمی تأیید شدند. **درس مهم‌تر از رفع:** اگر این بسته را با آن سه نقص تحویل می‌دادم، از یک انسان می‌خواستم چیزی را داوری کند که خودم می‌دیدم غلط است — و آن، گیت را به کاغذبازی تبدیل می‌کرد. «داوری مستقل» یعنی داوری چیزی که سازنده از آن راضی است، نه داوری اولین خروجی.

**Rollback:** ندارد.

### D-090 — آزمونی که با جهش زنده می‌مانَد، شاهد نیست؛ سه آزمون من این‌طور بودند

**Context:** پس از نوشتن آزمون‌های بالا، چهار جهش زدم. **سه‌تای اول فرار کرد:**

- آزمون شاخه‌ها `concept_outline` را مستقیم صدا می‌زد، در حالی که مسیر واقعی `build_script → outline_for` است. جهشی که `outline_for` را به `_keywords` برگرداند، آزمون را لمس نکرد.
- آزمون hub فقط عرض آن را می‌سنجید؛ جهش «hub بعد از حلقه اندازه بگیر» عرض را عوض نمی‌کرد، **ترتیب** را عوض می‌کرد.
- آزمون عنوان، `RenderSettings` را مستقیم می‌ساخت، پس جهشی که `render_local` را از انتقال `chapter_title` باز می‌داشت، دیده نشد.

**Decision:** آزمون‌ها بازنویسی شدند تا از مسیر واقعی بروند (`build_script`, `render_local`), hub در پیکسل اندازه‌گیری شود، و عنوان از payload تا هدر اسلاید ردیابی شود. جهش سوم (hub) با بازتولید **ترتیب** غلط واقعی شد، نه با ثابت‌کردن یک عدد.

**Consequences:** هر چهار جهش حالا گرفته می‌شوند. **این سومین بار در این فاز است که آزمون خودم از آزمونِ کد ضعیف‌تر بود** (پیش‌تر: هم‌زمانی SQLite، و Decimal در برابر float). الگو روشن است: آزمونی که تابع را مستقیم صدا می‌زند، مسیر را نمی‌سنجد.

**Rollback:** ندارد.

**Context:** ممیزی آغاز فاز ۹ سه شکاف را نشان داد که هر سه یک اثر داشتند:

### D-092 — دفتر مرکزی، جدولِ دوم نیست

**Context:** `token_usage_logs` از V0002 هدفِ نوشتنِ مشترکِ chat و studio بوده، ولی **هیچ‌کس آن را به‌عنوان یک کل نمی‌خواند**. کاربری که می‌پرسید «چقدر خرج کردم» باید می‌دانست کدام جدول را بپرسد.

**Decision:** `deeptutor/services/usage.py` — یک **نما** روی همان لاگ، نه جدول دوم. جدول دوم idempotency خودش، مهاجرت خودش و آشتی‌دهی خودش را می‌خواست، و اولین بار که دو جدول اختلاف داشتند راهی برای گفتن اینکه کدام درست است وجود نداشت. هر جمعی از فاز `actual` می‌آید؛ جایی که فقط تخمین هست، `pending` گزارش می‌شود و شمرده نمی‌شود.

**Rollback:** حذف ماژول؛ هیچ اسکیمایی تغییر نکرد.

### D-093 — قیمت یک واقعیتِ مربوط به یک لحظه است، نه ستونی که بازنویسی می‌شود

### D-094 — SSRF را با رشتهٔ URL نمی‌شود بست

**Context:** بررسی متنیِ URL با خودِ متن شکسته می‌شود: `127.1` معتبر است، `0x7f000001` حل می‌شود، `[::1]` و `[::ffff:127.0.0.1]` همان حلقهٔ محلی‌اند، و هر نامی می‌تواند یک ثانیه بعد از بررسی به آدرس خصوصی حل شود.

**Decision:** `deeptutor/services/net_guard.py` نام را حل می‌کند، **آدرس‌ها** را بررسی می‌کند و آدرس‌های بررسی‌شده را برمی‌گرداند تا فراخوان به همان‌ها وصل شود — وگرنه DNS دو بار پاسخ می‌دهد و پاسخ دوم برنده است. بلاک: loopback، private، link-local، unique-local (v4 و v6)، آدرس متادیتای ابری (به‌تفصیل `169.254.169.254` که اعتبارنامهٔ نمونه می‌دهد)، اسکیم غیر-HTTP، و نامی که حل نمی‌شود. **ریدایرکت دستی دنبال می‌شود**: ریدایرکت یک درخواست دوم به مقصدی است که کسی بررسی نکرده.

**Consequences:** ۳۱ آزمون؛ جهش «حلقهٔ محلی مجاز» ۶ آزمون را می‌شکند. یک نکتهٔ ظریف واقعی پیدا شد: CPython بازهٔ `169.254.0.0/16` را هم private می‌شمارد، پس `is_link_local` باید **قبل از** `is_private` بیاید وگرنه دلیل امتناع گمراه‌کننده می‌شود.

**Rollback:** ندارد.

### D-095 — کلید API یک کاربر هرگز در ردیف ذخیره نمی‌شود

**Context:** «provider خودت را بیاور» یعنی کاربر URL را تایپ می‌کند و سرور یک درخواست احراز‌شده به آن می‌زند — یک SSRF با رابط کاربری. مقصدهای جالب آن‌هایی‌اند که کسی عمداً تایپ نمی‌کند.

**Decision:** اعتبارسنجی **قبل از** ذخیره (نه بعدش: URL‌ایی که بدون بررسی ذخیره شد، بعداً توسط مسیری استفاده می‌شود که فرض می‌کند بررسی شده)، و **بررسی دوباره در زمان استفاده** (DNS بین ذخیره و استفاده یک پنجرهٔ حمله است). `PublicProvider` **هیچ فیلدی برای کلید ندارد** — کلاسی که نمی‌تواند راز نگه دارد از serializer‌ای که آن را حذف می‌کند قوی‌تر است، چون حذف با refactor زنده می‌ماند و فیلد خالی نه. کلید در **بدنهٔ** درخواست می‌آید نه query: query در هر access log روی مسیر، در تاریخچهٔ مرورگر و در `Referer` نوشته می‌شود.

**Consequences:** ۱۵ آزمون HTTP + ۲۲ آزمون سرویس. آزمون ساختار ردیف (`set(row) == {...}`) طوری نوشته شده که **افزودن ستون جدید را عمدی می‌کند** — ستونی که ممکن است اعتبارنامه حمل کند.

**Rollback:** V0015 در `DOWN` جدول را حذف می‌کند؛ up→down(14)→up تأیید شد.

### D-096 — آزمونی که با جهش زنده می‌مانَد، شاهد نیست (فاز ۹)

**Context:** ۲۸ جهش زده شد. **پنج فرار کرد.** هر پنج، ضعفِ آزمون بود نه کد:

۱. `pending_jobs` را چک نمی‌کردم که در حالت settle هم صفر است.
۲. ردیف media از لاگ فیلتر می‌شد ولی آزمون فقط `len == 1` را می‌دید و fixture فقط یک ردیف داشت.
۳. تخمینِ قیمت‌دار در واقعیت `cost_microusd` ندارد، پس جهش «تخمین را بشمار» **واقعاً بی‌اثر** بود — آزمون با نوشتن آن حالت بازنویسی شد، چون گام بعدی واضحِ کد پرکردن آن قیمت است.
۴. فیلتر کردن نمای operator به یک کاربر، با fixture تک‌کاربره دیده نمی‌شد.
۵. `recent()` نسخهٔ اولم با `rows.index(row)` روی dataclass یخ‌زده کار می‌کرد ولی شکننده بود؛ بازنویسی شد.

**Decision:** هر پنج آزمون تقویت شدند تا **تفاوت** را بسنجند نه یک عدد را که با چند پیاده‌سازی هم درست است.

**Consequences:** ۳۳/۳۳ جهش گرفته می‌شود. **این چهارمین فاز پیاپی است که آزمونِ خودم از کدِ خودم ضعیف‌تر بود.** الگو ثابت است: آزمونی که یک عدد را می‌سنجد که چند پیاده‌سازی می‌توانند تولیدش کنند، شاهد نیست.

**Rollback:** ندارد.
