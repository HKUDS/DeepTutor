# Tencent IMA 只读连接流程设计

## 背景与目标

DeepTutor v1.5.12 已具备 Tencent IMA 的后端检索管线、连接探测和按知识库保存连接信息的能力，但 Web 端没有接入这些专用接口。当前界面会把 IMA 显示为“就绪”，环境检查却因预检表缺少 `ima` 而返回 HTTP 500；创建知识库时又错误显示本地文件上传控件。

本次改动的目标是让用户在 DeepTutor 中完成 IMA 的只读连接，并让 Chat 等 RAG 消费方通过 IMA `search_knowledge` 返回的命中文档片段进行检索式问答。

这里的“读取”特指检索式读取：DeepTutor 获得搜索命中的标题与 `highlight_content` 片段，并交给现有 RAG 回答链路；不下载、解析或通读完整原始文件。

## 范围

包含：

- 使用 Client ID 和 API Key 验证 IMA 访问权限。
- 自动列出当前凭据可访问的 IMA 知识库。
- 以每页 20 条的游标分页展示知识库，并支持继续加载。
- 选择一个知识库并连接为 DeepTutor 知识库。
- 提供折叠的手填 Knowledge Base ID 高级入口。
- 修复 IMA 引擎预检的 HTTP 500。
- 将 IMA 引擎状态从误导性的“就绪”改为“按知识库连接”。
- 保持服务端二次探测，避免前端验证结果被直接信任。
- 覆盖前端、后端和真实 IMA 只读检索验证。

不包含：

- 向 IMA 上传、导入、修改或删除文档与笔记。
- 下载或通读完整原始文件。
- 修改现有凭据存储机制。
- 抽象通用外部知识库连接器框架。

## 用户流程

1. 用户打开“创建知识库”，切换到“关联已有”。
2. 用户选择 Tencent IMA。
3. 页面展示 Client ID、API Key 和“验证并读取知识库”按钮；API Key 使用密码输入框。
4. 验证成功后，页面展示第一批 20 个知识库；还有下一页时显示“加载更多”。列表展示名称和可用描述，不向普通流程暴露内部 ID。
5. 用户选择一个知识库。若 DeepTutor 知识库名称仍为空或仍是上一次自动填写的值，则自动填入 IMA 知识库名称；用户手工修改后的名称不得被覆盖。
6. 用户点击“连接”。DeepTutor 服务端再次调用 IMA 验证该知识库，成功后才保存连接。
7. 后续 RAG 查询只调用 IMA 的 `search_knowledge`，并把命中的标题与内容片段交给现有回答链路。

高级入口允许用户切换为手填 Knowledge Base ID。自动选择与手填模式互斥；手填后必须调用现有 `probe-ima` 并获得成功结果，才能连接。切换模式、修改 Client ID、修改 API Key 或修改手填 ID 时，必须清除不再有效的列表、选择和探测结果。

## 后端设计

### IMA 客户端

在现有 `ImaClient` 中增加两个只读能力：

- `search_knowledge_bases(query, cursor, limit)` 调用官方 `openapi/wiki/v1/search_knowledge_base`。列表模式使用空查询；`limit` 默认 20，并在 API 请求模型中验证为 1–20；响应原样保留 `next_cursor` 与 `is_end`。
- 将现有单个 `get_knowledge_base` 查询复用为可接收最多 20 个 ID 的批量查询，用官方 `get_knowledge_base` 补充描述；单个知识库探测继续通过这个批量能力的单 ID 包装工作。

搜索结果按 ID 去重并归一化为 ID、名称和可选描述。官方搜索接口本身只返回 ID、名称和封面，因此描述必须来自第二次批量详情查询；详情查询失败时保留名称列表，不让非关键的描述增强阻断连接。

### API 路由

新增 `POST /api/v1/knowledge/list-ima`，用请求体接收：

```json
{
  "client_id": "...",
  "api_key": "...",
  "cursor": "",
  "limit": 20
}
```

成功响应为：

```json
{
  "knowledge_bases": [
    {"id": "...", "name": "...", "description": null}
  ],
  "next_cursor": "...",
  "is_end": false
}
```

路由不落盘、不记录、不返回或缓存凭据。缺少凭据返回 400，凭据被拒绝返回 401，IMA 限流返回 429，IMA 网络或协议错误返回 502；错误正文使用安全的归一化消息，不包含请求头、请求体或凭据。前端调用该路由时必须设置 `skipAuthRedirect: true`，避免把 IMA 的 401 误判为 DeepTutor 登录会话过期并跳转登录页。

现有 `probe-ima` 继续负责验证手填 Knowledge Base ID；现有 `connect-ima` 继续执行服务端二次探测并注册连接。

### 预检

为 `ima` 注册专用预检。因为凭据按知识库配置，预检返回一个成功的说明性检查项：“Client ID 与 API Key 在连接知识库时提供”，不尝试读取全局配置或访问 IMA。引擎卡片和详情页仍把 HTTP 客户端可用性视为已安装，但显示状态文案“按知识库连接”，而不是“就绪”。

## 前端设计

- 在知识库 API 客户端中增加 IMA 列表、探测和连接函数及其类型。
- “新建”模式过滤掉 IMA，不再把它当作上传型引擎；这次不改变 LightRAG Server 等其他引擎的现有归属。
- “关联已有”模式显式启用 IMA，并渲染专用表单，而不是本地文件夹表单。现有 `linkable` 仍只表示“可关联本地索引文件夹”，不把 IMA 错误标记为本地可关联引擎。
- IMA 表单具有 `idle`、`loading`、`ready`、`empty`、`error` 和 `manual_verified` 状态。修改 Client ID 或 API Key 时回到 `idle`；加载下一页时保留已有列表，失败时允许重试。
- 自动列表模式下，DeepTutor 名称非空、凭据非空且选中一个列表项后连接按钮可用，最终有效性由 `connect-ima` 的服务端二次探测保证。手填模式下，DeepTutor 名称非空，且 `probe-ima` 对当前凭据与当前 ID 返回成功后按钮才可用。
- 弹窗关闭时清空 Client ID、API Key、游标、知识库列表、选择与探测结果，不把凭据放入客户端缓存。
- 连接中、验证中、空列表、认证失败、权限不足和网络错误均使用现有错误展示样式。
- 引擎详情页的环境要求展示 IMA 的按知识库连接说明，不再显示裸 `'ima'` 错误。
- 所有新增用户可见文案同时补入 `web/locales/en/app.json` 与 `web/locales/zh/app.json`，保持英文源文案和简体中文界面一致。

## 数据与安全边界

- 浏览器通过 DeepTutor 当前的同源 API 连接把凭据发送给后端；本地默认可能是 HTTP，远程部署必须由部署方提供 HTTPS。后端到 IMA 的请求固定使用 `https://ima.qq.com`。
- 日志、测试输出、错误消息和前端响应均不得包含凭据。
- 自动化测试使用虚构凭据和 HTTP mock；用户授权的真实凭据只用于本地临时 smoke test，不写入仓库、快照或测试夹具。
- 本次不改变现有连接成功后的本地配置保存行为。
- 列表响应中的知识库 ID 仅保存在当前弹窗内存中并用于连接；自动选择界面不显示该 ID，高级手填模式可由用户自行输入。本次不改变连接成功后既有知识库元数据的保存或展示规则。

## 错误处理

- 缺少凭据：前端禁用验证按钮，后端返回可读的 400 错误。
- 凭据错误或过期：后端归一化为 401 和安全错误信息，不回显请求头或请求体。
- 无可访问知识库：展示空状态，并提供手填 ID 高级入口。
- 手填 ID 不存在或无权限：探测失败，禁止连接。
- 列表验证成功但连接时状态已变化：以服务端二次探测结果为准。
- IMA 限流：返回 429，保留用户输入并允许稍后重试。
- IMA 网络或协议故障：返回 502，保留用户输入并允许重试；不得把 Python 异常或响应正文原样暴露给前端。
- 描述增强失败：仍返回搜索得到的名称列表，不阻断选择和连接。

## 测试与验收

自动化测试：

- `ImaClient` 对知识库列表的请求路径、空查询、20 条上限、游标、去重、批量描述增强和错误映射。
- 新列表路由的成功、空列表、下一页、缺少凭据、认证失败、限流、上游故障和不泄露凭据。
- IMA 预检返回说明性成功结果。
- Web API 客户端用 mock `fetch` 验证列表、探测和连接的请求体、分页响应、错误提取，以及 IMA 401 不触发全局登录跳转。
- 将可纯函数化的模式归属、名称自动填写、状态失效和连接门禁逻辑放入可测试 helper，用现有 Node test runner 覆盖；不为本 PR 引入新的 React 组件测试依赖。
- 运行 Python 相关测试、Web Node tests、TypeScript/Next build、lint 和 i18n 检查。

人工与真实 smoke test：

- 使用用户授权的本地凭据读取知识库列表。
- 对选定知识库执行一次无副作用的 `search_knowledge`，确认响应结构正确；若测试查询确有命中，再确认命中项包含标题和 `highlight_content`，不把“零命中”误判为连接失败。
- 在本地 Web 界面完成凭据验证、分页/空状态、知识库选择、手填 ID 和连接交互；连接 smoke test 使用隔离的数据目录，结束后删除整个临时目录，不让真实凭据留在常用运行时配置中。
- 确认 IMA 不出现在上传型“新建”引擎列表，关联流程不显示文件上传或本地文件夹控件，环境检查不再返回 HTTP 500，状态不再显示“就绪”。

## 验收标准

- 用户无需自行查找内部 Knowledge Base ID 即可选择并连接 IMA 知识库。
- 超过 20 个知识库时可以通过游标继续加载，且列表不会产生重复项。
- 高级手填 ID 流程仍可工作，并在连接前完成验证。
- DeepTutor 能用 IMA 命中文档片段完成只读检索式问答。
- IMA 不出现在上传型“新建”流程中。
- IMA 卡片显示“按知识库连接”，环境检查稳定返回说明性结果。
- 所有相关自动化测试通过，真实 smoke test 不泄露或持久化测试凭据。
