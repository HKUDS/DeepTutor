## ✨ Ключевые возможности

DeepTutor — это агентная учебная рабочая среда, объединяющая репетиторство, исследования, творчество и практику в одной расширяемой системе.

- **Единая среда выполнения, множество режимов обучения** — Chat, Quiz, Research, Visualize, Solve, Mastery Path, Reading и другие режимы используют общий контекст сессии, сохраняя специализированные рабочие процессы для своих задач.
- **Связанная учебная рабочая среда** — Home, Learning и Resources объединяют Chat, Books, Reading, Practice, Task Board, Calendar и Learning notebook, связывая материалы, прогресс и учебный контекст.
- **Знания и чтение с опорой на источники** — создавайте версионированные библиотеки с LlamaIndex, PageIndex, GraphRAG или LightRAG, подключайте внешние источники знаний и занимайтесь рядом с документами, видео и аудио, получая цитаты со ссылками на источники.
- **Partners и субагенты** — обращайтесь к живым агентам, таким как Claude Code, Codex и Grok CLI, импортируйте прошлые разговоры или запускайте постоянных Partners с собственной памятью, ресурсами и IM-каналами.
- **Проверяемая память** — трассировки L1, факты L2 и синтез L3 делают персонализацию видимой и редактируемой, а ссылки на доказательства можно проверять в Memory Graph.
- **Расширяемость по замыслу** — добавляйте персоны, встроенные навыки и навыки сообщества, MCP-сервисы, CLI-приложения и генеративные модели через единую агентную среду выполнения.

## 🚀 Начало работы

Выберите способ установки, соответствующий тому, как вы хотите использовать DeepTutor. Установки через терминал используют один домашний каталог среды выполнения: приватные настройки хранятся в `data/user/settings/` в директории запуска либо в `DEEPTUTOR_HOME` / `deeptutor start --home`, если они заданы явно. После запуска приложения настройте провайдера и модель в разделах **Настройки → Провайдеры** и **Языковые модели**.

<details>
<summary><b>Desktop — macOS и Windows (предварительная версия)</b></summary>

**Open DeepTutor** включает Python, Node.js и полную учебную рабочую среду, поэтому терминал и отдельная установка среды выполнения не нужны. Предварительные версии Desktop доступны в ветке `dev`; **выпуск v1.7.0 не включает установщики desktop**.

Откройте успешный запуск [рабочего процесса Desktop Release](https://github.com/HKUDS/DeepTutor/actions/workflows/desktop-release.yml?query=branch%3Adev), прокрутите до **Artifacts** и скачайте подходящий вариант. Требуется вход в GitHub, а артефакты хранятся семь дней.

| Ваш компьютер | Вариант для скачивания | Установщик |
| --- | --- | --- |
| **Mac с Apple Silicon** | `macos-arm64` | Откройте DMG и перетащите **Open DeepTutor** в **Applications**. |
| **Mac с Intel** | `macos-x64` | Откройте DMG и перетащите **Open DeepTutor** в **Applications**. |
| **Windows x64** | `windows-x64` | Запустите установочный `.exe` либо распакуйте переносимый ZIP и запустите `Open DeepTutor.exe`. |

Предварительные сборки Windows не подписаны и могут вызывать предупреждение SmartScreen. Сведения о подписании, локальных данных и сборке из исходного кода приведены в [руководстве по desktop](../../apps/desktop/README.md).

</details>

<details>
<summary><b>Docker — самый быстрый пробный запуск полного приложения</b></summary>

Запустите полное веб-приложение без установки Python или Node.js:

```bash
docker run --rm --name deeptutor \
  -p 127.0.0.1:3782:3782 \
  -v deeptutor-data:/app/data \
  ghcr.io/hkuds/deeptutor:latest
```

Откройте [http://127.0.0.1:3782](http://127.0.0.1:3782). Именованный том сохраняет настройки и локальные данные; для веб-приложения требуется только порт `3782`. Сведения о рабочих пространствах на хосте, локальных модельных сервисах, обратных прокси и развёртывании в производственной среде приведены в [руководстве по Docker](https://docs.deeptutor.info/get-started/docker/).

</details>

<details>
<summary><b>PyPI — полное веб-приложение и CLI</b></summary>

Используйте **Python 3.11–3.14** и **Node.js 20.9+**. В модульном выпуске 1.7.0 `deeptutor[full]` устанавливает веб-приложение и CLI, а `deeptutor` без дополнений — базовый чат и SDK.

```bash
mkdir -p my-deeptutor && cd my-deeptutor
python -m pip install -U "deeptutor[full]"
deeptutor init     # ports + LLM provider + optional embedding/search
deeptutor start    # starts backend + frontend
```

Откройте URL, напечатанный в терминале, по умолчанию [http://127.0.0.1:3782](http://127.0.0.1:3782). Нажмите `Ctrl+C`, чтобы остановить обе службы.

**Обновление с 1.6.15 или более ранней версии:** остановите DeepTutor, создайте резервную копию домашнего каталога среды выполнения и удалите устаревший пакет `deeptutor-cli` перед установкой нового семейства. Сохраните тот же `DEEPTUTOR_HOME`, затем выполните `python -m pip check` и `deeptutor module list`. Точные команды обновления приведены в [руководстве по PyPI и миграции](https://docs.deeptutor.info/get-started/pypi/).

</details>

<details>
<summary><b>Исходный код — текущая версия Dev и участие в разработке</b></summary>

Используйте **Python 3.11–3.14** и **Node.js 22 LTS** для соответствия CI и Docker.

```bash
git clone --branch dev https://github.com/HKUDS/DeepTutor.git
cd DeepTutor
python3 -m venv .venv && source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements/full.txt
python -m pip install -e . --no-deps
( cd web && npm ci --legacy-peer-deps )
deeptutor init
deeptutor start --dev
```

Используйте `deeptutor start` без `--dev` для производственной сборки. Необязательные зависимости устанавливаются из корня репозитория, например `python scripts/install_extras.py dev,partners,math-animator`. Сведения о Conda, дополнениях и устранении неполадок приведены в [руководстве по установке из исходного кода](https://docs.deeptutor.info/get-started/from-source/), а [руководство по настройке с помощью агента](../../docs-for-dev/AGENT_SETUP.md) позволяет поручить установку и её проверку агенту с доступом к терминалу.

</details>

<details>
<summary><b>CLI — использование в терминале и агентах</b></summary>

Для минимальной установки в терминале используйте базовый wheel; Node.js и веб-фронтенд не требуются:

```bash
mkdir -p my-deeptutor && cd my-deeptutor
python -m pip install -U deeptutor
deeptutor init --cli
deeptutor chat
```

Ядро включает Chat, Ask Questions, CLI и SDK; остальные возможности и команды управления требуют соответствующих функциональных модулей. Сведения об установке текущего исходного кода ветки `dev` и необязательных зависимостях приведены в [руководстве по установке только CLI](https://docs.deeptutor.info/get-started/cli-only/). [Справочник по CLI](#%EF%B8%8F-deeptutor-cli--интерфейс-для-агентов) ниже описывает одноразовые запуски и машиночитаемый вывод.

</details>

<details>
<summary><b>🏠 Home — разговоры, задачи, заметки и календарь</b></summary>

Home — место, где начинается повседневная работа: общайтесь с репетитором, организуйте следующие действия и развивайте собственные заметки в текущем рабочем пространстве. Calendar предоставляет общий для учётной записи обзор, сохраняя привязку учебных событий к исходному рабочему пространству.

<details>
<summary><b>💬 Chat — агентный цикл, которым вы действительно пользуетесь</b></summary>

Chat — возможность по умолчанию и место, где начинается большая часть работы. В одном потоке можно обычным образом общаться, вызывать инструменты, опираться на выбранные базы знаний, читать вложения, генерировать изображения, обращаться к субагентам, записывать в блокнот и продолжать с тем же контекстом в последующих ходах.

<div align="center">
<img src="../../assets/figs/web-dev/chat.png" alt="Рабочее пространство чата DeepTutor" width="900">
</div>

Репетитор вызывает инструменты по мере необходимости и может приостановиться, чтобы задать уточняющие вопросы. Кнопка **Настроить страницу** в правом верхнем углу выбирает видимые режимы и элементы управления Skills, MCP, Partners, предпочтениями и голосовым вводом. В разделе **Начальные запросы** можно добавлять, редактировать или удалять заголовки и запросы в Explain, Solve, Practice, Plan и Research. Сохранение применяет предпочтения учётной записи; отмена сбрасывает правки, а восстановление значений по умолчанию возвращает исходный набор.

<div align="center">
<img src="../../assets/figs/system/chat-agent-loop.svg" alt="Агентный цикл чата DeepTutor" width="900">
</div>

Переключаемые пользователем инструменты: `brainstorm`, `web_search`, `paper_search`, `zotero_search`, `reason` и `geogebra_analysis` — плюс `imagegen` и `videogen` после настройки соответствующей генеративной модели. Контекстные инструменты, такие как `rag`, `kb_files`, `knowledge_frontier`, `read_source`, `read_memory`, `write_memory`, `read_skill`, `load_tools`, `exec`, `web_fetch`, `ask_user`, `list_favorites`, `save_favorite`, `write_note`, `search_notes`, `question_bank`, `github`, `consult_subagent`, `workspace_list`, `workspace_read`, `workspace_search`, `workspace_present` и `workspace_export`, монтируются автоматически, когда ход имеет подходящий контекст.

Контекст бывает двух видов: **постоянный контекст сессии** (возможность, рабочее пространство или курс, инструменты, базы знаний, персона, модель и состояние Reading / Mastery) сохраняется между ходами; **ссылки** (файлы, история чата, книги, разделы чтения, блокноты, выбранные записи банка вопросов, импортированные агенты) берутся из меню `+` по умолчанию для одного хода либо для каждого хода, если они закреплены. Кнопка голосового ввода только транскрибирует текущее сообщение.

При полном профиле Home держит **Chat**, **Ask Questions**, **Quiz**, **Visualize** и **Video Lesson** в одном клике; **Research** для отчётов с цитатами и **Solve** для пошаговых рассуждений находятся в разделе *Дополнительные возможности*. Выделите текст в ответе, чтобы открыть **Little Tutor** — отдельный поток в боковой панели, который остаётся вложенным в исходный разговор. После отправки как минимум трёх сообщений в левом поле при достатке места появляется отметка для каждого вопроса; наведите указатель для предварительного просмотра, нажмите для возврата к вопросу или используйте **Alt/Option + ↑/↓** для перехода между вопросами.

</details>

<details>
<summary><b>✅ Task Board и Calendar — организация повседневного обучения</b></summary>

**Task Board** отслеживает учебные задачи в колонках «Сделать», «В работе» и «Готово», поддерживает заметки, перемещение перетаскиванием или доступными с клавиатуры элементами управления и восстановление из архива. Задачи остаются в текущем рабочем пространстве и не требуют настройки модели.

**Calendar** объединяет личные учебные занятия, повторяющиеся события и напоминания, поддерживая экспорт `.ics` для Apple Calendar, Google Calendar, Outlook и Thunderbird. Элементы рабочего пространства, такие как сроки задач и повторения, остаются связанными с исходным рабочим пространством.

</details>

<summary><b>✍️ Learning Notebook — страницы, источники и Dito</b></summary>

Learning notebook, ранее Co-Writer, организует ваши тексты в страницы, вложенные страницы и блоки внутри активного рабочего пространства. Статус сохранения страниц всегда виден; их можно экспортировать в Markdown или Word, при этом интерактивное содержимое в Word становится статическим.

Просматривайте предложенные изменения перед принятием либо вставляйте ответ под строкой и продолжайте работу. Favorites сохраняет исходные записи, а блокнот помогает выстроить собственное понимание.

<summary><b>📚 Knowledge Center — многодвигательные RAG-библиотеки</b></summary>

<div align="center">
<img src="../../assets/figs/web-dev/knowledge.png" alt="Центр знаний DeepTutor" width="900">
</div>

Базы знаний — это коллекции документов для RAG, которые обосновывают ходы Chat, правки Learning notebook, генерацию Book и разговоры с Partner. Отличительной чертой является **выбор движков поиска**: **LlamaIndex** (по умолчанию, гибридный векторный поиск + BM25 с необязательным переранжированием cross-encoder и индексами FAISS exact-flat или HNSW), **PageIndex** (поиск с рассуждением и цитатами на уровне страницы, размещённый или самостоятельно развёрнутый OSS), **GraphRAG** и **LightRAG** (поиск на основе графа знаний), **LightRAG Server** (поиск, делегированный внешнему экземпляру LightRAG, подключаемому по HTTP), **WeKnora** (поиск в базе знаний вашего самостоятельно размещённого развёртывания без локального индекса или копии документов), **Tencent IMA** (библиотека, которую вы курируете в IMA, — доступная для поиска, просмотра и записи через её OpenAPI), **MarginNote 4** (ваши учебные данные MN4 — документы, выдержки, карточки интеллект-карт и связи между ними — передаются дополнением приложения и используются с помощью специальных инструментов навигации), **Kiwix** (доступный для поиска ZIM-архив, предоставляемый по HTTP без локального индексирования) или связанное хранилище **Obsidian**, которое репетитор читает и изменяет на месте. Каждая KB привязана к одному движку.

<div align="center">
<img src="../../assets/figs/web-dev/knowledge-create.png" alt="Создание базы знаний" width="900">
</div>

Переносите существующую библиотеку Obsidian, Hermes или Markdown? В [руководстве по миграции знаний](../../docs-for-dev/KNOWLEDGE_MIGRATION.md) описаны варианты с подключённым хранилищем и индексированной копией.

При создании KB можно **создать новую** (загрузить и проиндексировать документы), **связать существующую** (повторно использовать индекс на месте) или **подключить Kiwix** (по мере необходимости искать в одном предоставляемом сервером ZIM-архиве). При создании выберите рабочее пространство для хранения KB; существующую KB можно перенести между рабочими пространствами после предварительного просмотра, сохранив назначения и сохранённые ссылки. База знаний также может отслеживать **репозитории GitHub** (репозиторий, ветка и glob-шаблон) или **URL сайтов документации** (с ограничениями глубины обхода и числа страниц, по умолчанию повторно синхронизируются каждые 24 часа); синхронизация сравнивает хеши содержимого, чтобы выявить добавленные, изменённые и удалённые материалы, поэтому документация, за которой вы следите, остаётся актуальной без повторной загрузки, а **связанные папки** подхватывают новые или изменённые локальные файлы при синхронизации. Переиндексирование записывает новую плоскую директорию `version-N` и сохраняет предыдущие, поэтому рабочий индекс никогда не уничтожается в процессе перестройки. Отдельный документ можно удалить даже из базы в состоянии **error** — убрав файл, который не удалось разобрать, без полного удаления и пересборки. Движок разбора документов — Text-only, MinerU, Docling, Tika, markitdown, PyMuPDF4LLM или LiteParse — и необязательная модель описания изображений выбираются в **Настройки → Знания и документы**, с отключёнными по умолчанию загрузками локальных моделей. Docling может также работать в **удалённом режиме**, обращаясь к серверу Docling Serve (без локальной установки и моделей), который настраивается на той же странице (`mode=remote`, базовый URL сервера и необязательный API-ключ) или через переменные окружения `DOCLING_MODE` / `DOCLING_API_BASE_URL` / `DOCLING_API_TOKEN`. Tika работает только в удалённом режиме и указывает на сервер Apache Tika, настроенный на этой странице. CLI отражает жизненный цикл через `list/info/create/connect-kiwix/add/search/eval/eval-diff/set-default/delete`, команды добавления/удаления источников, `list-sources` и `sync`.

Встроенный движок LightRAG устанавливается командой `pip install 'deeptutor[rag-lightrag]'`. Это дополнение содержит поддерживаемый SDK LightRAG, но не устанавливает MinerU. Выбирайте MinerU отдельно в разделе Document Parsing и либо настройте его облачный режим, либо установите актуальный локальный CLI, если нужен структурированный разбор. MinerU принимает PDF, распространённые растровые изображения, DOCX, PPTX и XLSX; устаревшая команда `magic-pdf` по-прежнему работает только с PDF. Text-only и другие движки разбора не требуют MinerU.

Нативные запросы LightRAG и инкрементальное индексирование требуют конфигурации встраивания, зафиксированной опубликованным индексом, включая модель, размерность и идентичность конечной точки. Если она меняется, восстановите исходную конфигурацию или пересоберите индекс с текущим встраиванием; индексы без зафиксированной идентичности встраивания требуют пересборки. Раздел сведений о базе знаний и представления версий индекса показывают рекомендации по восстановлению, а файлы остаются доступными для просмотра и скачивания.

**Оценка базы знаний.** Когда доступны несколько движков, вопрос «какой из них лучше ищет в этих материалах?» требует практической проверки — для этого есть `deeptutor kb eval`. Подготовьте набор вопросов и ответов (по одному объекту JSON на строку: `query` и отрывки `gold`, которые должен возвращать идеальный поиск), затем оцените KB командой `deeptutor kb eval <name> --dataset qa.jsonl --top-k 5 [--mode hybrid] [--save baseline.json]`. Поиск для каждого примера выполняется тем же способом, что и в ходе чата; ранжированные цитаты сопоставляются с эталонными отрывками по точному тексту или лексическому пересечению (пороги настраиваются через `--min-ratio`; семантическая эквивалентность не оценивается), а результат содержит **Recall@k / Precision@k / nDCG@k / MRR / MAP / Hit@k**. Метрики — чистые функции от ранжирования; никакая модель не оценивает результат. Сравнивайте сохранённые отчёты командой `deeptutor kb eval-diff baseline.json candidate.json`, чтобы увидеть изменения по каждой метрике и каждому примеру. Используйте `--rewrite off` или `--rewrite standalone` с `kb eval`, чтобы сравнить исходные и переписанные запросы; отчёты сохраняют сведения о переписывании запросов. Примеры, в которых поиск завершился ошибкой (отсутствующий индекс, неверные учётные данные), не получают оценки и указываются отдельно, не снижая средние значения. PageIndex использует рассуждение для поиска и не возвращает ранжированные фрагменты, поэтому исключён.

```jsonl
{"query": "Why do transformers scale attention?", "gold": ["Scaling keeps the dot products from growing with the dimension."]}
```

Назначения рабочих пространств и гранты пользователей определяют, какие ресурсы может использовать каждый ход.

</details>

<details>
<summary><b>🧠 Память — проверяемая персонализация</b></summary>

<div align="center">
<img src="../../assets/figs/web-dev/memory.png" alt="Обзор памяти DeepTutor" width="900">
</div>

Память — это трёхуровневая система на основе файлов, которую можно читать, курировать и проверять, — намеренно *не* скрытое векторное хранилище. **L1** — зеркало рабочего пространства плюс трассировка событий только для добавления (`trace/<surface>/<date>.jsonl`); **L2** — курированные факты на уровне поверхности (`L2/<surface>.md`) со ссылками на сущности L1; **L3** — межповерхностный синтез (`L3/<profile|recent|scope|preferences>.md`), фиксирующий участвующие поверхности L2.

<div align="center">
<img src="../../assets/figs/web-dev/memory-graph.png" alt="Граф памяти DeepTutor" width="900">
</div>

Memory Graph показывает всю пирамиду — синтез L3 в центре, L2 в среднем кольце, трассировки L1 снаружи — с точными рёбрами доказательств L2 → L1 и связями L3 → участвующие поверхности. Память отслеживается по поверхностям `chat`, `notebook`, `quiz`, `kb`, `book`, partner и `cowriter`; бюджеты обновления / аудита / дедупликации консолидатора настраиваются в **Настройки → Память**.

<summary><b>⚙️ Настройки — единая панель управления</b></summary>

<div align="center">
<img src="../../assets/figs/web-dev/settings.png" alt="Навигатор настроек" width="900">
</div>

Настройки — операционная панель управления, которая открывается на странице **Общие** для выбора языка интерфейса и вывода модели. Навигатор с поиском ведёт на независимые страницы: **Личное** включает рабочие пространства, миграцию данных, внешний вид и статистику использования; **Обучение и разговоры** — начальные запросы, вложения, Video Learning, управление учащимися и опекунами, прогресс обучения и Memory; **Модели и сервисы** — провайдеров, языковые модели, Task-модели, встраивание, поиск, речь и мультимодальную генерацию; **Возможности и интеграции** — инструменты, параметры возможностей, партнёров и агентов, знания и документы. **Система** содержит сеть, состояние среды выполнения и сведения о проекте; **Архивные чаты** позволяет искать, восстанавливать или навсегда удалять архивные разговоры. Состояние среды выполнения содержит состояние бэкенда, резидентную память и матрицу **Готовности**, оценивающую блокирующие проблемы, предупреждения и рекомендации для возможностей. Рабочие пространства разделяют файлы тем и состояние обучения, обеспечивая проверяемую миграцию и экспорт в разделе миграции данных. **Провайдер** хранит адрес и учётные данные поставщика для повторного использования его сервисными моделями; на страницах моделей выбираются сохранённые провайдеры и задаются имена и возможности моделей. **Task-модели** закрепляют небольшую быструю модель за автоматической работой — от названия разговоров и написания начальных запросов до исправлений Math Animator и Video Lesson — и при пустом значении используют активную модель по умолчанию. Речь объединяет синтез и распознавание речи; мультимодальная генерация объединяет модели изображений и видео. Раздел «Партнёры и агенты» настраивает локальные агентные среды и удалённый шлюз Hermes.

**Вьетнамский язык:** в **Настройки → Общие** выберите **Tiếng Việt** для **Язык интерфейса** и нажмите **Применить изменения**. **Язык вывода модели** настраивается независимо: выберите там **Tiếng Việt** для ответов на вьетнамском либо сохраните другой язык ответов при вьетнамском интерфейсе. Качество ответов зависит от поддержки вьетнамского языка выбранной моделью.

**Синтез речи Xiaomi MiMo.** Добавьте провайдера Xiaomi MiMo с адресом `https://api.xiaomimimo.com/v1` и его API-ключом, затем добавьте `mimo-v2.5-tts` в разделе Настройки → Voice. Выберите предустановленный голос, например `mimo_default`, `冰糖` или `苏打`, формат вывода `wav` или `pcm16` и прослушайте образец перед применением. Голосовые инструкции управляют стилем и скоростью речи. Этот адаптер поддерживает только предустановленные голоса; создание и клонирование голоса требуют отдельных моделей и не поддерживаются. Если старая речевая модель MiMo была настроена через общий адаптер, совместимый с OpenAI, создайте её речевой профиль заново с провайдером Xiaomi MiMo, чтобы использовать протокол chat-completions. См. [официальное руководство по синтезу речи MiMo](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/audio/speech-synthesis-v2.5).

**Синтез речи MiniMax** — в разделе Настройки → Voice выберите MiniMax для преобразования текста в речь и модель `speech-2.8-hd`. Настройте API-ключ MiniMax и явно выберите системный голос или введите идентификатор пользовательского голоса. Базовый URL API по умолчанию — `https://api.minimax.io/v1`; для региона Китай используйте `https://api.minimaxi.com/v1`. Чтение вслух и прослушивание образцов используют нативную конечную точку синтеза речи с выводом в MP3, WAV, FLAC или PCM и настройками частоты дискретизации, скорости и языка. Идентификаторы голосов и доступность для учётных записей описаны в [API синтеза речи MiniMax](https://platform.minimax.io/docs/api-reference/speech-t2a-http).


**Video Learning** в разделе Настройки → Learning & conversation настраивает субтитры YouTube и доступ к Invidious для Reading. Чтобы использовать Invidious, задайте управляемый администратором адрес его серверного API (например, `http://127.0.0.1:3000`) и публичный адрес, доступный из браузера, проверьте подключение, выберите Invidious и сохраните настройки. Кнопка **Browse Invidious** в диалоге добавления материалов Reading позволяет искать видео и открывать подключённые подписки и плейлисты. YouTube воспроизводится через официальный плеер с повышенной конфиденциальностью; отсутствие субтитров явно отображается и ограничивает доказательную базу репетитора, но не мешает нативному воспроизведению. В чекауте исходного кода выполните `python scripts/install_extras.py video-learning` для установки загрузчика субтитров YouTube по умолчанию. Существующие ссылки Watching переносятся в Reading с сохранением истории разговоров, совместимых транскриптов, заметок и прогресса; новые заметки с временными метками становятся аннотациями Reading. Bilibili использует собственный способ воспроизведения и получения субтитров.

<img src="../../assets/figs/web-dev/appearance.png" alt="Настройки внешнего вида и темы DeepTutor" width="900">
</div>

Большинство разделов используют поток черновика и применения, поэтому вы можете протестировать провайдера перед подтверждением. Вы также можете просто попросить об этом в Chat: ассистент читает текущую конфигурацию, применяет изменение и сообщает, требуется ли перезапуск или переиндексация, — предварительно проверяя новую модель перед её применением, поэтому он не может переключить себя на что-то недостижимое. API-ключи никогда не проходят через модель — вместо этого она открывает для вас соответствующую форму. В комплект входят четыре темы — Default, Cream, Dark и Glass. Корневые файлы `.env` проекта намеренно игнорируются; конфигурация среды выполнения хранится в `data/user/settings/*.json`, если только `DEEPTUTOR_HOME` или `deeptutor start --home` не указывает приложению другое место.

**OpenAI Codex OAuth (экспериментально).** Добавление **OpenAI Codex** в разделе Настройки → Providers открывает вход через браузер с использованием вашего собственного плана ChatGPT, поэтому `OPENAI_API_KEY` не требуется. Токены хранятся только в `data/system/user-secrets/<owner>/private/openai-codex/` — в многоконтейнерном развёртывании Compose это за пределами любого дерева, доступного песочнице выполнения, — и DeepTutor никогда не читает и не изменяет вашу CLI-авторизацию `~/.codex`. Список моделей формируется из актуального каталога этой учётной записи; вход публикует профиль, но тот становится активной моделью, только если LLM ещё не настроена. Поскольку токен авторизует план одного человека, профиль нельзя передать через гранты для пользователей — каждая учётная запись входит сама за себя, включая обычных пользователей: их карточка входа находится в разделе Providers, а получившиеся модели, каталог и выход из системы остаются приватными для этой учётной записи.

При входе и нажатии **Refresh models** DeepTutor считывает последнюю стабильную версию `@openai/codex` из официального реестра npm и использует её как `client_version` запроса каталога. Это только метаданные: DeepTutor не устанавливает, не скачивает и не обновляет Codex CLI, а запрос к npm не содержит OAuth-учётных данных. У обнаружения есть предельный срок в три секунды и лимит ответа 64 КиБ. Если оно не удаётся, DeepTutor использует последнюю успешную версию для этой учётной записи либо встроенный резервный вариант, если ничего не закэшировано. Новую версию сохраняет только успешно разобранный актуальный каталог; валидаторы никогда не используются повторно между версиями или поколениями учётных данных. Отклонение версии или несовместимая структура каталога допускает одну повторную попытку с предыдущей версией; сбои аутентификации, ограничения частоты запросов и TLS не считаются проблемами версии и не повторяются как таковые. Неудачное ручное обновление сообщает об ошибке, а не выдаёт старый закэшированный каталог как обновлённый.

История успешных версий сохраняется при обновлении токена той же учётной записи и при ошибках аутентификации каталога, но не делает недействительные данные модели или ETags снова пригодными для использования. Выход из системы очищает локальный кэш этой учётной записи, включая историю версий. Обычные проверки состояния и инференс не обращаются к npm. Новые записи каталога не заменяют уже выбранную вами модель и не перезапускают учебные сессии; появление в каталоге не означает полную совместимость протокола инференса. Фонового обновления версий или настройки версии пользователем не существует.

Локальные развёртывания Docker и Podman по умолчанию используют раздельные loopback-сети и во время входа требуют временного моста. Следуйте [руководству по временному локальному мосту Codex OAuth](../../docs-for-dev/CONTAINERIZATION.md#temporary-local-codex-oauth-bridge) для точных команд Docker, Compose, Podman и отключения моста.

При удалённом развёртывании `localhost` браузера и `localhost` сервера — это разные машины, поэтому обычный обратный прокси сам по себе не может доставить обратный вызов с localhost браузера на сервер. Используйте SSH-туннель в качестве моста для обратного вызова. Туннель ведёт к уже опубликованному порту Web; Next.js переписывает только точный путь обратного вызова на публичный брокер обратных вызовов, а брокер проверяет `state`, прежде чем перенаправить к исходной операции OAuth. Слушатель обратного вызова остаётся на loopback-интерфейсе бэкенда, порты `1455` и `1457` не публикуются, и этот путь поддерживает сеть Docker bridge по умолчанию.

```bash
ssh -N -L 1455:127.0.0.1:3782 <ssh-user>@<server-host>
```

Если DeepTutor сообщает резервный порт обратного вызова `1457`, используйте:

```bash
ssh -N -L 1457:127.0.0.1:3782 <ssh-user>@<server-host>
```

Выполняйте только ту команду, которая соответствует фактическому порту обратного вызова; никогда не запускайте обе. `3782` — это только пример порта Web: это настроенный порт фронтенда/контейнера, указанный как `callback_forward_port`. Это значение не гарантирует, что тот же порт прослушивается на `127.0.0.1` SSH-хоста. Если Docker или Podman публикует другой хост-порт или обратный прокси слушает другой порт, замените только правый целевой порт (`3782` выше) на порт Web, который фактически прослушивается на `127.0.0.1` SSH-хоста; левый порт обратного вызова оставьте равным `1455` или `1457`. `<server-host>` — это SSH-хост, чей loopback владеет этим прослушиваемым портом. Если URL браузера указывает на обратный прокси или балансировщик нагрузки, замените его на правильный SSH-хост фронтенда.

CLI выводит команду туннеля, а затем сразу пытается открыть браузер. При удалённом развёртывании оставьте страницу авторизации открытой, не завершая её, установите выведенный туннель в другом терминале и только после этого продолжите авторизацию.

У определения удалённой топологии есть граница localhost. Если сам Web доступен через переадресацию localhost по SSH или из IDE, браузер не может определить, что сервер удалённый. Для текущей операции Web оставьте её страницу авторизации незавершённой, прочитайте `redirect_uri` в URL авторизации этой операции, чтобы определить порт обратного вызова `1455` или `1457`, и создайте второй туннель от этого локального порта к фактическому порту Web. В качестве альтернативы отмените эту операцию Web и начните новую через CLI; вывод CLI относится к новой операции и не должен использоваться для уже существующей операции Web. Ошибки квоты и сбои каталога показываются как есть и никогда не приводят к переключению на платного провайдера. Этот путь совместимости экспериментален: вышестоящий интерфейс может измениться.

### 🛠️ Администрирование и общие развёртывания

Пять областей выше описывают рабочую среду учащегося. Следующие средства управления развёртыванием предназначены для администраторов, размещающих DeepTutor для нескольких пользователей.

<details>
<summary><b>👥 Multi-User — общие развёртывания</b> · необязательная аутентификация, изолированные пользовательские рабочие пространства</summary>

Аутентификация **отключена по умолчанию** — DeepTutor работает в однопользовательском режиме. Включите её, и одно дерево `data/` будет одновременно содержать рабочее пространство администратора, изолированные пользовательские рабочие пространства и рабочие пространства партнёров:

```text
data/
├── user/                    # Admin workspace + global settings
├── users/<uid>/             # Per-user scope: chat history, memory, notebooks, KBs
├── partners/<id>/workspace/ # Partner (synthetic-user) scope
├── cli-apps/                # Installed CLI apps, mounted read-only into the sandbox
└── system/                  # auth · grants · audit · user-secrets/<owner> (OAuth tokens)
```

**Первый зарегистрированный пользователь становится администратором** и владеет каталогами моделей, учётными данными провайдеров, общими базами знаний, навыками, каноническими общими книгами и грантами для пользователей. Локальные пользователи, созданные администратором, выбирают Standard, Learner или Custom. Learner блокирует учебные возможности и политику материалов, добавляет адаптивный профиль и поддерживает отзываемые учётные данные устройства со сроком действия и дневными лимитами; авторизованные опекуны могут просматривать отчёты, одобрять материалы и сбрасывать учётные данные. Остальные пользователи получают изолированные рабочие пространства и ограниченный доступ к моделям, KB, навыкам, партнёрам и общим книгам без получения необработанных API-ключей. Если `auth.json` уже содержит `username` + `password_hash`, эта учётная запись *является* администратором: `/register` остаётся закрытым, а учётные записи, созданные в `/admin/users`, всегда имеют `role=user` до повышения роли.

**Включение:** включите аутентификацию в `data/user/settings/auth.json`, перезапустите `deeptutor start`, зарегистрируйте первого администратора по адресу `/register`, затем добавляйте пользователей из `/admin/users` и назначайте модели, KB, навыки, партнёров, политику инструментов/MCP/CLI-приложений и доступ к выполнению кода через гранты; настройте общие книги в панели **Book access** каждого пользователя.

Для раздельных приватного и публичного источников задайте `auth.private_login_hosts` (или `AUTH_PRIVATE_LOGIN_HOSTS`) — список приватных хостов фронтенда, на которых может показываться вход по паролю и регистрация. Фронтенд передаёт входящий HTTP `Host` на бэкенд как своё утверждение хоста фронтенда. Сохраняйте `Host` браузера через ваш обратный прокси и настройте публичный входной шлюз так, чтобы он отклонял запросы, называющие приватный хост; не открывайте необработанный порт Next.js, принимающий произвольные значения `Host`. HTTP `Host` может быть подделан прямым клиентом, поэтому авторизация приватного хоста зависит от этой границы входного шлюза. По умолчанию бэкенд принимает утверждения хоста фронтенда только с loopback. Если веб-фронтенд подключается из другого контейнера или хоста, задайте `AUTH_TRUSTED_FRONTEND_PROXY_IPS` — точный IP-адрес этого прокси фронтенда в процессе бэкенда (через запятую, если их несколько). Это заменяет значения по умолчанию; добавьте `127.0.0.1,::1`, если нужны также локальные подключения фронтенда. Держите API бэкенда приватным для прокси фронтенда и не включайте в этот список общие клиентские сети. Когда `private_login_hosts` не пуст, аутентифицированный пользователь на приватном источнике может открыть **Profile → Public device sign-in** и создать недолговечную, привязанную к хосту ссылку сопряжения для публичного источника HTTPS. Публичная страница `/handoff` обменивает одноразовый код на такой же недолговечный билет JWE в теле POST-запроса, использует билет один раз и получает обычную сессионную куки HttpOnly.

> PocketBase остаётся однопользовательской интеграцией — оставьте `integrations.pocketbase_url` пустым для многопользовательских развёртываний, если только вы не подключили внешнее хранилище пользователей.

</details>

## ⌨️ DeepTutor CLI — Интерфейс для Агентов

Один бинарный файл `deeptutor`, два способа входа: интерактивный **REPL** для тех, кто живёт в терминале, и структурированный **JSON** для других агентов, которые управляют DeepTutor как инструментом. Одни и те же возможности, инструменты и базы знаний в любом случае.

<details>
<summary><b>Управляйте им самостоятельно</b></summary>

`deeptutor chat` открывает интерактивный REPL и выбирает режим с помощью `--capability`; `deeptutor run <capability> "<message>"` принимает эту возможность как первый позиционный аргумент и завершается после одного хода. Обе команды принимают `--tool`, `--kb`, `--config` и `--workspace` для выбора зарегистрированного рабочего пространства.

```bash
deeptutor chat                                              # interactive REPL
deeptutor chat --capability deep_solve --kb my-kb
deeptutor run chat "Explain the Fourier transform" --kb textbook
deeptutor run chat "Find recent work beyond this material" --kb textbook
deeptutor run deep_research "Survey 2026 papers on RAG" \
  --config mode=report --config depth=standard
```

`--kb` задаёт контекст для автоматически подключаемых инструментов RAG и Knowledge Frontier; Frontier требует одновременно модулей knowledge и research. `--tool` выбирает переключаемые пользователем инструменты. Включённые модули также предоставляют команды для баз знаний, сессий, партнёров, навыков, блокнотов, памяти и конфигурации.

</details>

<details>
<summary><b>Позвольте агенту управлять им</b></summary>

DeepTutor создан для того, чтобы *им управлял другой агент*. Добавьте `--format json` к любой команде `run`, и каждый ход транслирует **NDJSON — одно событие на строку** (`content`, `tool_call`, `tool_result`, `done`, …), каждая строка помечена своим `session_id`. Запуски безопасны без TTY: пауза `ask_user` без TTY автоматически разрешается пустым ответом вместо зависания.

```bash
# One shot, machine-readable
deeptutor run deep_solve "Find d/dx[sin(x^2)]" --tool reason --format json

# Chain turns in one stateful session — capture the id, reuse it
SID=$(deeptutor run deep_research "Survey 2026 papers on RAG" \
  --config mode=report --config depth=standard --format json \
  | jq -r 'select(.type=="done").session_id')
deeptutor run deep_question "Quiz me on that survey" --session "$SID" --format json
```

В репозитории есть корневой [`SKILL.md`](../../SKILL.md) — краткое руководство для агента по работе с CLI. Явно попросите агента прочитать его; [руководство по настройке с помощью агента](../../docs-for-dev/AGENT_SETUP.md) описывает установку и конфигурацию. Также можно обернуть `deeptutor run` как инструмент в цикл LangChain / AutoGen. Полные рецепты: [Agent Handoff](https://deeptutor.info/docs/cli/agent-handoff/).

</details>

<details>
<summary><b>Необязательная визуальная проверка анимаций Manim</b></summary>

Установите `enable_visual_review=true`, чтобы проверять отрисованные кадры на перекрытия, читаемость
и компоновку, а затем передавать обнаруженные проблемы в существующий цикл исправления кода:

```bash
deeptutor run math_animator "Animate a sine wave" --config enable_visual_review=true
deeptutor run visualize "Animate a sine wave" \
  --config render_mode=manim_video --config enable_visual_review=true
```

По умолчанию этот параметр имеет значение `false`. Он также работает с `output_mode=image` для
`math_animator` и `render_mode=manim_image` для `visualize`. Другие визуализаторы,
включая общий цикл `auto`, игнорируют его. Необязательные зависимости Manim
по-прежнему требуются.

Для ходов SDK передайте `config={"enable_visual_review": True}` в `TurnRequest`,
отправляемый в `DeepTutorApp.start_turn()`. Клиенты API используют тот же объект `config` с
JSON-значением `true`. Для анимационных блоков книги задайте
`params={"enable_visual_review": True}` в анимационном `Block`.

Проверка добавляет вызовы зрительной модели и может добавлять вызовы исправления и повторные отрисовки, увеличивая
стоимость и задержку. Используется существующий лимит в четыре повторные попытки, с 120-секундным
тайм-аутом проверки и 180-секундным тайм-аутом исправления. Если кадры недоступны или
настроенная модель проверки не может анализировать изображения, проверка пропускается с итоговым сообщением.
Неудачная проверка после всех повторных попыток возвращает лучшую доступную отрисовку и её
неуспешный результат проверки; тайм-аут проверки следует существующему пути ошибки/повторной попытки отрисовки.
Результаты возможностей предоставляют `render.visual_review`; блоки книги сохраняют те же
данные проверки в `metadata.visual_review` (`null`, если проверка не выполнялась).

</details>

<details>
<summary><b>Справочник команд</b></summary>

Таблица охватывает полную установку и необязательные дополнения; команды и возможности требуют включения соответствующих модулей. Ядро предоставляет `chat` и `ask_questions`.

| Команда | Описание |
|:---|:---|
| `deeptutor init [--non-interactive] [--home PATH]` | Запустить мастер настройки или создать отсутствующие настройки по умолчанию без запросов |
| `deeptutor doctor [--online]` | Проверить, готова ли среда выполнения к запуску сессии; `--online` также проверяет настроенного провайдера модели, `--format json` выводит отчёт |
| `deeptutor start [--home PATH] [--dev] [--detach] [--no-browser]` | Запустить бэкенд + фронтенд вместе; при необходимости отсоединить процесс или запретить открытие браузера |
| `deeptutor stop [--home PATH]` | Остановить лаунчер, запущенный с `--detach` |
| `deeptutor serve [--port PORT]` | Запустить только бэкенд FastAPI |
| `deeptutor module list/install/uninstall/enable/disable` | Просматривать модули и изменять их при остановленном DeepTutor; чекауты исходного кода поддерживают включение и отключение |
| `deeptutor workspace show/set/reset` | Просматривать, выбирать или восстанавливать персональное Content Workspace |
| `deeptutor run <capability> <message>` | Запустить один ход возможности (`chat`, `ask_questions`, `deep_solve`, `deep_question`, `deep_research`, `visualize`, `math_animator`, `video_lesson`, `mastery_path`, `immersive_reading`, `audio_overview`); добавьте `--format json` для вывода NDJSON |

| `deeptutor skill search/install/list/remove/login/logout/publish/update` | Управление навыками, установка из хабов и публикация своих (`eduhub:<slug>` по умолчанию, см. Ecosystem) |

| `deeptutor notebook list/create/show/add-md/replace-md/remove-record` | Управление блокнотами из файлов Markdown |

Учётные данные GitHub Copilot принадлежат вошедшему в систему владельцу DeepTutor и хранятся только в
`<runtime-home>/data/system/user-secrets/<owner-id>/private/github-copilot/credentials.v1.json`,
вне рабочих пространств песочницы. Партнёры CLI/администратора используют учётные данные администратора;
остальные пользователи входят отдельно, а профилями Copilot нельзя делиться через гранты моделей.
Внешние файлы токенов nanobot/Copilot никогда не импортируются: после обновления повторно выполните
`deeptutor provider login github-copilot`.

При входе проверяется инференс с моделью, обнаруженной в актуальном каталоге; `init` проверяет выбранную
модель и при ошибке прерывает работу без сохранения черновой конфигурации. Успешная аутентификация GitHub
сама по себе не подтверждает доступ к моделям Copilot (сохранённая авторизация остаётся,
даже если проверка не пройдена). Запросы во время работы используют конечную точку API, полученную при обмене токена,
в том числе после его обновления, и учитывают метаданные конечных точек Responses/Chat Completions для каждой модели.

Специальная совместимость Responses для Copilot применяется при отправке запроса без перезаписи сохранённой истории.

<details>
<summary><b>Дистрибутив только с CLI</b></summary>

Базовый wheel предоставляет CLI и SDK; `deeptutor-cli` — метапакет для совместимости. Исходный код предоставляет все включённые в репозиторий модули, поэтому для использования CLI установите их зависимости Python и пропустите настройку фронтенда:

```bash
python -m pip install -r requirements/full.txt
python -m pip install -e . --no-deps
```

Для минимальной установки используйте базовый wheel. Необязательные дистрибутивы добавляют инструменты, возможности, API-маршруты, фоновые сервисы и навигацию. Модули используют одну среду Python, и их версии должны совпадать с версией ядра. `deeptutor[full]` выбирает основные модули приложения при установке; отдельные функции можно удалить позднее.

Остановите DeepTutor (`Ctrl+C` в его терминале), затем используйте ту же среду Python и `DEEPTUTOR_HOME`:

```bash
deeptutor module list                       # installed / enabled / ready
deeptutor module disable research           # hide and deactivate; keep code
deeptutor module enable research            # restore it and required modules

# Package installations only; source checkouts use enable / disable:
deeptutor module install solve              # install the matching module and dependencies
deeptutor module uninstall solve --dry-run  # inspect the plan and dependency blockers
deeptutor module uninstall solve            # remove only this module's distribution
deeptutor chat                              # restart the CLI; use start for an installed Web app
```

Примеры: `solve`, `research`, `questions`, `knowledge`, `parsing`, `reading`, `mastery`, `books`, `memory`, `notebook` и `partners`. Зависимые модули препятствуют удалению; ядро нельзя удалить командой управления модулями. Отключение и удаление сохраняют настройки, разговоры, базы знаний и созданные файлы. Общие сторонние зависимости тоже сохраняются.

**В браузере:** раздел **Настройки → Runtime status → Modules** показывает состояние модулей и соответствующие команды терминала. Изменение пакетов требует остановленной среды и выполняется через CLI. **Chat → Customize page** и **Learning → New learning activity → Customize page** сразу меняют личные настройки страниц; скрытие элемента не удаляет его модуль и не отзывает доступ.

В семействе пакетов 1.7.0 версии wheels ядра и функциональных модулей совпадают. При установке локальных wheels передайте `--wheelhouse /path/to/wheels` в `module install`. Инструкции по сборке wheels и развёртыванию приведены в разделе [Установка модулей и разработка из исходного кода](../../docs-for-dev/MODULES.md).

</details>

## 🧩 Экосистема — EduHub и Сообщество Навыков

Навыки DeepTutor используют открытый формат **Agent-Skills** — папку с плейбуком `SKILL.md` (YAML frontmatter + Markdown) и необязательными справочными файлами. В нём нет ничего специфичного для DeepTutor, поэтому любой реестр, поддерживающий этот формат, становится источником для вашей библиотеки. DeepTutor поставляется с **[EduHub](https://eduhub.deeptutor.info/)** — нашим собственным образовательным реестром навыков — встроенным в качестве хаба по умолчанию.

<details>
<summary><b>EduHub — экосистема навыков DeepTutor</b></summary>

[**EduHub**](https://eduhub.deeptutor.info/) — это хаб сообщества, запущенный DeepTutor для обмена обучающими навыками агентов — сократовскими репетиторами, создателями флэш-карточек, средствами обратной связи по эссе, планами экзаменов, объяснениями концепций и многим другим. Он встроен в DeepTutor, поэтому настраивать ничего не нужно: простой слаг или префикс `eduhub:` разрешается в него.

**Найти и установить** — в браузере откройте **Персонализация → Skills → Import from EduHub** для просмотра каталога и загрузки навыка прямо в вашу библиотеку. Из терминала:

```bash
deeptutor skill search "socratic tutor"               # search EduHub (the default hub)
deeptutor skill install socratic-tutor                # fetch → verify → register
deeptutor skill install eduhub:socratic-tutor@1.2.0   # pin a hub and a version
deeptutor skill list                                  # local skills with their hub provenance
```

**Опубликуйте свой** — упакуйте `SKILL.md` и поделитесь им с сообществом:

```bash
deeptutor skill login                                 # browser sign-in to EduHub
deeptutor skill publish ./my-skill                    # interactive: pick a track + tags, then upload
deeptutor skill update                                # roll back or release a new version
```

EduHub также является отдельным, совместимым с ClawHub реестром, поэтому агенты, отличные от DeepTutor (Claude Code, Codex, …), могут использовать его напрямую через CLI `eduhub` — `npx eduhub install socratic-tutor`.

</details>

<details>
<summary><b>Шлюз безопасности импорта</b></summary>

Независимо от источника, каждый импорт проходит через **один и тот же шлюз безопасности** перед тем, как что-либо коснётся вашего рабочего пространства:

- сначала проверяется **вердикт безопасности** реестра — отмеченные пакеты отклоняются, если вы не передали `--allow-unverified`;
- архивы извлекаются безопасно с проверками обхода путей, числа записей, размера, коэффициента сжатия, суффиксов и символических ссылок; биты исполнения снимаются, а файлы без расширения остаются разрешёнными;
- frontmatter нормализуется по схеме DeepTutor, и `always:` **удаляется**, поэтому загруженный навык никогда не может принудительно добавить себя в каждый системный промпт;
- происхождение — хаб, версия, вердикт и время установки — записывается в `.hub-lock.json` для аудитов и обновлений.

В многопользовательских развёртываниях импорт через браузер попадает в слой навыков аутентифицированного пользователя, тогда как установки через CLI и консоль администратора направляются в рабочее пространство владельца/администратора; навыки администратора остаются скрытыми и доступными обычным пользователям только для чтения, пока не выдан грант.

</details>

<details>
<summary><b>Также совместим с ClawHub</b></summary>

Поскольку DeepTutor использует открытый формат Agent-Skills, **[ClawHub](https://clawhub.ai/)** также работает как первоклассный источник — он встроен рядом с EduHub. Выберите его с префиксом хаба:

```bash
deeptutor skill search "git release notes" --hub clawhub
deeptutor skill install clawhub:git-release-notes@1.0.1
deeptutor skill install clawhub:udiedrichsen/stock-analysis
```

Когда один и тот же слаг используют несколько издателей, поиск показывает каждого издателя и
полностью определённую ссылку для установки (`clawhub:<ownerHandle>/<slug>`).

Добавляйте дополнительные реестры в `data/user/settings/skill_hubs.json`: запись `type: "clawhub"` указывает на любой совместимый HTTP API (EduHub и ClawHub оба его поддерживают), `type: "command"` оборачивает любой CLI получения, который поставляет реестр, а `"default"` выбирает хаб, используемый для простых слагов. Все они проходят через тот же шлюз импорта.

</details>
