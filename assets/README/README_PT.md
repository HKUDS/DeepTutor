## ✨ Recursos Principais

O DeepTutor é um espaço de trabalho de aprendizagem nativo de agentes que liga tutoria, pesquisa, criação e prática num sistema extensível.

- **Um runtime, muitos modos de aprendizagem** — Chat, Quiz, Research, Visualize, Solve, Mastery Path, Reading e outros partilham o contexto da sessão, mantendo fluxos de trabalho criados para cada finalidade.
- **Um espaço de trabalho de aprendizagem conectado** — Página inicial, Aprendizagem e Recursos ligam Chat, Books, Reading, Practice, Task Board, Calendar e o caderno de aprendizagem com materiais, progresso e contexto de aprendizagem partilhados.
- **Conhecimento e leitura fundamentados** — crie bibliotecas com versões usando LlamaIndex, PageIndex, GraphRAG ou LightRAG, ligue fontes de conhecimento externas e aprenda junto a documentos, vídeo e áudio com citações ligadas às fontes.
- **Partners e subagentes** — consulte agentes ao vivo como Claude Code, Codex e Grok CLI, importe conversas anteriores ou execute Partners persistentes com memória, recursos e canais IM próprios.
- **Memória inspecionável** — rastreamentos L1, factos L2 e síntese L3 tornam a personalização visível e editável, com ligações às evidências que pode auditar no Memory Graph.
- **Extensível por design** — adicione personas, skills integradas ou da comunidade, serviços MCP, aplicações CLI e modelos de geração através de um runtime nativo de agentes.

## 🚀 Começar

Escolha o caminho de instalação adequado à forma como pretende usar o DeepTutor. As instalações pelo terminal partilham um diretório de runtime: as definições privadas ficam em `data/user/settings/` sob o diretório de arranque, ou sob `DEEPTUTOR_HOME` / `deeptutor start --home` quando definidos explicitamente. Depois de iniciar a aplicação, configure um provedor e um modelo em **Settings → Providers** e **Language models**.

<details>
<summary><b>Desktop — macOS e Windows (Pré-visualização)</b></summary>

O **Open DeepTutor** inclui Python, Node.js e o espaço de trabalho de aprendizagem completo, pelo que não é necessário usar o terminal nem instalar runtimes separados. As pré-visualizações desktop estão disponíveis em `dev`; a **versão v1.7.0 não inclui instaladores desktop**.

Abra uma execução bem-sucedida do [workflow Desktop Release](https://github.com/HKUDS/DeepTutor/actions/workflows/desktop-release.yml?query=branch%3Adev), desça até **Artifacts** e transfira o destino correspondente. É necessário iniciar sessão no GitHub, e os artefactos expiram após sete dias.

| O seu computador | Destino da transferência | Instalador |
| --- | --- | --- |
| **Mac com Apple Silicon** | `macos-arm64` | Abra o DMG e arraste o **Open DeepTutor** para **Applications**. |
| **Mac com Intel** | `macos-x64` | Abra o DMG e arraste o **Open DeepTutor** para **Applications**. |
| **Windows x64** | `windows-x64` | Execute o Setup `.exe` ou extraia o ZIP portátil e inicie `Open DeepTutor.exe`. |

As compilações de pré-visualização para Windows não são assinadas e podem apresentar um aviso do SmartScreen. Consulte o [guia desktop](../../apps/desktop/README.md) para assinatura, dados locais e compilações a partir do código-fonte.

</details>

<details>
<summary><b>Docker — A Forma Mais Rápida de Experimentar a Aplicação Completa</b></summary>

Execute a aplicação Web completa sem instalar Python nem Node.js:

```bash
docker run --rm --name deeptutor \
  -p 127.0.0.1:3782:3782 \
  -v deeptutor-data:/app/data \
  ghcr.io/hkuds/deeptutor:latest
```

Abra [http://127.0.0.1:3782](http://127.0.0.1:3782). O volume nomeado preserva as definições e os dados locais; apenas a porta `3782` é necessária para a aplicação Web. Consulte o [guia Docker](https://docs.deeptutor.info/get-started/docker/) para workspaces do host, serviços de modelos locais, proxies inversos e implementação em produção.

</details>

<details>
<summary><b>PyPI — Aplicação Web Completa e CLI</b></summary>

Use **Python 3.11–3.14** e **Node.js 20.9+**. Na versão modular 1.7.0, `deeptutor[full]` instala a aplicação Web e a CLI; o `deeptutor` simples instala o chat do núcleo e o SDK.

```bash
mkdir -p my-deeptutor && cd my-deeptutor
python -m pip install -U "deeptutor[full]"
deeptutor init     # ports + LLM provider + optional embedding/search
deeptutor start    # starts backend + frontend
```

Abra o URL impresso no terminal, por predefinição [http://127.0.0.1:3782](http://127.0.0.1:3782). Prima `Ctrl+C` para parar ambos os serviços.

**Atualizar a partir da versão 1.6.15 ou anterior:** pare o DeepTutor, faça uma cópia de segurança do diretório de runtime e desinstale o pacote legado `deeptutor-cli` antes de instalar a nova família. Mantenha o mesmo `DEEPTUTOR_HOME` e depois execute `python -m pip check` e `deeptutor module list`. Consulte o [guia PyPI e de migração](https://docs.deeptutor.info/get-started/pypi/) para os comandos exatos de atualização.

</details>

<details>
<summary><b>Código-Fonte — Dev Atual e Contribuidores</b></summary>

Use **Python 3.11–3.14** e **Node.js 22 LTS** para coincidir com CI e Docker.

```bash
git clone --branch dev https://github.com/HKUDS/DeepTutor.git
cd DeepTutor
python3 -m venv .venv && source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements/full.txt
python -m pip install -e . --no-deps
( cd web && npm ci --legacy-peer-deps )
deeptutor init
deeptutor start --dev
```

Use `deeptutor start` sem `--dev` para uma compilação de produção. As dependências opcionais são instaladas a partir da raiz do repositório, por exemplo `python scripts/install_extras.py dev,partners,math-animator`. Consulte o [guia de instalação a partir do código-fonte](https://docs.deeptutor.info/get-started/from-source/) para Conda, extras e resolução de problemas, ou o [guia de configuração por agentes](../../docs-for-dev/AGENT_SETUP.md) para permitir que um agente com acesso ao terminal execute e verifique a configuração.

</details>

<details>
<summary><b>CLI — Utilização no Terminal e por Agentes</b></summary>

Para uma instalação mínima pelo terminal, use o wheel do núcleo; não são necessários Node.js nem frontend Web:

```bash
mkdir -p my-deeptutor && cd my-deeptutor
python -m pip install -U deeptutor
deeptutor init --cli
deeptutor chat
```

O núcleo inclui Chat, Ask Questions, a CLI e o SDK; outras capacidades e comandos de gestão requerem os respetivos módulos de funcionalidades. Para a instalação atual a partir do código-fonte `dev` e dependências opcionais, consulte o [guia de apenas CLI](https://docs.deeptutor.info/get-started/cli-only/). A [referência da CLI](#️-deeptutor-cli--interface-nativa-de-agentes) abaixo abrange execuções únicas e saída legível por máquina.

</details>

<details>
<summary><b>🏠 Página Inicial — Conversas, Tarefas, Notas e Calendário</b></summary>

A Página inicial é onde o trabalho diário começa: fale com o tutor, organize as próximas ações e desenvolva as suas próprias notas no workspace atual. O Calendar oferece uma vista abrangente da conta, mantendo o workspace de origem dos eventos de estudo.

<details>
<summary><b>💬 Chat — O Loop de Agente que Realmente Usa</b></summary>

Chat é a capacidade predefinida e o lugar onde a maior parte do trabalho começa. Um único thread pode conversar normalmente, chamar ferramentas, fundamentar-se em bases de conhecimento selecionadas, ler anexos, gerar imagens, consultar subagentes, escrever registos de notebook e continuar com o mesmo contexto entre turnos.

<div align="center">
<img src="../../assets/figs/web-dev/chat.png" alt="Espaço de trabalho de chat DeepTutor" width="900">
</div>

O tutor chama ferramentas conforme necessário e pode pausar para fazer perguntas de esclarecimento. **Personalizar página**, no canto superior direito, escolhe os modos visíveis e os controlos de Skills, MCP, Partners, Preferências e entrada de voz. Em **Prompts iniciais**, adicione, edite ou remova os títulos e prompts de Explicar, Resolver, Praticar, Planear e Pesquisar. Guardar aplica as preferências da conta; Cancelar descarta as alterações e Restaurar predefinições repõe as escolhas originais.

<div align="center">
<img src="../../assets/figs/system/chat-agent-loop.svg" alt="Loop de agente de chat DeepTutor" width="900">
</div>

As ferramentas ativáveis pelo utilizador são `brainstorm`, `web_search`, `paper_search`, `zotero_search`, `reason` e `geogebra_analysis` — mais `imagegen` e `videogen` depois de configurar o modelo de geração correspondente. Ferramentas contextuais como `rag`, `kb_files`, `knowledge_frontier`, `read_source`, `read_memory`, `write_memory`, `read_skill`, `load_tools`, `exec`, `web_fetch`, `ask_user`, `list_favorites`, `save_favorite`, `write_note`, `search_notes`, `question_bank`, `github`, `consult_subagent`, `workspace_list`, `workspace_read`, `workspace_search`, `workspace_present` e `workspace_export` montam automaticamente quando o turno tem o contexto certo.

O contexto é de dois tipos: o **contexto de sessão fixo** (capacidade, workspace ou curso, ferramentas, bases de conhecimento, persona, modelo e estado de Reading / Mastery) persiste entre turnos; as **referências** (ficheiros, histórico de chat, livros, secções de leitura, notebooks, entradas selecionadas do banco de questões, agentes importados) vêm do menu `+` para um turno por predefinição, ou para todos os turnos quando fixadas. O botão de voz transcreve apenas a mensagem atual.

Com o perfil completo, a Página inicial mantém **Chat**, **Ask Questions**, **Quiz**, **Visualize** e **Video Lesson** a um clique de distância; **Research** para relatórios com citações e **Solve** para raciocínio desenvolvido ficam em *Mais capacidades*. Selecione texto numa resposta para abrir o **Little Tutor**, um thread focado na barra lateral que permanece aninhado sob a conversa de origem. Com pelo menos três mensagens enviadas, a margem esquerda mostra uma marca para cada pergunta quando há espaço; passe o cursor para pré-visualizar, clique para voltar ou use **Alt/Option + ↑/↓** para se mover entre perguntas.

</details>

<details>
<summary><b>✅ Task Board e Calendar — Organize a Aprendizagem Diária</b></summary>

O **Task Board** acompanha tarefas de estudo em Por fazer, Em curso e Concluído, com notas, arrastar e largar ou controlos de movimentação acessíveis por teclado, e um arquivo do qual pode restaurá-las. As tarefas permanecem no workspace atual e não requerem configuração de modelo.

O **Calendar** reúne sessões de estudo pessoais, eventos recorrentes e lembretes, com exportação `.ics` para Apple Calendar, Google Calendar, Outlook e Thunderbird. As sobreposições do workspace, como datas de vencimento de tarefas e revisões, permanecem ligadas ao respetivo workspace de origem.

</details>

<details>
<summary><b>✍️ Caderno de Aprendizagem — Páginas, Fontes e Dito</b></summary>

<div align="center">
<img src="../../assets/figs/web-dev/co-writer.png" alt="Páginas do caderno de aprendizagem" width="900">
</div>

O caderno de aprendizagem, anteriormente Co-Writer, organiza a sua escrita em páginas, subpáginas e blocos no workspace ativo. Importe documentos Word, organize uma árvore de páginas e insira registos originais dos Favoritos como evidência. As páginas mantêm o estado de gravação visível e podem ser exportadas para Markdown ou Word; o conteúdo interativo torna-se estático no Word.

**Exportar cartões flash para o Anki.** As páginas do caderno podem incluir Flash Cards. Numa página que os contenha, abra o menu da página e escolha **Exportar cartões flash (Anki)**. Na fila de revisão do caderno, escolha **Exportar tudo para o Anki**. No Anki, use **Ficheiro → Importar** e selecione o ficheiro `.txt` transferido. Os cartões são colocados num baralho chamado `DeepTutor::<note title>` com campos de frente/verso, etiquetas e matemática preservados. Voltar a importar o mesmo ficheiro atualiza os cartões existentes em vez de os duplicar. O calendário de revisão próprio do DeepTutor não está incluído.

<div align="center">
<img src="../../assets/figs/web-dev/notebook-detail.png" alt="Editor de blocos do caderno de aprendizagem e Dito" width="900">
</div>

Discuta um trecho ou bloco com **Dito**: peça uma explicação, um exemplo, uma reescrita ou uma pergunta de prática. As conversas permanecem associadas à página e à linha relevantes. Reveja as alterações propostas antes de as aceitar, ou insira uma resposta abaixo da linha e continue a trabalhar. Os Favoritos preservam os registos das fontes; o caderno é onde constrói a sua própria compreensão.

</details>

</details>

<details>
<summary><b>🎓 Aprendizagem — Livros, Percursos, Leitura e Prática</b></summary>

A Aprendizagem é a área de estudo do workspace atual. Crie uma atividade em **Aprendizagem → Nova aprendizagem** e depois reabra-a em **Toda a aprendizagem** com o progresso, as conversas e o contexto das fontes intactos.

<div align="center">
<img src="../../assets/figs/web-dev/learning.png" alt="Atividades de aprendizagem no workspace atual" width="900">
</div>

| Atividade | Para que serve | O que conserva |
| --- | --- | --- |
| **Book** | Criar um livro estruturado e interativo a partir de fontes selecionadas | Capítulos editáveis, blocos tipados, progresso de leitura e Page Chat |
| **Mastery Path** | Dividir um objetivo de aprendizagem em tópicos e estudo orientado | Um mapa de pontos de conhecimento, conversas por tópico e evidências de domínio |
| **Immersive Reading** | Trabalhar junto a um documento, página Web, vídeo ou fonte de áudio | Conversas ligadas às fontes, citações verificadas, destaques, notas e progresso |
| **Practice** | Rever perguntas recolhidas ou importadas | Respostas, erros, classificações de recordação e a próxima data de revisão |

<details>
<summary><b>📖 Book — Livros Vivos dos Seus Materiais</b></summary>

<div align="center">
<img src="../../assets/figs/web-dev/books.png" alt="Biblioteca de livros DeepTutor" width="900">
</div>

Book converte fontes selecionadas num **livro vivo** interativo — não um PDF estático, mas um ambiente de leitura construído a partir de blocos tipados. Um livro pode começar a partir de bases de conhecimento, Favoritos, bancos de perguntas ou histórico de chat; o fluxo de criação propõe uma estrutura de capítulos antes de o conteúdo ser gerado, para que possa rever a forma em vez de aceitar uma saída cega de disparo único.

<p align="center">
<img src="../../assets/figs/web-dev/book-quiz.png" alt="Bloco de quiz do Book" width="31%">
&nbsp;
<img src="../../assets/figs/web-dev/book-detail.png" alt="Estrutura e capítulos do livro" width="31%">
&nbsp;
<img src="../../assets/figs/web-dev/book-widget.png" alt="Bloco de widget interativo do Book" width="31%">
</p>

Cada capítulo compila em blocos tipados editáveis — texto, callouts, quizzes, cartões flash, linhas do tempo, código, figuras, HTML interativo, animações, gráficos de conceitos, aprofundamentos e notas de utilizador — com o seu próprio Page Chat. Insira, mova, regenere, reescreva ou mude o tipo de um bloco; os trechos selecionados entram numa caixa de entrada de capturas de aprendizagem sujeita a revisão. O progresso, os marcadores, as tentativas de quiz, as capturas e o Page Chat permanecem privados por leitor, mesmo quando um livro do administrador é partilhado em modo só de leitura ou para edição colaborativa; a eliminação de livros partilhados continua reservada ao administrador. Qualquer livro pode ser exportado para Markdown, as compilações longas pausam e retomam, `deeptutor book health` assinala divergências nas fontes e `deeptutor book refresh-fingerprints` atualiza a linha de base das fontes.

<summary><b>📚 Centro de Conhecimento — Bibliotecas RAG Multi-Motor</b></summary>

<div align="center">
<img src="../../assets/figs/web-dev/knowledge.png" alt="Centro de Conhecimento DeepTutor" width="900">
</div>

As bases de conhecimento são as coleções de documentos por trás do RAG — fundamentam os turnos do Chat, edições do caderno de aprendizagem, geração do Book e conversas do Partner. O que é distintivo é uma **escolha de motores de recuperação**: **LlamaIndex** (o padrão, vetor híbrido + BM25 com reranking opcional por cross-encoder e índices FAISS exact-flat ou HNSW), **PageIndex** (recuperação de raciocínio com citações ao nível da página, alojado ou OSS auto-hospedado), **GraphRAG** e **LightRAG** (recuperação de grafo de conhecimento), **LightRAG Server** (recuperação delegada a uma instância externa de LightRAG conectada via HTTP), **WeKnora** (recuperação a partir de uma base de conhecimento na sua implementação auto-hospedada, sem índice local nem cópia de documentos), **Tencent IMA** (uma biblioteca que cura no IMA — pesquisada, navegada e escrita de volta através da sua OpenAPI), **MarginNote 4** (os seus dados de estudo MN4 — documentos, excertos, cartões de mapa mental e as ligações entre eles — enviados pelo Add-on da aplicação e navegados com ferramentas dedicadas), **Kiwix** (um arquivo ZIM pesquisável servido por HTTP sem indexação local), ou um vault **Obsidian** vinculado que o tutor lê e escreve no lugar. Cada KB está vinculada a um motor.

<div align="center">
<img src="../../assets/figs/web-dev/knowledge-create.png" alt="Criar uma base de conhecimento" width="900">
</div>

Vai migrar uma biblioteca Obsidian, Hermes ou Markdown existente? Consulte o [guia de migração de Knowledge](../../docs-for-dev/KNOWLEDGE_MIGRATION.md) para os caminhos de vault ligado e cópia indexada.

Ao criar uma KB, pode **criar nova** (carregar e indexar documentos), **vincular existente** (reutilizar um índice no local) ou **conectar Kiwix** (pesquisar um arquivo ZIM servido quando necessário). Escolha o workspace de armazenamento ao criar a KB; uma KB existente pode ser movida entre workspaces após uma pré-visualização, mantendo as atribuições e as referências guardadas. Uma KB também pode rastrear **repositórios GitHub** (repositório, branch, glob) ou **URLs de sites de documentação** (com profundidade de rastreio e número de páginas limitados, resincronizados a cada 24 h por predefinição); a sincronização compara hashes para detetar conteúdo adicionado, alterado ou removido, para que a documentação que segue se mantenha atual sem reenvio, e as **pastas vinculadas** capturam ficheiros locais novos ou alterados na sincronização. A reindexação escreve um novo diretório plano `version-N` e mantém os anteriores, pelo que um índice funcional nunca é destruído a meio de uma reconstrução. Um único documento pode ser removido mesmo de uma base em estado de **erro** — descartando um ficheiro que falhou a análise sem uma eliminação e reconstrução completas. A análise de documentos — Somente Texto, MinerU, Docling, Tika, markitdown, PyMuPDF4LLM ou LiteParse — e um modelo opcional de descrição de imagens são escolhidos em **Settings → Knowledge & documents**, com downloads de modelos locais desativados por predefinição. O Docling também pode correr em modo **remoto** contra um servidor Docling Serve (sem necessidade de instalação local nem de modelos), configurado nessa página (`mode=remote`, um URL base do servidor e uma chave API opcional) ou das variáveis de ambiente `DOCLING_MODE` / `DOCLING_API_BASE_URL` / `DOCLING_API_TOKEN`. O Tika é apenas remoto e aponta para o servidor Apache Tika configurado nessa página. A CLI espelha o ciclo de vida com `list/info/create/connect-kiwix/add/search/eval/eval-diff/set-default/delete`, comandos para adicionar ou remover fontes, `list-sources` e `sync`.

O motor LightRAG integrado é instalado com `pip install 'deeptutor[rag-lightrag]'`. Esse extra contém o SDK LightRAG suportado, mas não instala o MinerU. Escolha o MinerU de forma independente em Document Parsing e configure o seu modo cloud ou instale a sua CLI local atual quando quiser análise estruturada. O MinerU aceita PDF, imagens raster comuns, DOCX, PPTX e XLSX; o comando legado `magic-pdf` continua limitado a PDF. O motor Somente Texto e os restantes motores de análise não requerem o MinerU.

As consultas nativas do LightRAG e a indexação incremental exigem a configuração de embedding registada pelo índice publicado, incluindo o modelo, a dimensão e a identidade do endpoint. Se esta mudar, restaure a configuração original ou reconstrua com o embedding atual; os índices sem uma identidade de embedding registada exigem uma reconstrução. As vistas de detalhe da base de conhecimento e de versão do índice mostram orientações de recuperação, enquanto os ficheiros permanecem disponíveis para visualização e download.

**Avaliar uma base de conhecimento.** Com vários motores disponíveis, «qual recupera melhor aqui?» é uma pergunta empírica — e `deeptutor kb eval` responde-lhe. Escreva um conjunto de perguntas e respostas (um objeto JSON por linha: uma `query` e os trechos `gold` que uma recuperação ideal deveria devolver) e avalie a KB com `deeptutor kb eval <name> --dataset qa.jsonl --top-k 5 [--mode hybrid] [--save baseline.json]`. Cada caso é recuperado pelo mesmo caminho usado num turno de chat; as suas citações ordenadas são comparadas com os trechos de referência por texto exato ou sobreposição lexical (os limiares são ajustáveis com `--min-ratio`; a equivalência semântica não é avaliada), e a execução apresenta **Recall@k / Precision@k / nDCG@k / MRR / MAP / Hit@k**. As métricas são funções puras sobre a ordenação; nenhum modelo julga o resultado. Compare os relatórios guardados com `deeptutor kb eval-diff baseline.json candidate.json` para ver as alterações por métrica e por caso. Use `--rewrite off` ou `--rewrite standalone` em `kb eval` para comparar as consultas originais e reescritas; os relatórios conservam a proveniência da reescrita. Os casos em que a pesquisa falhou (índice em falta, credenciais incorretas) não recebem pontuação e são reportados separadamente, em vez de baixar as médias. O PageIndex usa raciocínio para a recuperação e não devolve chunks ordenados, pelo que fica excluído.

```jsonl
{"query": "Why do transformers scale attention?", "gold": ["Scaling keeps the dot products from growing with the dimension."]}
```

<summary><b>⚙️ Configurações — Um Plano de Controlo</b></summary>

<div align="center">
<img src="../../assets/figs/web-dev/settings.png" alt="Navegador de configurações" width="900">
</div>

Configurações é o plano de controlo operacional e abre em **Geral**, com o idioma da interface e o de saída do modelo. O navegador pesquisável liga a páginas independentes: **Pessoal** inclui Workspaces, Migração de dados, Aparência e Estatísticas de utilização; **Aprendizagem e conversa** inclui pontos de partida, anexos, Video Learning, controlos de alunos e responsáveis, Progresso de aprendizagem e Memory; **Modelos e serviços** inclui Provedores, Modelos de linguagem, Modelos de tarefa, Embedding, Search, Voz e Geração multimodal; **Funcionalidades e integrações** inclui ferramentas, parâmetros de capacidades, Partners e agentes e Conhecimento e documentos. **Sistema** reúne Rede, Estado de execução e Sobre; **Conversas arquivadas** permite pesquisar, restaurar ou eliminar permanentemente conversas arquivadas. Estado de execução contém a saúde do backend, memória residente e a matriz de **Prontidão**, que classifica bloqueios, avisos e sugestões das capacidades. Workspaces mantém os ficheiros dos temas e o estado de aprendizagem separados, com migração e exportação verificadas em Migração de dados. Um **provedor** guarda o endereço e a credencial de um fornecedor para reutilização pelos seus modelos de serviço; as páginas de modelos selecionam provedores guardados e configuram nomes e capacidades dos modelos. Os **modelos de tarefa** fixam um modelo pequeno e rápido para trabalho automático — desde nomear conversas e escrever pontos de partida até reparações do Math Animator e Video Lesson — e usam a predefinição ativa quando deixados em branco. Voz agrupa síntese e transcrição de voz; Geração multimodal agrupa modelos de imagem e vídeo. Partners e agentes configura harnesses locais e um gateway Hermes remoto.

**Vietnamita:** em **Settings → Geral**, escolha **Tiếng Việt** para **Idioma da interface** e selecione **Aplicar alterações**. O **Idioma de saída do modelo** é independente: escolha **Tiếng Việt** nesse campo para respostas em vietnamita, ou mantenha outro idioma de resposta enquanto usa a interface em vietnamita. A qualidade das respostas depende do suporte de vietnamita do modelo selecionado.

**Voz Xiaomi MiMo.** Adicione um provedor Xiaomi MiMo com `https://api.xiaomimimo.com/v1` e a sua chave API; depois adicione `mimo-v2.5-tts` em Settings → Voz. Escolha uma voz predefinida como `mimo_default`, `冰糖` ou `苏打`, use saída `wav` ou `pcm16` e experimente-a antes de aplicar. As instruções de voz controlam o estilo e a velocidade da fala. Este adaptador suporta apenas vozes predefinidas; o design e a clonagem de voz exigem modelos separados e não são suportados. Se um modelo de voz MiMo anterior tiver sido configurado através do adaptador genérico compatível com OpenAI, recrie a respetiva entrada de voz usando o provedor Xiaomi MiMo, para que utilize o protocolo chat-completions. Consulte o [guia oficial de voz MiMo](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/audio/speech-synthesis-v2.5).

**Voz MiniMax** — em Settings → Voz, escolha MiniMax para síntese de voz e selecione `speech-2.8-hd`. Configure uma chave API MiniMax e selecione explicitamente uma voz do sistema ou introduza um ID de voz personalizado. A base da API é `https://api.minimax.io/v1` por predefinição; para a região da China, use `https://api.minimaxi.com/v1`. A leitura em voz alta e as pré-visualizações de voz usam o endpoint de voz nativo, com saída MP3, WAV, FLAC ou PCM e controlos de taxa de amostragem, velocidade e idioma. Consulte a [API de voz MiniMax](https://platform.minimax.io/docs/api-reference/speech-t2a-http) para IDs de voz e disponibilidade por conta.


**Video Learning** em Settings → Aprendizagem e conversa configura as legendas do YouTube e o acesso ao Invidious para Reading. Para usar o Invidious, defina a origem da API do backend gerida pelo administrador (por exemplo, `http://127.0.0.1:3000`) e a origem pública acessível pelo navegador, teste a ligação, selecione Invidious e guarde. **Browse Invidious** no diálogo para adicionar materiais do Reading pesquisa vídeos e acede às subscrições e listas de reprodução conectadas. A reprodução do YouTube usa o leitor oficial com privacidade melhorada; a ausência de legendas permanece visível e limita as evidências do tutor sem bloquear a reprodução nativa. Num checkout do código-fonte, execute `python scripts/install_extras.py video-learning` para o carregador predefinido de legendas do YouTube. Os links existentes de Watching migram para Reading, preservando o histórico de conversas, transcrições compatíveis, notas e progresso; as novas notas com marcas temporais são anotações do Reading. O Bilibili usa o seu próprio caminho de reprodução e legendas.

<div align="center">
<img src="../../assets/figs/web-dev/appearance.png" alt="Configurações de aparência e temas DeepTutor" width="900">
</div>

A maioria das secções usa um fluxo de rascunho e aplicação, para que possa testar um provedor antes de o confirmar. Também pode simplesmente pedir no Chat: o assistente lê a configuração atual, aplica uma alteração e diz se é necessário reiniciar ou reindexar — testando um novo modelo antes de o confirmar, para que nunca possa mudar-se sozinho para algo inacessível. As chaves API nunca passam pelo modelo, que em vez disso abre o formulário correspondente para si. Quatro temas incluídos — Default, Cream, Dark e Glass. Os ficheiros `.env` da raiz do projeto são intencionalmente ignorados; a configuração de runtime vive sob `data/user/settings/*.json` a menos que `DEEPTUTOR_HOME` ou `deeptutor start --home` aponte a aplicação para outro lugar.

**OpenAI Codex OAuth (experimental).** Adicionar **OpenAI Codex** em Settings → Provedores abre um login no navegador que corre contra o seu próprio plano ChatGPT, pelo que não é necessária nenhuma `OPENAI_API_KEY`. Os tokens vivem apenas em `data/system/user-secrets/<owner>/private/openai-codex/` — na implementação multi-contentor com Compose, fora de qualquer árvore que o sandbox de execução possa alcançar — e o DeepTutor nunca lê nem modifica o seu login CLI `~/.codex`. A lista de modelos vem do catálogo ao vivo dessa conta; iniciar sessão publica o perfil mas só se torna o modelo ativo quando ainda não há nenhum LLM configurado. Como um token autoriza o plano de uma pessoa, o perfil não é partilhável através de concessões de utilizador — cada conta inicia sessão por si própria, incluindo utilizadores comuns: o seu cartão de início de sessão está em Provedores, e os modelos, o catálogo e o logout resultantes permanecem privados dessa conta.

No início de sessão e em **Refresh models**, o DeepTutor lê a última versão estável de `@openai/codex` do registo npm oficial e usa-a como o `client_version` do pedido de catálogo. Isto é apenas metadados: não instala, descarrega nem atualiza a CLI Codex, e o pedido npm não transporta credenciais OAuth. A descoberta tem um limite de três segundos e um limite de resposta de 64 KiB. Se falhar, o DeepTutor usa a última versão bem-sucedida para essa conta, ou o seu fallback incorporado quando nenhuma estiver em cache. Apenas um catálogo ao vivo analisado com sucesso guarda uma nova versão; os validadores nunca são reutilizados entre versões ou entre gerações de credenciais. Uma rejeição de versão ou uma estrutura de catálogo incompatível permite uma repetição com a versão anterior; falhas de autenticação, de limite de taxa e de TLS não são repetidas como problemas de versão. Uma atualização manual falhada reporta um erro em vez de apresentar um catálogo antigo em cache como atualizado.

O histórico de versões bem-sucedido sobrevive à renovação de token da mesma conta e a erros de autenticação do catálogo, sem tornar novamente utilizáveis dados de modelo ou ETags invalidados. Terminar sessão limpa a cache local dessa conta, incluindo o histórico de versões. As leituras de estado normais e a inferência não consultam o npm. Novas entradas do catálogo não substituem um modelo já selecionado nem reiniciam sessões de aprendizagem em curso; aparecer no catálogo não estabelece compatibilidade total do protocolo de inferência. Não existe um atualizador de versão em segundo plano nem uma definição de versão pelo utilizador.

As implementações locais predefinidas com Docker e Podman usam redes loopback separadas e precisam de uma ponte temporária durante o início de sessão. Siga o [guia da ponte OAuth temporária local do Codex](../../docs-for-dev/CONTAINERIZATION.md#temporary-local-codex-oauth-bridge) para os comandos exatos de Docker, Compose, Podman e desmontagem.

Para uma implementação remota, o `localhost` do navegador e o `localhost` do servidor são máquinas diferentes, pelo que um proxy inverso comum sozinho não consegue transportar o callback localhost do navegador até ao servidor. Use um túnel SSH como ponte de callback. O túnel alcança a porta Web já publicada; o Next.js reencaminha apenas o caminho exato de callback para o broker de callback público, e o broker valida `state` antes de encaminhar para a operação OAuth original. O listener de callback permanece no loopback do backend, as portas `1455` e `1457` não são publicadas, e este caminho suporta a rede bridge predefinida do Docker.

```bash
ssh -N -L 1455:127.0.0.1:3782 <ssh-user>@<server-host>
```

Se o DeepTutor reportar a porta de callback de reserva `1457`, use:

```bash
ssh -N -L 1457:127.0.0.1:3782 <ssh-user>@<server-host>
```

Execute apenas o comando que corresponde à porta de callback real; nunca execute ambos. `3782` é apenas a porta Web de exemplo: é a porta de frontend/contentor configurada, reportada como `callback_forward_port`. Esse valor não garante que a mesma porta esteja à escuta no `127.0.0.1` do host SSH. Se o Docker ou o Podman publicarem uma porta de host diferente, ou um proxy inverso escutar numa porta diferente, substitua apenas a porta de destino do lado direito (`3782` acima) pela porta Web que realmente está à escuta no `127.0.0.1` do host SSH; mantenha a porta de callback do lado esquerdo como `1455` ou `1457`. `<server-host>` é o host SSH cujo loopback possui essa porta à escuta. Se o URL do navegador nomear um proxy inverso ou balanceador de carga, substitua-o pelo host frontend SSH correto.

A CLI imprime o comando do túnel e depois tenta imediatamente abrir o navegador. Numa implementação remota, mantenha a página de autorização aberta sem a concluir, estabeleça o túnel impresso noutro terminal, e só depois continue a autorização.

A deteção de topologia remota tem um limite de localhost. Se o próprio Web for alcançado através de um encaminhamento localhost SSH ou de IDE, o navegador não consegue saber que o servidor é remoto. Para a operação Web atual, deixe a sua página de autorização por concluir, leia `redirect_uri` no URL de autorização dessa operação para identificar a porta de callback `1455` ou `1457`, e crie o segundo túnel a partir dessa porta local para a porta Web real. Em alternativa, cancele essa operação Web e inicie uma nova com a CLI; a saída da CLI pertence à nova operação e não deve ser usada para a operação Web existente. Erros de quota e falhas de catálogo são reportados tal como ocorrem e nunca recorrem a um provedor pago. Este caminho de compatibilidade é experimental: a interface upstream pode mudar.

</details>

</details>

### 🛠️ Administração e Implementações Partilhadas

As cinco áreas acima descrevem o workspace virado para o estudante. Os controlos de implementação seguintes destinam-se a administradores que alojam o DeepTutor para vários utilizadores.

<details>
<summary><b>👥 Multi-Utilizador — Implementações Partilhadas</b> · autenticação opcional, espaços de trabalho isolados por utilizador</summary>

A autenticação está **desativada por predefinição** — o DeepTutor corre em modo de utilizador único. Ative-a e uma árvore `data/` aloja um espaço de trabalho de administrador, espaços de trabalho por utilizador isolados e espaços de trabalho de partners lado a lado:

```text
data/
├── user/                    # Admin workspace + global settings
├── users/<uid>/             # Per-user scope: chat history, memory, notebooks, KBs
├── partners/<id>/workspace/ # Partner (synthetic-user) scope
├── cli-apps/                # Installed CLI apps, mounted read-only into the sandbox
└── system/                  # auth · grants · audit · user-secrets/<owner> (OAuth tokens)
```

O **primeiro utilizador registado torna-se administrador** e possui catálogos de modelos, credenciais de provedores, bases de conhecimento partilhadas, skills, livros partilhados canónicos e concessões por utilizador. Os utilizadores locais criados pelo administrador podem ser Standard, Learner ou Custom. Learner bloqueia as capacidades de aprendizagem e a política de materiais, acrescenta um perfil adaptativo e suporta credenciais de dispositivo revogáveis com validade e limites diários; responsáveis autorizados podem consultar relatórios, aprovar materiais e repor credenciais. Os restantes utilizadores recebem espaços de trabalho isolados e modelos, KBs, skills, Partners e acesso a livros partilhados com âmbito, sem receber chaves API brutas. Se `auth.json` já contiver um `username` + `password_hash`, essa conta *é* o administrador: `/register` permanece fechado e as contas criadas em `/admin/users` são sempre `role=user` até serem promovidas.

**Ativar:** ligue a autenticação em `data/user/settings/auth.json`, reinicie `deeptutor start`, registe o primeiro administrador em `/register`, depois adicione utilizadores em `/admin/users` e atribua modelos, KBs, skills, Partners, política de ferramentas/MCP/aplicações CLI e acesso de execução de código através de concessões; configure os livros partilhados no painel **Book access** de cada utilizador.

Para origens privadas/públicas separadas, defina `auth.private_login_hosts` (ou `AUTH_PRIVATE_LOGIN_HOSTS`) para os hosts de frontend privados que podem mostrar o início de sessão por palavra-passe e o registo. O frontend reencaminha o `Host` HTTP recebido para o backend como a sua afirmação de host de frontend. Preserve o `Host` do navegador através do seu proxy inverso, e faça com que o ingress público recuse pedidos que indiquem um host privado; não exponha uma porta Next.js em bruto que aceite valores de `Host` arbitrários. O `Host` HTTP pode ser falsificado por um cliente direto, por isso a autorização de host privado depende dessa fronteira de ingress. O backend aceita afirmações de host de frontend apenas a partir do loopback por predefinição. Se o frontend Web se ligar a partir de outro contentor ou host, defina `AUTH_TRUSTED_FRONTEND_PROXY_IPS` para o endereço IP exato desse proxy de frontend no processo do backend (separado por vírgulas para mais de um). Isto substitui as predefinições; inclua `127.0.0.1,::1` se também forem necessárias ligações locais do frontend. Mantenha a API do backend privada para o proxy de frontend e não inclua redes de clientes gerais nesta lista. Quando `private_login_hosts` não está vazio, um utilizador autenticado numa origem privada pode abrir **Profile → Public device sign-in** e criar uma ligação de emparelhamento de curta duração e vinculada ao host para uma origem pública HTTPS. A página pública `/handoff` troca o código único por um bilhete JWE igualmente de curta duração num corpo POST, consome o bilhete uma vez e recebe o cookie de sessão HttpOnly normal.

> O PocketBase continua a ser uma integração de utilizador único — mantenha `integrations.pocketbase_url` em branco para implementações multi-utilizador a menos que tenha ligado um armazém de utilizadores externo.

</details>

## ⌨️ DeepTutor CLI — Interface Nativa de Agentes

Um binário `deeptutor`, duas formas de entrada: um **REPL** interativo para pessoas que vivem no terminal, e **JSON** estruturado para outros agentes que conduzem o DeepTutor como uma ferramenta. As mesmas capacidades, ferramentas e bases de conhecimento de qualquer forma.

<details>
<summary><b>Conduzir você mesmo</b></summary>

`deeptutor chat` abre um REPL interativo e seleciona um modo com `--capability`; `deeptutor run <capability> "<message>"` recebe essa capacidade como primeiro argumento posicional e sai após um turno. Ambos aceitam `--tool`, `--kb`, `--config` e `--workspace` para selecionar um workspace registado.

```bash
deeptutor chat                                              # interactive REPL
deeptutor chat --capability deep_solve --kb my-kb
deeptutor run chat "Explain the Fourier transform" --kb textbook
deeptutor run chat "Find recent work beyond this material" --kb textbook
deeptutor run deep_research "Survey 2026 papers on RAG" \
  --config mode=report --config depth=standard
```

`--kb` fornece contexto para as ferramentas automáticas de RAG e Knowledge Frontier; o Frontier requer os módulos de conhecimento e pesquisa. `--tool` seleciona as ferramentas ativáveis pelo utilizador. Os módulos ativados também fornecem comandos para bases de conhecimento, sessões, partners, skills, notebooks, memória e configuração.

</details>

<details>
<summary><b>Deixar um agente conduzir</b></summary>

O DeepTutor foi construído para ser *operado por outro agente*. Adicione `--format json` a qualquer `run` e cada turno transmite **NDJSON — um evento por linha** (`content`, `tool_call`, `tool_result`, `done`, …), cada linha marcada com o seu `session_id`. As execuções são seguras sem TTY: uma pausa `ask_user` sem TTY resolve-se automaticamente com uma resposta vazia em vez de bloquear.

```bash
# One shot, machine-readable
deeptutor run deep_solve "Find d/dx[sin(x^2)]" --tool reason --format json

# Chain turns in one stateful session — capture the id, reuse it
SID=$(deeptutor run deep_research "Survey 2026 papers on RAG" \
  --config mode=report --config depth=standard --format json \
  | jq -r 'select(.type=="done").session_id')
deeptutor run deep_question "Quiz me on that survey" --session "$SID" --format json
```

O repositório inclui um [`SKILL.md`](../../SKILL.md) na raiz — um documento compacto de orientação para a CLI. Peça ao seu agente para o ler explicitamente; o respetivo [guia de configuração por agentes](../../docs-for-dev/AGENT_SETUP.md) cobre a instalação e a configuração. Também pode envolver `deeptutor run` como uma ferramenta num loop LangChain / AutoGen. Receitas completas: [Agent Handoff](https://deeptutor.info/docs/cli/agent-handoff/).

</details>

<details>
<summary><b>Revisão visual opcional para animações Manim</b></summary>

Defina `enable_visual_review=true` para inspecionar fotogramas renderizados quanto a sobreposição, legibilidade
e enquadramento, e depois envie os problemas detetados para o loop de reparação de código existente:

```bash
deeptutor run math_animator "Animate a sine wave" --config enable_visual_review=true
deeptutor run visualize "Animate a sine wave" \
  --config render_mode=manim_video --config enable_visual_review=true
```

A opção é `false` por predefinição. Também funciona com `output_mode=image` para
`math_animator` e `render_mode=manim_image` para `visualize`. Outros visualizadores,
incluindo o loop `auto` geral, ignoram-na. As dependências opcionais do Manim
continuam a ser necessárias.

Para turnos do SDK, passe `config={"enable_visual_review": True}` no `TurnRequest`
enviado para `DeepTutorApp.start_turn()`. Os clientes da API usam o mesmo objeto `config` com
`true` JSON. Para blocos de animação de livros, defina
`params={"enable_visual_review": True}` no `Block` de animação.

A revisão adiciona chamadas ao modelo de visão e pode acrescentar chamadas de reparação e novas renderizações, aumentando
o custo e a latência. Usa o limite existente de quatro tentativas, com um tempo limite de 120 segundos
para a revisão e de 180 segundos para a reparação. Se não houver fotogramas disponíveis ou o
modelo de revisão configurado não conseguir inspecionar imagens, a revisão é omitida com um resumo.
Uma revisão sem sucesso após todas as tentativas devolve a melhor renderização disponível e o respetivo
resultado de revisão falhado; um tempo limite de revisão segue o caminho existente de erro/repetição da renderização.
Os resultados da capacidade expõem `render.visual_review`; os blocos de livros conservam os mesmos
dados de revisão em `metadata.visual_review` (`null` quando a revisão não foi executada).

</details>

<details>
<summary><b>Referência de comandos</b></summary>

A tabela cobre a instalação completa e os complementos opcionais; os comandos e as capacidades requerem que os respetivos módulos estejam ativados. O núcleo fornece `chat` e `ask_questions`.

|:---|:---|

| `deeptutor doctor [--online]` | Verificar se o runtime está pronto para iniciar uma sessão; `--online` também sonda o provedor de modelo configurado, `--format json` imprime o relatório |
| `deeptutor start [--home PATH] [--dev] [--detach] [--no-browser]` | Lançar backend + frontend juntos, opcionalmente desconectado ou sem abrir o navegador |
| `deeptutor stop [--home PATH]` | Parar um launcher iniciado com `--detach` |

| `deeptutor provider login <provider>` | Autenticação de provedor (`openai-codex` login OAuth; `github-copilot` login por dispositivo do GitHub; `codebuddy` valida a autenticação do SDK CodeBuddy e inicia o login quando necessário) |

As credenciais do GitHub Copilot pertencem ao proprietário do DeepTutor com sessão iniciada e ficam apenas em
`<runtime-home>/data/system/user-secrets/<owner-id>/private/github-copilot/credentials.v1.json`,
fora dos workspaces da sandbox. Os partners da CLI/do administrador usam as credenciais do administrador;
os outros utilizadores iniciam sessão separadamente, e os perfis Copilot não podem ser partilhados através de concessões de modelos.
Os ficheiros de tokens externos do nanobot/Copilot nunca são importados: após a atualização, execute
`deeptutor provider login github-copilot` novamente.

O login valida a inferência com um modelo descoberto no momento; `init` valida o modelo selecionado
e aborta em caso de falha sem guardar o rascunho de configuração. A autenticação bem-sucedida no GitHub
por si só não comprova acesso aos modelos Copilot (o login guardado é mantido
se a validação falhar). Os pedidos de runtime seguem o endpoint da API devolvido pela troca de tokens,
incluindo nas atualizações, e respeitam os metadados de endpoint Responses/Chat Completions de cada modelo.

A compatibilidade Responses específica do Copilot é aplicada no envio sem reescrever o histórico guardado.

</details>

<details>
<summary><b>Distribuição de apenas CLI</b></summary>

O wheel do núcleo fornece a CLI e o SDK; `deeptutor-cli` é um metapacote de compatibilidade. O código-fonte disponibiliza todos os módulos presentes no repositório, pelo que deve instalar as respetivas dependências Python e dispensar a configuração do frontend para usar a CLI:

```bash
python -m pip install -r requirements/full.txt
python -m pip install -e . --no-deps
```

Para uma instalação mínima, use o wheel do núcleo. As distribuições opcionais acrescentam ferramentas, capacidades, rotas de API, serviços em segundo plano e navegação. Os módulos partilham um ambiente Python e têm de corresponder à versão do núcleo. `deeptutor[full]` seleciona os módulos comuns da aplicação na instalação; as funcionalidades individuais podem ser removidas mais tarde.

Pare o DeepTutor (`Ctrl+C` no respetivo terminal) e use o mesmo ambiente Python e o mesmo `DEEPTUTOR_HOME`:

```bash
deeptutor module list                       # installed / enabled / ready
deeptutor module disable research           # hide and deactivate; keep code
deeptutor module enable research            # restore it and required modules

# Package installations only; source checkouts use enable / disable:
deeptutor module install solve              # install the matching module and dependencies
deeptutor module uninstall solve --dry-run  # inspect the plan and dependency blockers
deeptutor module uninstall solve            # remove only this module's distribution
deeptutor chat                              # restart the CLI; use start for an installed Web app
```

Exemplos: `solve`, `research`, `questions`, `knowledge`, `parsing`, `reading`, `mastery`, `books`, `memory`, `notebook` e `partners`. Os módulos dependentes bloqueiam a remoção; o núcleo não pode ser removido através do comando de módulos. Desativar ou desinstalar preserva as definições, conversas, bases de conhecimento e ficheiros gerados. As dependências de terceiros partilhadas são mantidas.

**No navegador:** **Settings → Runtime status → Modules** mostra o estado dos módulos e os comandos de terminal correspondentes. As alterações de pacotes exigem um ambiente parado e são efetuadas na CLI. **Chat → Personalizar página** e **Aprendizagem → Nova atividade de aprendizagem → Personalizar página** alteram imediatamente as escolhas pessoais de página; ocultar uma entrada não desinstala o respetivo módulo nem revoga o acesso.

A família de pacotes 1.7.0 usa versões correspondentes no núcleo e nos wheels de funcionalidades. Para instalar wheels locais, passe `--wheelhouse /path/to/wheels` a `module install`. Consulte [instalação de módulos e desenvolvimento a partir do código-fonte](../../docs-for-dev/MODULES.md) para compilar os wheels e conhecer os detalhes de implementação.

## 🧩 Ecossistema — EduHub e a Comunidade de Skills

As skills do DeepTutor usam o formato aberto **Agent-Skills** — uma pasta com um playbook `SKILL.md` (frontmatter YAML + Markdown) e ficheiros de referência opcionais. Nada nisto é específico do DeepTutor, por isso qualquer registo que fale o formato torna-se uma fonte para a sua biblioteca. O DeepTutor inclui o **[EduHub](https://eduhub.deeptutor.info/)** — o nosso próprio registo de skills focado em educação — como hub padrão.

<details>
<summary><b>EduHub — o ecossistema de habilidades do DeepTutor</b></summary>

[**EduHub**](https://eduhub.deeptutor.info/) é o hub da comunidade que o DeepTutor lançou para partilhar skills de agentes orientadas para o ensino — tutores socráticos, construtores de cartões flash, feedback de redações, planos de exames, explicadores de conceitos e muito mais. Está integrado no DeepTutor, por isso não há nada a configurar: um slug simples ou um prefixo `eduhub:` resolve para ele.

**Encontrar e instalar** — no navegador, abra **Personalização → Skills → Importar do EduHub** para navegar no catálogo e descarregar uma skill diretamente para a sua biblioteca. Do terminal:

```bash
deeptutor skill search "socratic tutor"               # search EduHub (the default hub)
deeptutor skill install socratic-tutor                # fetch → verify → register
deeptutor skill install eduhub:socratic-tutor@1.2.0   # pin a hub and a version
deeptutor skill list                                  # local skills with their hub provenance
```

**Publicar a sua própria** — empacote um `SKILL.md` e partilhe-o de volta com a comunidade:

```bash
deeptutor skill login                                 # browser sign-in to EduHub
deeptutor skill publish ./my-skill                    # interactive: pick a track + tags, then upload
deeptutor skill update                                # roll back or release a new version
```

O EduHub também é um registo independente compatível com ClawHub, por isso agentes que não são o DeepTutor (Claude Code, Codex, …) podem usá-lo diretamente através da CLI `eduhub` — `npx eduhub install socratic-tutor`.

</details>

<details>
<summary><b>A porta de segurança de importação</b></summary>

Seja qual for a fonte, cada importação passa pela **mesma porta de segurança** antes de qualquer coisa tocar no seu espaço de trabalho:

- o **veredicto de segurança** do registo é verificado primeiro — os pacotes sinalizados são recusados a menos que passe `--allow-unverified`;
- os arquivos são extraídos defensivamente com verificações de travessia de caminhos, número de entradas, tamanho, taxa de compressão, sufixo e links simbólicos; os bits executáveis são removidos, enquanto ficheiros sem extensão continuam a ser permitidos;
- o frontmatter é normalizado para o esquema do DeepTutor e `always:` é **removido**, por isso uma skill descarregada nunca pode forçar-se em cada prompt do sistema;
- a proveniência — hub, versão, veredicto e hora de instalação — é escrita em `.hub-lock.json` para auditorias e atualizações.

Em implementações multi-utilizador, as importações pelo navegador chegam à camada de skills do chamador autenticado, enquanto as instalações pela CLI e pela consola de administração têm como alvo o espaço de trabalho do proprietário/administrador; as skills do administrador permanecem ocultas e em modo somente leitura para utilizadores comuns até serem atribuídas.

</details>

<details>
<summary><b>Também compatível com ClawHub</b></summary>

Como o DeepTutor fala o formato aberto Agent-Skills, o **[ClawHub](https://clawhub.ai/)** também funciona como fonte de primeira classe — está integrado juntamente com o EduHub. Escolha-o com o prefixo de hub:

```bash
deeptutor skill search "git release notes" --hub clawhub
deeptutor skill install clawhub:git-release-notes@1.0.1
deeptutor skill install clawhub:udiedrichsen/stock-analysis
```

Quando vários publicadores partilham o mesmo slug, a pesquisa mostra cada publicador e uma referência de instalação totalmente qualificada (`clawhub:<ownerHandle>/<slug>`).

Adicione mais registos em `data/user/settings/skill_hubs.json`: uma entrada `type: "clawhub"` aponta para qualquer API HTTP compatível (EduHub e ClawHub falam ambos), `type: "command"` envolve qualquer CLI de busca que um registo forneça, e `"default"` escolhe o hub usado para slugs simples. Todos eles alimentam a mesma porta de importação.

</details>
